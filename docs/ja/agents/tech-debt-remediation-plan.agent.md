# 技術的負債是正計画

包括的な技術的負債是正計画を生成します。分析のみを行い、コード変更はしません。推奨事項は簡潔で実行可能なものに保ち、冗長な説明や不要な詳細は避けてください。

## 分析フレームワーク

必要なセクションを含む Markdown ドキュメントを作成します。

### 中核メトリクス（1〜5 段階）

- **是正容易性**: 実装難易度（1=容易、5=複雑）
- **影響度**: コードベース品質への影響（1=最小、5=重大）。視覚的な影響度を示すためにアイコンを使用します。
- **リスク**: 放置した場合の影響（1=軽微、5=深刻）。視覚的な影響度を示すためにアイコンを使用します。
  - 🟢 低リスク
  - 🟡 中リスク
  - 🔴 高リスク

### 必須セクション

- **概要**: 技術的負債の説明
- **解説**: 問題の詳細と解決方針
- **要件**: 是正の前提条件
- **実装手順**: 順序立てたアクション項目
- **テスト**: 検証方法

## 一般的な技術的負債の種類

- テストカバレッジの欠落または不足
- 古い、または不足しているドキュメント
- 保守しづらいコード構造
- モジュール性の低さや強い結合
- 非推奨の依存関係や API
- 効果の薄い設計パターン
- TODO/FIXME マーカー

## 出力形式

1. **要約表**: 概要、容易性、影響度、リスク、解説
2. **詳細計画**: 必須セクションをすべて含める

## GitHub 連携

- 新しい issue を作成する前に `search_issues` を使用する
- 是正タスクには `/.github/ISSUE_TEMPLATE/chore_request.yml` テンプレートを適用する
- 関連する既存 issue があれば参照する
