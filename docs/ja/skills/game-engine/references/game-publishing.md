# ゲーム公開

このリファレンスでは、Webベースのゲーム公開における3つの柱、すなわち配信チャネルとプラットフォーム、プロモーション戦略、マネタイズモデルを扱います。

## ゲーム配信

ゲーム配信とは、プレイヤーがあなたのゲームを発見し、アクセスするためのチャネルとプラットフォーム全体を指します。適切な配信戦略の選択は、ターゲットユーザー、ゲームの種類、ビジネス目標によって決まります。

### セルフホスティング

セルフホスティングは、ゲームに対する最大限のコントロールを可能にし、アプリストアの承認を待たずに即時アップデートを配信できます。

- 覚えやすく魅力的なドメイン名で、リモートサーバーにゲームをアップロードする。
- ペイロードサイズを減らすために、ソースコードを連結して最小化する。
- 逆コンパイルを難しくし知的財産を守るために、コードを難読化する。
- iTunes や Steam のようなクローズドストア向けにパッケージ化する予定があるなら、オンラインデモを提供する。
- 無料ホスティング、バージョン管理、コミュニティからの貢献可能性の観点で、GitHub Pages の利用を検討する。

### パブリッシャーとポータル

インディー系ゲームポータルは、トラフィックの多いサイトから自然な宣伝効果を得られ、広告やレベニューシェアによる収益化の可能性もあります。

**人気のインディーポータル:**

- HTML5Games.com
- GameArter.com
- MarketJS.com
- GameFlare
- GameDistribution.com
- GameSaturn.com
- Playmox.com
- Poki (developers.poki.com)
- CrazyGames (developer.crazygames.com)

**ライセンスの選択肢:**

- 独占ライセンス: 配信先を単一の購入者に限定し、1契約あたりの収益を高める。
- 非独占ライセンス: 複数ポータルへ広く展開し、リーチを拡大する。

### Webストア

**Chrome Web Store:**

- マニフェストファイルと、ゲームリソースを含む zip パッケージが必要。
- ゲームの改修は最小限で済む。
- オンライン提出フォームがシンプル。

### ネイティブモバイルストア

**iOS App Store:**

- 要件が厳格で、承認待ちは1〜2週間。
- 何十万本ものアプリが存在し、競争が非常に激しい。
- 一般的に有料ゲームが有利。
- 最も有力なモバイルストアだが、埋もれずに目立つのが最も難しい。

**Google Play (Android):**

- iOS より要件が緩い。
- 日々の申請本数が多い。
- フリーミアムモデル（無料ダウンロード＋アプリ内課金または広告）が好まれる。
- iOS で有料のゲームは、Android では基本無料として提供されることが多い。

**その他のモバイルプラットフォーム（Windows Phone、BlackBerry など）:**

- 競合が少なく、露出を得やすい。
- 市場規模は小さいが、過密ではない。

### ネイティブデスクトップ

**Steam:**

- 最大のデスクトップ向けゲーム配信プラットフォーム。
- インディー開発者は Steam Direct プログラム経由で参入可能。
- 複数プラットフォーム（Windows、macOS、Linux）対応が必要で、アップロードは別々に行う。
- クロスプラットフォーム互換性の問題に対応する必要がある。

**Humble Bundle:**

- 主に露出とプロモーションの機会。
- 低価格のバンドル販売モデル。
- 直接収益の最大化より、認知拡大に重きがある。

### パッケージングツール

HTML5ゲームをクローズドなエコシステムへ配信するためのツール:

| Tool | Platforms |
|------|-----------|
| Ejecta | iOS (ImpactJS-specific) |
| NW.js | Windows, Mac, Linux |
| Electron | Windows, Mac, Linux |
| Intel XDK | Multiple platforms |
| Manifold.js | iOS, Android, Windows |

### プラットフォーム戦略

- **モバイル優先:** HTML5ゲームのトラフィックの大半はモバイル。端末を持ったまま1〜2本指で遊べる設計にする。
- **開発はデスクトップ中心:** モバイルでのデバッグ前に、まずデスクトップで構築・テストする。
- **マルチプラットフォーム:** 主対象がモバイルでもデスクトップ対応は行う。HTML5ゲームの強みは「1回書いて、どこでも配信」できること。
- **分散:** 単一ストアに依存しない。複数プラットフォームに広げてリスクを下げる。
- **即時アップデート:** Web配信の大きな利点は、ストア承認待ちなしで素早くバグ修正を出せること。

## ゲームプロモーション

ゲームのプロモーションには、継続的なマルチチャネル戦略が必要です。多くの施策は無料で実施できるため、予算の限られたインディー開発者でも取り組めます。可視性はゲーム品質と同じくらい重要で、どれだけ優れたゲームでも宣伝なしでは埋もれます。

### Webサイトとブログ

**必須のWebサイト構成要素:**

- スクリーンショットとゲームトレーラー。
- 詳細な説明とダウンロード可能なプレスキット（Presskit() などのツールを活用）。
- 動作要件と対応プラットフォーム。
- サポートと連絡先情報。
- 少なくともブラウザで遊べるデモ。
- 発見されやすくするための SEO 最適化。

**ブログ戦略:**

- 開発プロセス、遭遇したバグ、学んだことを記録する。
- 毎月の進捗レポートを公開する。
- 継続的なコンテンツ作成は、時間とともに SEO 順位を改善する。
- 信頼性とコミュニティ内での評判を築く。

### ソーシャルメディア

- Twitter/X などでは `#gamedev` ハッシュタグを使ってコミュニティと交流する。
- 押し売り的な広告や味気ないプレスリリースは避け、誠実に発信する。
- 開発のコツ、業界インサイト、舞台裏コンテンツを共有する。
- あなたのゲームを取り上げる可能性のある YouTube や Twitch の配信者を追う。
- HTML5GameDevs.com のようなフォーラムに参加する。
- コミュニティと誠実に関わる。質問に答え、支援し、自己宣伝ばかりにならないようにする。
- 割引やコンテスト賞品を提供し、好意的な関係を築く。

### プレスへのアプローチ

- 自分のゲームジャンルやプラットフォームを専門に扱うメディアを調査する。
- 記者やレビュアーへの連絡は、謙虚・丁寧・辛抱強く行う。
- 無差別で無関係な一斉送信は避け、対象を絞ってアプローチする。
- 高品質なゲームと誠実な姿勢の組み合わせが、最良の成功率につながる。
- 詳細戦略として、Pixel Prospector の「How To Contact Press」のようなガイドを参照する。

### コンペティション

- ゲーム開発コンペ（ゲームジャム）に参加して、ネットワークづくりと認知獲得を行う。
- 必須テーマは創造的な発想を促し、革新を強制する。
- 受賞すれば主催者からの自動的な宣伝とコミュニティの注目が得られる。
- 早期デモ公開と評判構築に最適。

### チュートリアルと教育コンテンツ

- 自分のゲームで実装した内容を記録し、教える。
- 記事やチュートリアルで、ゲームを実践的なケーススタディとして使う。
- Tuts+ Game Development のような、原稿料が出るプラットフォームで公開する。
- 1つのテーマを深く掘り下げ、読者に本当に価値ある内容を提供する。
- 二重の効果: ゲームの宣伝になり、知見ある開発者としての立場も築ける。

### イベント

**カンファレンス:**

- 開発中に乗り越えた課題について技術トークを行う。
- API 実装を、実ゲームを使った実例としてデモする。
- 宣伝より知識共有を重視する。開発者は押しの強い営業的な話に特に敏感。

**見本市・展示会:**

- 他の開発者に混じってブースを確保し、ファンと直接交流する。
- ユニークで独創的な見せ方で差別化する。
- 現実のユーザーテストと即時フィードバックを得られる。
- プレイヤーが自然に見つけるバグや問題の発見に役立つ。

### プロモコード

- 無料または限定アクセスのプロモコードを配布できる仕組みを作る。
- プレス、メディア、YouTube/Twitch 関係者、コンペ優勝者、コミュニティのインフルエンサーへ配布する。
- 適切な相手に無料アクセスを届けることで、数千人規模の潜在プレイヤーへの無料広告につながる。

### コミュニティ構築

- 定期更新を含む週次ニュースレターを配信する。
- 自作ゲームやゲーム開発全般に関連したオンライン大会を企画する。
- 開発者同士が直接会える地域ミートアップを開催する。
- 情熱を示し、信頼性と安心感を築く。
- コミュニティは、ローンチ時に支援や話題化が必要なときの強力な味方になる。

### プロモーションの重要原則

| Factor | Importance |
|--------|-----------|
| Consistency | すべてのチャネルでの定期的な発信と交流 |
| Authenticity | 取引的ではない、誠実なコミュニティ交流 |
| Patience | 関係性と評判の構築には時間がかかる |
| Value-first | 何かを求める前に、消費する価値のある内容を提供する |
| Multiple channels | 単一のプロモーション戦略に依存しない |

## ゲームマネタイズ

マネタイズ戦略は、ゲームの種類、ターゲットユーザー、配信プラットフォームに合わせるべきです。収益源を分散することで、事業の安定性が高まります。

### 有料ゲーム

**モデル:** プレイヤーがアクセスする前に固定価格を前払いで課金する。

- 購入を促すために、相応のマーケティング投資が必要。
- 価格は市場と品質で変動: iOS のアーケード作品は約 $0.99、Steam のデスクトップ RPG は約 $20。
- 成功はゲーム品質、市場調査、マーケティング効果に依存する。
- 市場トレンドを研究し、失敗から素早く学ぶ。

### アプリ内課金（IAPs）

**モデル:** ゲーム自体は無料で獲得し、任意コンテンツや機能に課金する。

**購入可能コンテンツの種類:**

- ボーナスレベル
- より強力な武器や魔法
- エネルギー回復
- ゲーム内通貨
- プレミアム機能やバーチャルアイテム

**主要指標と考慮点:**

- 意味のある収益を得るには数千件のダウンロードが必要。
- 実際に購入するプレイヤーは、通常およそ 1,000 人に 1 人程度。
- 収益はプロモーション活動とプレイヤー数に大きく依存する。
- プレイヤー数こそが成功の最重要要因。

### フリーミアム

**モデル:** 無料ゲームに、任意のプレミアム機能や有料特典を加える。

- コアコンテンツを課金壁で制限するより、ゲーム全体の価値を高める。
- プレイヤーに嫌われ、継続率や評判を損なう「pay-to-win」要素は避ける。
- 進行自体を課金壁にしない。
- まずは無料体験として十分に楽しいことを優先し、その後にプレミアム拡張を提供する。

**アドオンとDLCs:**

- 新キャラクター、武器、ストーリーを含む新レベルセット。
- 実績ある人気のベースゲームが前提。
- 既存の熱心なプレイヤーに追加価値を提供できる。

### 広告

**モデル:** 広告表示による受動収益。開発者と広告ネットワークで収益分配する。

**広告ネットワーク:**

- **Google AdSense:** 最も効果的だがゲーム向け最適化ではない。ゲーム関連アカウントではリスクもある。
- **LeadBolt:** 実装しやすい、ゲーム特化の代替案。
- **動画広告:** ローディング画面中のプレロール形式が人気上昇中。

**配置戦略:**

- セッション間やゲームオーバー画面で広告を表示する。
- 広告の視認性とプレイヤー体験のバランスを取る。
- プレイヤーを苛立たせて継続率を落とさないよう、広告は控えめにする。
- 低トラフィックゲームでは収益は通常ごく小さい。

**レベニューシェア:** パブリッシャーとの分配は通常 70/30 または 50/50。

### ライセンス

**モデル:** 配信権に対する一時金。収益化はパブリッシャー側が担当する。

**独占ライセンス:**

- 単一パブリッシャーのみに販売。
- 契約後は、いかなる形でも再販売できない。
- 価格帯: $2,000〜$5,000 USD。
- 独占の価値が見合う十分な利益が出る場合のみ検討。販売後はゲームの宣伝を停止する。

**非独占ライセンス:**

- 複数パブリッシャーに同時販売可能。
- パブリッシャーは自社ポータル内でのみ配信可能（site-locked）。
- 価格帯: パブリッシャーあたり約 $500 USD。
- 最も一般的なライセンス方式。複数パブリッシャーとの継続運用に適する。

**サブスクリプションモデル:**

- ゲームごとに月次の受動収益。
- 価格帯: 1ゲームあたり月 $20〜$50 USD。
- 支払い方式は一括または月払いを選べる。
- リスク: パブリッシャー都合でいつでも解約され得る。

**広告収益分配:**

- 集客はパブリッシャーが行い、収益を分配する。
- 分配率: 70/30 または 50/50、月次で受け取り。
- 注意: 新規または低品質のパブリッシャーでは、総額 $2 USD 程度の提示しかない場合もある。

**ライセンスに関する重要事項:**

- パブリッシャーから独自 API 実装を求められる場合がある（開発コストを価格に織り込む）。
- 無名の買い手による詐欺リスクを取るより、実績ある信頼できるパブリッシャーの低めのライセンス料を受ける方がよい。
- パブリッシャーへの連絡は、各社Webサイトまたは HTML5 Gamedevs フォーラム経由で行う。

### ブランディングとカスタム案件

**ブランディング付き非独占ライセンス:**

- クライアントがコード権利を購入し、自社グラフィックを実装する。
- 例: ゲーム内の食べ物アイテムをクライアントブランド商品に差し替える。

**フリーランスのブランディング対応:**

- 開発者が既存ゲームコードを再利用し、クライアント提供グラフィックを追加する。
- 実装の詳細はクライアント主導で決まる。
- 価格はブランド力、クライアント要求、作業範囲によって大きく変わる。

### その他のマネタイズ戦略

**デジタルアセット販売:**

- Envato Market や ThemeForest などで、ゲーム用グラフィックやアートアセットを販売する。
- 再利用可能アセットを作れるグラフィックデザイナーに向いている。
- 受動的で控えめながら、継続的な収入を得られる。

**記事・チュートリアル執筆:**

- Tuts+ Game Development のような、原稿料が支払われるプラットフォームでゲーム開発記事を公開する。
- 二重の効果: ゲーム宣伝と直接収益を同時に得られる。
- 実例として自作ゲームを使い、誠実な知識共有に焦点を当てる。

**グッズ販売:**

- Tシャツ、ステッカー、ブランドガジェット。
- 高い人気と視覚的認知があるゲーム（例: Angry Birds）で最も利益が出やすい。
- ゲーム本体よりグッズ収益の方が多い開発者もいる。
- 収益源分散のための二次的手段として有効。

**コミュニティ寄付:**

- ゲームページに寄付ボタンを設置する。
- 効果はコミュニティとの関係の強さに依存する。
- プレイヤーがあなたを個人的に知っており、寄付が継続開発にどう役立つか理解している場合に最も機能する。

### マネタイズまとめ

| Model | Revenue Type | Best For | Risk Level |
|-------|-------------|----------|------------|
| Paid Games | 一時金 | 強いマーケティング力を伴う高品質ゲーム | High |
| In-App Purchases | 取引ごと | ダウンロード数の多い人気ゲーム | Medium |
| Advertisements | 受動/CPM | カジュアルで中毒性の高いゲーム | Low-Medium |
| Non-Exclusive Licensing | 一時金（約$500） | すべてのゲームタイプ | Low |
| Exclusive Licensing | 一時金（$2K-$5K） | 実績ある高品質ゲーム | Medium |
| Subscriptions | 月次受動収益 | 実績を積んだゲーム | Medium |
| Merchandise | 販売ごと | 視覚的アイデンティティの強い人気IP | High |
| Articles/Tutorials | 公開ごと | ニッチな専門性を持つ開発者 | Low |
