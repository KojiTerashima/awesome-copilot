# ゲーム開発用語集

ビデオゲーム開発で使われる用語と概念を、すばやく参照できるようカテゴリ別に整理した包括的な用語集です。

出典: https://www.gameindustrycareerguide.com/video-game-development-terms-glossary/

---

## 一般的な開発用語

### AAA (Triple-A)
大規模スタジオが、多額の予算・大人数のチーム・高い制作品質で開発するゲームの区分。代表例として、Call of Duty、Assassin's Creed、The Last of Us などのシリーズが挙げられます。

### Indie
「independent（独立系）」の略。大手パブリッシャーの資金支援なしで、小規模チームや個人が開発するゲームを指します。Indieゲームは、制作規模よりも創造性や革新性を重視する傾向があります。

### Alpha
ゲーム開発の初期段階。主要機能は実装されているものの、未完成で磨き込みが不十分であり、重大なバグを含む可能性が高い状態です。Alphaビルドは、内部テストや機能検証に使われます。

### Beta
開発後期の段階。機能は出そろっているものの、テストとバグ修正を継続している状態です。Beta版は、限定ユーザー向け（closed beta）または一般公開（open beta）で配布されることがあります。

### Gold / Gone Gold
製造・流通の承認を受けたゲームの最終版。「Going gold」は、ゲームが完成し、リリース準備が整ったことを意味します。

### Build
開発時点の特定状態をコンパイルして実行可能にしたゲーム版。チームはテストやマイルストーンレビューのために定期的にビルドを作成します。

### Milestone
開発スケジュール上の節目となるチェックポイントで、特定の成果物の完成が求められます。進捗管理に使われ、パブリッシャーからの資金提供条件と連動することも多いです。

### Crunch
締切に間に合わせるため、開発終盤に発生しやすい長時間残業期間。ゲーム業界で広く知られ、しばしば問題視される慣行です。

### Post-Mortem
プロジェクト完了後に行う振り返り分析。うまくいった点、問題点、次回プロジェクトへの教訓を整理します。

### Vertical Slice
アート・デザイン・プログラミング・音響など全領域で、最終品質目標を示す磨き込まれたプレイ可能区間。ゲームのビジョン検証や資金調達に使われます。

## ゲームデザイン用語

### Game Design Document (GDD)
ゲームのコンセプト、メカニクス、ストーリー、アート方針、技術要件など、設計に関する要素を包括的に記述した文書。チーム全体の設計図として機能します。

### Game Mechanic
ゲームの動作やプレイヤーとの相互作用を定義するルールやシステム。例として、ジャンプ、射撃、インベントリ管理、クラフト、戦闘システムなどがあります。

### Gameplay Loop (Core Loop)
プレイヤーがゲーム中で繰り返す基本行動サイクル。優れたコアループは没入感があり報酬感を生みます。例: 探索→敵と戦う→戦利品を集める→キャラ強化→繰り返し。

### Level Design
プレイヤーが移動する環境、挑戦要素、空間レイアウトを作る工程。レベルデザイナーは地形、敵、アイテム、トリガー、スクリプトイベントを配置します。

### Progression System
プレイヤーの成長を記録し報酬を与えるシステム。経験値、スキルツリー、アンロック能力、装備強化、物語進行などを含みます。

### Balancing
ゲーム内パラメータ（ダメージ値、体力量、リソース消費、難易度曲線）を調整し、公平で手応えがあり、楽しめるゲームプレイを実現する工程。

### Difficulty Curve
プレイヤー進行に伴って難易度が上がる度合い。適切に調整された難易度曲線は、プレイヤーの上達に合わせて段階的に複雑さを導入します。

### NPC (Non-Player Character)
人間プレイヤーが操作しないゲーム内キャラクターの総称。味方、敵、クエスト提供者、商人、背景キャラクターなどが含まれます。

### HUD (Heads-Up Display)
体力バー、ミニマップ、弾薬数、スコア、目標マーカーなど、プレイヤーに情報を表示する画面上のオーバーレイ。

### UI (User Interface)
メニュー、インベントリ画面、設定パネル、ダイアログ、HUD など、プレイヤーが操作・参照する視覚要素全般。

### UX (User Experience)
使いやすさ、アクセシビリティ、直感性、満足度を含む、プレイヤー体験全体の質。UX設計は、学びやすく遊びやすいゲーム作りに焦点を当てます。

### Spawn / Spawning
ゲームエンティティ（プレイヤーキャラ、敵、アイテム）を、特定の場所と時間でゲーム世界に生成・配置すること。

### Respawn
プレイヤーキャラやエンティティが、倒された後にゲーム世界へ再出現する処理。

### Hitbox
攻撃や飛び道具が対象に当たったかを判定するために使う、エンティティに付随した不可視の幾何形状（当たり判定）。

### Cooldown
一定時間が経過するまで、同じ能力・アイテム・行動を再使用できないようにする時間制限。

### Buff / Debuff
キャラクターの能力値や性能に一時的な変化を与える効果。buffは強化（速度上昇、ダメージ増加、防御上昇）、debuffは弱体化（移動低下、命中低下）を指します。

### Aggro
「aggravation」の略で、敵がプレイヤーに向ける敵対度を意味します。「Drawing aggro」は敵の注意と攻撃を引きつけることです。

### AoE (Area of Effect)
単体ではなく、定義された範囲内のすべてのエンティティに影響する攻撃・呪文・能力。

### DPS (Damage Per Second)
キャラクター、武器、能力が1秒あたりに与える平均ダメージ量を示す指標。戦闘性能の比較やバランス調整に使われます。

### RNG (Random Number Generation)
戦利品ドロップ、クリティカル発生率、プロシージャル生成など、ゲームメカニクスにランダム性を導入する仕組み。口語では「運要素」の意味でも使われます。

### Proc (Programmed Random Occurrence)
プレイ中に確率で発動するイベント。例: 武器命中時に一定確率で特殊効果が発動する。

### Meta / Metagame
対戦コミュニティで「最も有効」と見なされる戦略、ビルド、戦術。プレイヤーが最適解を発見するにつれてmetaは変化します。

### Nerf
キャラクター、武器、能力、戦術の強さや有効性を下げるバランス調整。buffの反対。

### Sandbox
厳密な直線的進行を設けず、プレイヤーに探索や相互作用の自由を与えるゲームデザイン。プレイヤー主導の体験を重視します。

### Procedural Generation
レベル、地形、アイテム、クエストなどのコンテンツを手作業ではなくアルゴリズムで実行時生成する手法。少ない手動制作で広大かつ多様な世界を実現できます。

### Permadeath
キャラクターの死亡が永続的で、リロードやリスポーンができないゲームメカニクス。多くの場合、プレイヤーは新キャラクターで最初からやり直します。

### Roguelike / Roguelite
プロシージャル生成レベル、permadeath、ターン制またはリアルタイム戦闘を特徴とするジャンル。rogueliteはより軽量な派生で、プレイ間の一部恒久成長を許すことがあります。

## プログラミング・技術用語

### Game Engine
レンダリング、物理、音響、入力、スクリプティング、アセット管理など、ゲーム構築に必要な基盤システムを提供する中核ソフトウェアフレームワーク。例: Unity、Unreal Engine、Godot、独自エンジン。

### Rendering / Renderer
ゲーム映像を画面に描画する処理とシステム。2Dスプライト描画、3Dポリゴン描画、ライティング、影、ポストプロセス効果を含みます。

### Frame Rate (FPS -- Frames Per Second)
1秒間に描画・表示される画像（フレーム）数。フレームレートが高いほどアニメーションは滑らかになります。一般的な目標値: 30 FPS、60 FPS、120 FPS。

### Tick Rate
ゲームサーバーやシミュレーションがゲーム状態を更新する頻度（Hz）。64-tickサーバーは1秒間に64回更新します。

### Delta Time
現在フレームと前フレームの経過時間差。フレームレート変動に左右されず一貫したゲームロジックを実行するために使います。

### Physics Engine
重力、衝突、剛体動力学、軟体変形、ラグドールなどの物理挙動をシミュレートするシステム。例: Box2D、Bullet、PhysX、Havok。

### Collision Detection
2つ以上のゲームオブジェクトが交差・接触したかを判定する処理。代表的手法には bounding box (AABB)、球、カプセル、メッシュベース衝突があります。

### Raycasting
ある点から指定方向へ不可視のレイを飛ばし、オブジェクトとの交差を検出する技術。視線判定、弾道計算、マウスピッキング、可視性テストなどに使われます。

### Pathfinding
AI制御キャラクターの移動経路を計算するアルゴリズム。代表例は A* (A-star)、Dijkstra法、navigation meshes (NavMesh) です。

### State Machine (FSM -- Finite State Machine)
エンティティが定義済み状態集合のいずれかに存在し、状態遷移ルールで制御されるプログラミングパターン。AI挙動、アニメーションシステム、ゲームフロー管理で広く使われます。

### Shader
GPU上で実行され、頂点やピクセルの描画方法を制御するプログラム。vertex shaderはジオメトリ変換、fragment (pixel) shaderはピクセル単位の色やライティング計算を行います。

### LOD (Level of Detail)
遠距離オブジェクトの視覚的複雑さを、低ポリゴンモデル・簡易テクスチャ・効果削減へ切り替えて下げる技術。描画性能を向上させます。

### Occlusion Culling
他オブジェクトに隠れて見えないオブジェクトの描画を省く最適化。カメラから完全に遮蔽される場合、レンダリングパイプラインから除外されます。

### Frustum Culling
カメラの可視範囲（view frustum）外にあるオブジェクトを描画計算から除外する最適化。

### Draw Call
GPUに対してジオメトリセットを描画するよう指示するコマンド。バッチ処理やインスタンシングでdraw callを削減することは重要な最適化戦略です。

### Sprite
ゲームで使う2D画像またはアニメーション。2Dゲームでキャラクター、アイテム、エフェクト、環境要素を表現します。

### Sprite Sheet / Sprite Atlas
複数のスプライトをグリッドまたはパック配置でまとめた単一画像ファイル。描画時のdraw callやテクスチャ切替を削減します。

### Tilemap
再利用可能なタイルのグリッドで2Dレベルを構築する手法。各セルはtileset内のタイル種別を参照し、効率的なレベル制作と描画を可能にします。

### API (Application Programming Interface)
ソフトウェア構築・連携のために定義されたインターフェースとプロトコルの集合。ゲーム開発では graphics API（OpenGL、DirectX、Vulkan、Metal）、audio API、platform API などがあります。

### SDK (Software Development Kit)
特定プラットフォームやフレームワーク向けアプリ開発に提供される、ツール・ライブラリ・ドキュメント・サンプルコード一式。

### Middleware
特定機能を提供するため、ゲームエンジンや開発パイプラインに統合するサードパーティ製ライブラリ・ツール。例: 物理（Havok）、音響（FMOD、Wwise）、アニメーション。

### Serialization
ゲームオブジェクト、状態、データ構造を保存・送信可能な形式（JSON、binary、XML）へ変換する処理。逆処理はdeserialization。

### Latency
操作開始から結果観測までの遅延。ネットワークではlatency（ping）はクライアントとサーバー間のデータ往復時間を指します。

### Netcode
マルチプレイヤーゲームのネットワークコードおよび設計。client-server通信、状態同期、ラグ補償、予測処理を含みます。

### Client-Server Architecture
中央サーバーが正規のゲーム状態を保持し、クライアントが入力送信と状態受信を行うネットワークモデル。不正行為を抑え、一貫性を確保します。

### Peer-to-Peer (P2P)
中央サーバーなしでクライアント同士が直接通信するネットワークモデル。導入は比較的容易ですが、不正対策は難しくなります。

### Lag Compensation
client-side prediction、server reconciliation、entity interpolation など、ネットワーク遅延の影響を軽減するマルチプレイヤー向け技術群。

### Rubber Banding
クライアント予測とサーバー補正の不一致により、プレイヤーやオブジェクトが過去位置へ引き戻されるように見えるマルチプレイヤー上の視覚現象。

## アート・ビジュアル用語

### Asset
3Dモデル、テクスチャ、スプライト、効果音、音楽、アニメーション、スクリプト、レベルデータなど、ゲームで使うあらゆるコンテンツ要素。

### Texture
3Dモデル表面に貼る、または2D描画で直接使う2D画像。色、細部、材質感を表現します。

### Normal Map
ピクセルごとの表面向き情報を保持するテクスチャ。追加ジオメトリなしで平面に奥行きや凹凸、細かなディテールを見せられます。

### Mesh
頂点・辺・面（ポリゴン）で構成される3Dモデルの幾何構造。キャラクター、オブジェクト、環境の形状を作ります。

### Polygon / Poly
3Dメッシュの基本単位となる平面図形（通常は三角形）。「poly count」はモデルやシーン内の総ポリゴン数を指します。

### Rigging
3Dモデル内にスケルトン（armature）を作成し、アニメーション可能にする工程。ボーンを配置し、メッシュ変形へ影響するようウェイト設定します。

### Skinning
3Dメッシュをスケルトンに結びつけ、アニメーション時に自然に変形させる処理。各頂点は1つ以上のボーンにウェイト付けされます。

### Keyframe Animation
特定時点（keyframe）でポーズを定義し、その間の動きをシステムが補間するアニメーション手法。

### Skeletal Animation
階層化されたボーン構造で駆動するアニメーション。親ボーンの変換が子ボーンに伝播し、自然なキャラクター動作を実現します。

### Particle System
多数の小さな視覚要素（パーティクル）を生成・管理し、炎、煙、雨、火花、爆発、魔法などの効果を表現するシステム。

### Parallax Scrolling
前景に対して背景レイヤーを異なる速度で動かし、奥行きの錯覚を生む2D表現技法。

### Voxel
体積を持つピクセル。2Dグリッド上のピクセルに対する、3Dグリッド上の値に相当します。Minecraftのようなブロック型ワールド構築や医療・科学可視化で使われます。

### Anti-Aliasing
ポリゴン境界や高コントラスト境界のジャギー（aliasing）を滑らかにする描画技術。MSAA、FXAA、TAA などがあります。

### Post-Processing
メインシーン描画後のフレームに適用する視覚効果。例: bloom、motion blur、depth of field、color grading、ambient occlusion。

## オーディオ用語

### SFX (Sound Effects)
足音、発砲、アイテム取得、UI操作、環境音など、ゲーム内イベントで再生される短い音声クリップ。

### BGM (Background Music)
ゲームプレイ、カットシーン、メニュー中に流れる楽曲。雰囲気を作り、感情的トーンを高めます。

### Adaptive Audio / Dynamic Music
ゲームイベント、プレイヤー行動、ゲーム状態に応じて変化する音楽・音響。例: 敵が増えるほど戦闘曲が激化する。

### FMOD / Wwise
ゲームにおける高度なサウンドデザイン、ミキシング、適応型オーディオ実装に使われる業界標準のオーディオmiddlewareツール。

### Spatial Audio / 3D Audio
3D空間内の音源位置と移動を再現し、プレイヤーに方向手がかりを与えるオーディオ処理。

## プラットフォーム・配信用語

### Platform
ゲームが動作するハードウェア/ソフトウェア環境: PC、PlayStation、Xbox、Nintendo Switch、mobile (iOS/Android)、web browser、VR headsets。

### Cross-Platform
ゲームが複数プラットフォームで動作できること。多くの場合、異なるプラットフォーム間で一緒に遊べる（cross-play）ことも含みます。

### Port / Porting
あるプラットフォーム向けに開発したゲームを別プラットフォームで動作するよう移植する工程。ハード性能差により大きな技術的再調整が必要な場合があります。

### DLC (Downloadable Content)
初回発売後に配信される追加コンテンツ。新レベル、キャラクター、ストーリーチャプター、アイテム、コスメティック要素などを含むことがあります。

### Microtransaction
主にコスメティック、仮想通貨、ゲームプレイ上の利点を対象とした少額課金。free-to-playゲームで一般的な収益化モデルです。

### Free-to-Play (F2P)
基本ゲームを無料でダウンロード・プレイ可能にし、任意のゲーム内購入で収益を得るビジネスモデル。

### Games as a Service (GaaS)
継続的に新コンテンツ、イベント、機能を追加運営するモデル。サブスクリプションやmicrotransactionなど継続収益で支えられることが多いです。

### Early Access
開発継続中のゲームを、プレイヤーが購入・プレイしてフィードバックと資金提供を行えるリリースモデル。

### Day One Patch
正式発売日当日またはそれ以前に配信される更新。物理版製造時に間に合わなかった不具合修正、性能改善、追加要素を含むことがあります。

### QA (Quality Assurance)
バグ、不具合、性能問題、設計上の問題を見つけるための体系的テスト。QAテスターはさまざまな条件で繰り返しプレイし、品質を担保します。

### Bug
ゲームのコード、設計、コンテンツに含まれる誤り・欠陥・意図しない挙動。軽微な表示崩れから進行不能クラッシュまで幅があります。

### Exploit
ゲームメカニクスやバグの想定外利用により、不公平な優位を得る行為・手法。通常、発見後に修正されます。

### Patch
既存ゲームに配信されるソフトウェア更新。バグ修正、exploit対応、性能改善、バランス調整、新コンテンツ追加などを行います。

### Hotfix
重大不具合を緊急対応するための小規模かつ限定的なpatch。通常patchほどの完全なテストサイクルを待たずに配信されることがあります。

## ゲームジャンル用語

### FPS (First-Person Shooter)
一人称視点でゲームを体験し、主に遠距離戦闘を行うジャンル。

### TPS (Third-Person Shooter)
カメラがプレイヤーキャラクターの後方または肩越しに配置されるシューティングゲーム。

### RPG (Role-Playing Game)
プレイヤーがキャラクターの役割を担い、物語と戦闘を通じて意思決定し、能力や属性を成長させていくジャンル。

### MMORPG (Massively Multiplayer Online RPG)
多数のプレイヤーが同時に永続的オンライン世界で活動するRPG。

### RTS (Real-Time Strategy)
ターン制ではなくリアルタイムで、資源管理、拠点建設、ユニット指揮を行う戦略ゲーム。

### MOBA (Multiplayer Online Battle Arena)
固有能力を持つ個別キャラクターを操作し、チームで協力して相手チームの拠点破壊を目指す対戦ジャンル。

### Battle Royale
多数のプレイヤーが、縮小するプレイエリア内で最後の1人（1チーム）を目指して競うジャンル。

### Metroidvania
相互接続されたマップ、能力による進行制限、そして新能力獲得後に以前行けなかった場所へ戻る探索を特徴とするアクションアドベンチャーのサブジャンル。

### Soulslike
Dark Soulsシリーズに影響を受けたゲーム群。高難度戦闘、スタミナ管理メカニクス、最小限の誘導、失敗から学ぶ体験の重視が特徴です。
