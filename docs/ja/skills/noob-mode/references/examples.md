# Noobモード — ビフォー＆アフターの例

これらの例は、Noobモードが**オフ**のときと**オン**のときでCopilot CLIがどのように動作するかを示しています。同じ操作でも、まったく異なる体験です。

---

## 1. ファイル読み取りの承認

### ❌ Noobモードなし
```
Allow tool: view on path "/Users/you/contracts/nda-template.md"?
[y/n]
```

### ✅ Noobモードあり
```
📋 私がお願いしたいこと:
ファイル "contracts/nda-template.md" を開いて中身を読みたいです。

🎯 理由:
あなたがNDAテンプレートの確認を依頼したので、まず内容を読む必要があります。

⚠️ リスク: 🟢 低
これはファイルを読むだけで、変更や削除はしません。ドキュメントを開いて見るのと同じです。

✅ 承認いただければ: ファイルを読み、その内容をお伝えします。
❌ 拒否されれば: ファイルを見ることができないので、別の方法を考えます。

[y/n]
```

## 3. Bashコマンド — 安全なコマンド

### ❌ Noobモードなし
```
Allow tool: bash with command "grep -r 'indemnification' ./contracts/"?
[y/n]
```

### ✅ Noobモードあり
```
📋 私がお願いしたいこと:
"contracts"フォルダ内のすべてのファイルから「indemnification」という単語を検索したいです。

🎯 理由:
契約書ファイル全体でindemnificationの記述を探すよう依頼されました。

⚠️ リスク: 🔴 高（ただし今回は安全）
コマンド実行は通常リスクが高いですが、このコマンドは検索のみで、変更や削除はしません。

✅ 承認いただければ: "indemnification"が含まれるすべてのファイルを検索してお見せします。
❌ 拒否されれば: ファイルを一つずつ読む方法もありますが、時間がかかります。

[y/n]
```

## 4. Bashコマンド — リスクのあるコマンド

### ❌ Noobモードなし
```
Allow tool: bash with command "rm -rf node_modules && npm install"?
[y/n]
```

### ✅ Noobモードあり
```
📋 私がお願いしたいこと:
(1) ダウンロード済みのソフトウェアライブラリが入った "node_modules" フォルダを削除し、(2) それらを新たに再ダウンロードしたいです。

🎯 理由:
一部のライブラリが壊れているようです。削除して再ダウンロードするのが一般的な対処法です。

⚠️ リスク: 🔴 高
最初のコマンドはフォルダ全体を削除しますが、すぐに再ダウンロードするのでデータは失われません。所要時間は1〜2分程度です。

✅ 承認いただければ: 古いライブラリを削除し、新しいコピーをダウンロードします。プロジェクトファイルには影響ありません。
❌ 拒否されれば: 壊れたライブラリは残り、エラーが続く可能性があります。

[y/n]
```

## 7. ビルドエラー出力

### ❌ Noobモードなし
```
npm ERR! code ERESOLVE
npm ERR! ERESOLVE unable to resolve dependency tree
npm ERR! Found: react@18.2.0
npm ERR! node_modules/react
npm ERR!   react@"^18.2.0" from the root project
npm ERR! Could not resolve dependency:
npm ERR!   peer react@"^17.0.0" from react-beautiful-dnd@13.1.1
```

### ✅ Noobモードあり
```
❌ 問題の内容:
2つのソフトウェアライブラリが同じツール（React）の異なるバージョンを要求しており、互換性がありません。

💡 意味すること:
スマホのアプリがそれぞれ異なるiOSバージョンを必要とするようなものです。 "react-beautiful-dnd" は古いReact（17）を必要としますが、このプロジェクトは新しいReact（18）を使っています。

🔧 対処法:
選択肢A: "react-beautiful-dnd" をReact 18対応の新しいバージョンに更新する
選択肢B: 強制的にインストールする（後で微妙な問題が起きる可能性あり）
選択肢C: React 18対応の代替ライブラリを探す

💡 おすすめは選択肢Aです。最もクリーンな解決策です。
```

## 11. ユーザーへの技術的質問

### ❌ Noobモードなし
```
Should I use a relative or absolute path for the import?
```

### ✅ Noobモードあり
```
ご意見をお聞きしたいことがあります:

**選択肢A: 相対パス**
意味: このファイルの場所を基準にファイルを参照する（「隣のフォルダ」と言うようなもの）
トレードオフ: ファイルが近くにある場合は便利ですが、移動すると壊れることがあります。

**選択肢B: 絶対パス**
意味: プロジェクトのルートからの完全なパスで参照する（「住所を完全に指定する」ようなもの）
トレードオフ: ファイルの場所が変わっても動作しますが、記述が長くなります。

💡 私のおすすめは選択肢Bです。プロジェクト構造が変わっても壊れにくいです。
```

## 14. 複雑なエラーメッセージ

### ❌ Noobモードなし
```
Error: EACCES: permission denied, open '/usr/local/lib/node_modules/@github/copilot/package.json'
    at Object.openSync (node:fs:603:3)
    at Object.readFileSync (node:fs:471:35)
```

### ✅ Noobモードあり
```
❌ 問題の内容:
ユーザーアカウントにファイルの変更権限がなく、アクセスが拒否されました。

💡 意味すること:
ファイルは管理者権限が必要な保護されたシステムフォルダ（"/usr/local/..."）にあります。これは重要なシステムファイルの誤変更を防ぐセキュリティ機能です。

🔧 対処法:
選択肢A: 管理者権限（"sudo"）でコマンドを実行し、一時的に権限を上げる
選択肢B: 特別な権限が不要な別の場所にインストールする

💡 おすすめは選択肢Bです。安全で管理者権限が不要です。
```
