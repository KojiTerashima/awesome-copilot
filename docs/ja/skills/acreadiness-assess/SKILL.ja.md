# /acreadiness-assess — AI 対応度評価

ユーザーが **AI 対応性評価**、**対応性チェック**、**監査**を要求した場合、またはリポジトリが**AI 対応性をどの程度確認**したい場合には、このスキルを使用します。

このスキルは、AgentRC の **測定 → 生成 → 維持** ループの *測定* ステップです。結果として、ユーザーが `file://` で開くか、リポジトリにコミットできる自己完結型の HTML ダッシュボードが作成されます。

## ステップ

1. **前提条件を確認してください。** ノード 20 以降は PATH 上にある必要があります。不明な場合は、`node --version` を実行してください。

2. **ポリシーを決定します** (オプションですが推奨されます):
   - ユーザーが `--policy <source>` を指定した場合は、それをキャプチャします。
   - それ以外の場合は、`policies` 配列について `agentrc.config.json` を確認してください。
   - どちらでもない場合は、ポリシーなしで実行します (組み込みのデフォルト)。
   - ポリシーの入門書として、`acreadiness-policy` スキルを提案してください。

3. **準備スキャンを実行**し、構造化された出力をリポジトリ ルートで使用します。
   ```bash
   npx -y github:microsoft/agentrc readiness --json [--policy <source>] [--per-area]
   ```
`CommandResult<T>` JSON エンベロープは、次のステップの入力です。

4. **`ai-readiness-reporter` カスタム エージェント**に引き渡して、JSON を解釈して `reports/index.html` を生成します。エージェントはバンドルされたテンプレート `report-template.html` (このスキルと一緒に出荷される) を介してレンダリングするため、すべてのレポートの外観と操作性は同じになります。エージェント:
   - バンドルされている `report-template.html` を読み取り、プレースホルダーを実際のデータに置き換えます。
   - すべての CSS をインライン化し、単一の静的ファイルを配布します (`file://` で動作します)。
   - 成熟度レベル、総合スコア、グレード、合格率としきい値をレンダリングします。
   - **Repo Health** (8) と **AI Setup** (1) の 9 つの柱すべてを、*測定内容*、*AI にとって重要な理由*、*現在の状態*、および *具体的な推奨事項*で分類します。
   - すべての柱に **AI 関連性** バッジ (高 / 中 / 低) のタグを付けます。
   - **エクストラ**を個別に表示します (スコアに影響を与えることはありません)。
   - 無効化/上書きされた基準としきい値を含む **アクティブ ポリシー** を表示します。
   - **優先順位の高い修復計画** (🔴 最初に修正 / 🟡 次の修正 / 🔵 計画) を作成します。
   - 再利用のために生の AgentRC JSON を埋め込みます。

5. **レポートの保存場所** (`reports/index.html`) とその開き方をユーザーに伝えます。チャットで要約します: 成熟度レベル、総合スコア、上位 3 つの最低の柱、および最もレバレッジが高い 1 つの次のアクション (ほとんどの場合: `acreadiness-generate-instructions` スキルを実行します)。

## 注意事項

- AgentRC には組み込みの HTML レンダラー (`--visual` / `--output report.html`) もありますが、その出力は意図的に汎用的です。このスキルは、カスタム エージェントを介して、カスタマイズされた独自のダッシュボードを生成します。これは、メトリクス ダンプというよりもコード レビューに近いものです。
- CI ゲーティングの場合は、`agentrc readiness --fail-level <n>` (1 ～ 5) を推奨します。
- このスキルは、`reports/index.html` の作成以外にリポジトリ ファイルを変更することはありません。
