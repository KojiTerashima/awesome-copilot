# Azure スマート シティ IoT ソリューション ビルダー

このスキルを使用して、Azure IoT およびスマート シティ ソリューションの完全なワークフローを再構築および標準化します。

## いつ使用するか

ユーザーが次のようなことを要求した場合に、このスキルを使用します。

- 「Azure上にIoTソリューションを構築したい」
- 「交通、照明、廃棄物のためのスマートシティアーキテクチャ」
- 「デバイス、分析、アラートを接続するにはどうすればよいですか?」
- 「都市プラットフォームのロードマップとバックログが必要です」

## 目的

- 大まかなアイデアを展開可能なアーキテクチャに変換します。
- 可能な限り、既存の Azure 中心のスキルを再利用します。
- チームが実装できる具体的な成果物を作成します。

## ワークフロー

### 0) 必須のドキュメントレビュー (アーキテクチャの前に)

エッジ コンピューティングに関係するアーキテクチャまたはテクノロジの決定を提案する前に、まず Azure IoT Edge のドキュメントを確認してください。

- https://learn.microsoft.com/azure/iot-edge/

レビューする最小ページ数:

- Azure IoT エッジとは
- ランタイムアーキテクチャ
- サポートされているシステム
- バージョン履歴/リリースノート
- このシナリオに関連する Linux/Windows クイックスタート

ドキュメントを参照できない場合は、そのことを明示的に述べ、明確にマークされた仮定に基づいて続行します。

### 1) 範囲と制約

収集して確認します。

- 都市ドメイン: モビリティ、駐車場、大気質、水、エネルギー、公共の安全、廃棄物など。
- スケール: デバイスの数、テレメトリの頻度、保持、地域。
- レイテンシと可用性の目標。
- 規制とプライバシーの制約。
- 統合する既存のシステム (SCADA、GIS、ERP、チケット発行、API)。

### 2) 能力マップ

プラットフォームをレイヤーに分割します。

- デバイスとエッジ: オンボーディング、アイデンティティ、ファームウェア、OTA、エッジ処理。
- 取り込みとメッセージング: コマンドと制御、イベント ルーティング、バッファリング。
- データと分析: ホット パスとコールド パス、ダッシュボード、履歴分析。
- 運用: 可観測性、インシデント フロー、SLO。
- ガバナンス: RBAC、シークレット、ポリシー、ネットワーク分離。

### 3) Azureサービスの選択(参考)

- デバイスの接続: Azure IoT Hub、Azure IoT Operations、IoT Edge。
- イベント ストリーミング: Event Hubs、Service Bus、Event Grid。
- ストレージ: Blob Storage、Data Lake、Cosmos DB、SQL。
- 分析: Azure データ エクスプローラー、ストリーム分析、ファブリック/シナプス。
- API とアプリケーション: API Management、App Service、コンテナー アプリ、関数。
- 監視: Azure Monitor、Application Insights、Log Analytics。
- セキュリティ: Key Vault、Defender for IoT、プライベート エンドポイント、マネージド ID。

### 4) 非機能的なデザイン

以下を定義して文書化します。

- 信頼性モデル (ゾーン/リージョン、再試行、デッドレター処理、リプレイ)。
- セキュリティ制御 (ゼロトラスト、暗号化、シークレットローテーション、最小特権)。
- コスト管理 (保持層、適切なサイズ設定、自動スケーリング、ワークロードのスケジュール設定)。
- データのライフサイクル (生、厳選、集約、アーカイブ)。

### 5) 納品計画

段階的実行を作成します。

- フェーズ 1: パイロット地区または単一のユースケース。
- フェーズ 2: マルチドメインの統合。
- フェーズ 3: 都市規模の展開と最適化。

各フェーズには次のものが含まれます。

- 終了基準
- 依存関係
- リスクと緩和策
- KPIセット

### ローカル リポジトリの代替手段 (このリポジトリで使用)

ランタイム スキルが利用できない場合は、このリポジトリ内の既存のローカル スキルを優先します。

- `azure-architecture-autopilot` アーキテクチャの生成と改良用。
- `azure-resource-visualizer` (リソース関係図)。
- 役割選択のガイダンスについては `azure-role-selector` を参照してください。
- `az-cost-optimize` と `azure-pricing` はコストと価格の分析に使用されます。
- `azure-deployment-preflight` は展開前チェック用です。
- `appinsights-instrumentation` テレメトリ計測パターン用。

利用可能な特殊なスキルがない場合は、このスキルを継続し、前提条件を明確にしてください。

## 必要な出力アーティファクト

常に次の出力を提供します。

1. スマート シティ ソリューションの概要 (範囲、前提条件、制約)。
2. リファレンス アーキテクチャ (コンポーネントとデータ フロー)。
3. セキュリティとガバナンスのチェックリスト。
4. コストとスケーリング戦略。
5. 段階的な実装バックログ (エピックとマイルストーン)。

## 出力テンプレート

次の応答構造を使用します。

1. 背景と目的
2. 提案されたアーキテクチャ
3. テクノロジーに関する決定とトレードオフ
4. セキュリティ、運用、コストの管理
5. 段階的な実装計画
6. リスクと未解決の質問

## ガイドライン

- 前提条件を検証する前に展開にジャンプしないでください。
- 重要な都市のワークロードに対して単一リージョンの運用を推奨しないでください。
- 運用上の所有権 (インシデント、SLA、変更期間を誰が処理するか) を省略しないでください。
- 仮定と確認された事実を明確に区別します。
