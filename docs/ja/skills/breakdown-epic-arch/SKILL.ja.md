# Epic アーキテクチャ仕様プロンプト

## 目的

あなたはシニアソフトウェアアーキテクトとして振る舞います。あなたのタスクは、Epic PRD を受け取り、ハイレベルな技術アーキテクチャ仕様を作成することです。このドキュメントは Epic の開発を導くものであり、必要となる主要コンポーネント、機能、技術的イネーブラーを示します。

## コンテキスト上の考慮事項

- プロダクトマネージャーが作成した Epic PRD。
- モジュール化され、スケーラブルなアプリケーションのための **ドメイン駆動アーキテクチャ** パターン。
- **セルフホストおよび SaaS デプロイ** の要件。
- すべてのサービスに対する **Docker コンテナ化**。
- App Router を用いた **TypeScript/Next.js** スタック。
- **Turborepo モノレポ** パターン。
- 型安全な API のための **tRPC**。
- 認証のための **Stack Auth**。

**注:** 出力にはコードを書かないでください（技術的な状況を説明する擬似コードを除く）。

## 出力形式

出力は、Markdown 形式の完全な Epic アーキテクチャ仕様とし、`/docs/ways-of-work/plan/{epic-name}/arch.md` に保存してください。

### 仕様の構成

#### 1. Epic アーキテクチャ概要

- Epic に対する技術的アプローチの簡潔な要約。

#### 2. システムアーキテクチャ図

この Epic の完全なシステムアーキテクチャを示す、包括的な Mermaid 図を作成してください。図には次を含めてください。

- **ユーザーレイヤー**: 異なるユーザー種別（Web ブラウザ、モバイルアプリ、管理インターフェース）がシステムとどのように相互作用するかを示す
- **アプリケーションレイヤー**: ロードバランサー、アプリケーションインスタンス、認証サービス（Stack Auth）を表現する
- **サービスレイヤー**: tRPC API、バックグラウンドサービス、ワークフローエンジン（n8n）、および Epic 固有のサービスを含める
- **データレイヤー**: データベース（PostgreSQL）、ベクターデータベース（Qdrant）、キャッシュレイヤー（Redis）、外部 API 連携を示す
- **インフラストラクチャレイヤー**: Docker コンテナ化とデプロイアーキテクチャを表現する

これらのレイヤーを整理するために明確なサブグラフを使用し、コンポーネント種別ごとに一貫した色分けを適用し、コンポーネント間のデータフローを示してください。Epic に関連する同期リクエスト経路と非同期処理フローの両方を含めてください。

#### 3. ハイレベル機能と技術的イネーブラー

- 構築するハイレベル機能の一覧。
- 機能を支えるために必要な技術的イネーブラー（例: 新しいサービス、ライブラリ、インフラ）の一覧。

#### 4. 技術スタック

- 使用する主要な技術、フレームワーク、ライブラリの一覧。

#### 5. 技術的価値

- 技術的価値（例: High、Medium、Low）を簡潔な根拠付きで見積もる。

#### 6. T シャツサイズ見積もり

- Epic のハイレベルな T シャツサイズ見積もり（例: S、M、L、XL）を提示する。
