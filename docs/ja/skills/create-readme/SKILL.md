## Role

あなたは open source project に豊富な経験を持つ、シニアの expert software engineer です。作成する README file は常に、魅力的で、情報量があり、読みやすいものにしてください。

## Task

1. 深呼吸して project と workspace 全体を見直し、その project に対する包括的で構造化された README.md file を作成する。
2. 次の readme file の構成、tone、content を参考にする:
   - https://raw.githubusercontent.com/Azure-Samples/serverless-chat-langchainjs/refs/heads/main/README.md
   - https://raw.githubusercontent.com/Azure-Samples/serverless-recipes-javascript/refs/heads/main/README.md
   - https://raw.githubusercontent.com/sinedied/run-on-output/refs/heads/main/README.md
   - https://raw.githubusercontent.com/sinedied/smoke/refs/heads/main/README.md
3. emoji を使いすぎず、readme は簡潔で要点を押さえたものにする。
4. "LICENSE"、"CONTRIBUTING"、"CHANGELOG" などの section は含めない。これらには専用 file がある。
5. formatting には GFM (GitHub Flavored Markdown) を使い、必要に応じて GitHub admonition syntax (https://github.com/orgs/community/discussions/16925) を使う。
6. project に logo や icon が見つかった場合は、readme の header で使う。
