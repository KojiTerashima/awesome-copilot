# 取締役会・投資家コミュニケーション

取締役会ミーティング、投資家向けアップデート、経営層コミュニケーションを、信頼を築き意思決定を前進させる形で構造化しましょう。誰にも読まれないスライドデッキを作るためではありません。

## 使うべきタイミング

**トリガー:**
- 「取締役会ミーティングはどう準備すればいい？」
- 「投資家向けアップデートには何を入れるべき？」
- 「目標未達だった。どう伝えるべき？」
- 「取締役会デッキの構成」
- 「投資家へのアップデート頻度はどれくらいが適切？」
- 「うちの取締役会ミーティングは生産的じゃない」

**コンテキスト:**
- シードからグロースステージの企業
- 取締役会ミーティングの準備とフォローアップ
- 月次/四半期の投資家向けアップデート
- 未達や悪いニュースへの対応
- 取締役会から組織への戦略の展開

---

## コアフレームワーク

### 1. まずストーリーを語り、その後にデータを示す

**パターン:**

多くの取締役会ミーティングは、データの投げ込みから始まります。メトリクスのスライドが延々と続き、最後の10分のQ&Aで取締役が「結局何を意味するのか」を読み解こうとします。

これを逆にします。ナラティブが先、データはその確認です。

**進め方:**

まず、今どの地点にいるかを語ります。「これがARRです」ではなく、「この四半期の冒頭で何を信じていて、何を学び、今どこにいるか」を示します。その後で、ナラティブを裏づけるデータを示します。

**取締役会ミーティングの構成:**

**Pre-Read（48〜72時間前に送付）**
- 財務ダッシュボード（ARR、burn、runway、pipeline）
- 健全性インジケーター付きメトリクススコアカード（green/yellow/red）
- 市場コンテキストと戦略アップデートを含む2〜3ページのナラティブ要約
- ルール: 読めるものはプレゼンしない

**ミーティング本編（90〜120分）**

1. **市場コンテキストとPre-Readへの質問**（15分）
   - 前回ミーティング以降で市場に何が変わったか？
   - Pre-Readで不明確だった点を取締役が質問
   - データの再説明はしない

2. **CEO戦略アップデート — 「Three Things」**（15分）
   - **うまくいっていること**（勢いのある2〜3領域）
   - **うまくいっていないこと**（曖昧でない1〜2個の具体的ギャップ）
   - **それに対して何をしているか**（約束ではなく具体策）
   - ここは数字ではなくナラティブ

3. **意思決定事項**（30〜45分）
   - 取締役会の意見または承認が必要なテーマを1〜3件
   - 準備して臨む: 「XとYで意思決定したい。取締役会としてどう考えるか？」
   - 「次四半期に再検討」で終えず、決定を持ち帰る

4. **深掘り**（20〜30分）
   - 1テーマを深く扱う（ミーティングごとに持ち回り）
   - その領域の責任者を参加させる
   - 例: 価格戦略、競争環境、組織設計、市場拡大

5. **クロージング**（10分）
   - 決定事項とアクションオーナーを要約
   - クローズドセッション（経営陣なしで取締役会のみ）
   - CEOと取締役会議長でデブリーフ

**よくある失敗:**

- ナラティブより先にデータから入る（文脈がなく取締役会が数字で迷子になる）
- 複数の競合するナラティブが並立する（統合できない。一本の筋に絞る）
- 深掘りするテーマを増やしすぎる（全件が駆け足判断になる）
- 深掘りがない（取締役会が追認機関化する）
- 良いニュースで会議を埋める（勝ち話しか共有しないCEOは信頼されない）

### 2. 「Three Things」ナラティブモデル

**パターン:**

事業は複雑すぎて、1つの見出しでは要約できません。3つの明確なポイント — うまくいっていること、うまくいっていないこと、変えようとしていること — で、取締役会は数分で現在地と軌道を把握できます。

**うまくいっていること（2〜3領域）:**
具体的に。単に「営業は順調」ではなく、「初の6桁エンタープライズ契約を獲得し、商談モーションの妥当性を実証した」。勢いは定量で示します:
- 新製品ローンチの採用が進んでいる
- セールスモーションが成熟（初の大型顧客、再現可能な動きが見え始めた）
- コミュニティ/エコシステムのマイルストーン

**うまくいっていないこと（1〜2領域）:**
同じく具体的に。「課題がありました」ではなく、「セルフサーブ転換が弱い — 認知は強いがCVRが0.1%」。取締役会が必要なのは婉曲表現ではなく実際の問題です。

**それに対して何をしているか（各「うまくいっていないこと」に対して）:**
具体策を明示します。どんなプロダクト変更か？どんな組織変更か？タイムラインは？どのリソースを投入しているか？

**これが機能する理由:**

取締役は大量のアップデートを読みます。Three Thingsモデルは、頭の中の整理棚を提供します: 勢い（安心材料）、リスク（要注意）、当事者性（このチームは問題に対処できる）。これがないと、取締役会は単一の悪い指標に過剰反応するか、40枚デッキに埋もれた本質を見落とします。

### 3. 進捗は絶対値ではなく方向で示す

**パターン:**

ユーザー100Kを達成したかどうかは、それ単体では意味がありません。目標が50Kだったのか、200Kだったのかで意味は変わります。文脈がすべてです。数字だけでなく、目標に対する進捗を示します。

**進捗の示し方:**

- **On track:** 「目標はアクティブ開発者100K。現在70K。施策は計画どおりに機能。確度: 高」
- **At risk:** 「目標はアクティブ開発者100K。現在50K。獲得コストが想定より高い。新チャネルを検証中。修正目標: 85K。確度: 中」
- **Ahead:** 「目標はアクティブ開発者100K。現在95K。獲得予測を上回る。新規パートナーシップが成長を加速。確度: 非常に高い」

**ルール:**
1. 目標を先に置く（すべてのメトリクスにターゲットが必要）
2. 絶対値だけでなく、目標達成率（%）で進捗を示す
3. 未達を認め、ピボットを説明する
4. 軌道に基づいて確度レベルを示す

**よくある失敗:**

未達時に目標をすり替えること。取締役会は見ています。Q1目標が100Kで実績60Kなら、Q2を75Kにして「修正ガイダンス」と呼んではいけません。未達を明示し、理由を説明し、回復計画を示す。信頼はメトリクスより速く複利で積み上がります。

### 4. 4層メトリクス階層

**パターン:**

メトリクスが多すぎると取締役会は混乱し、少なすぎると重要なシグナルを見逃します。4層で構造化し、四半期ごとに変えないこと。

**Tier 1: North Star（1メトリクス）**
会社の健全性を最もよく表す単一指標。
- 例: ARR、active users、tasks completed
- 現在値だけでなくトレンドラインを示す
- 他を忘れても取締役会に覚えていてほしい指標

**Tier 2: Driver Metrics（3〜5メトリクス）**
North Starを予測する先行指標。
- User acquisition rate
- Retention curves（先月アクティブだった何人が今月もアクティブか？）
- Feature adoption（主要機能を使うユーザー割合）
- DAU/MAU ratio
- Pipeline coverage
- 追う理由: 売上影響前の早期警戒

**Tier 3: Health Metrics（3〜5メトリクス）**
チーム/オペレーションの健全性シグナル。
- Burn rateとrunway
- Headcount vs plan
- Engineering velocity / shipping pace
- NPSまたは顧客満足度
- 追う理由: 成長を制約するキャパシティを把握するため

**Tier 4: Red Flags（2〜3しきい値）**
しきい値を超えたら即時対応が必要な指標。
- Churn rateがX%超
- CACが$Y超
- Retention低下がZ%超
- 追う理由: 監視だけでなく戦略対話のトリガー

**運用ルール:**

1. **毎四半期同じメトリクス。** 4〜6四半期の実績列を作る。新規追加は可、ただし既存を落とさない。
2. **各メトリクスに1文の文脈説明。** 何を示すか？良い/悪いどちらか？示唆は何か？
3. **常に実績 vs 計画。** 計画値なしでメトリクスを出さない。会話は差分で生まれる。
4. **必要なら分解。** 総量はセグメントを隠す。顧客タイプ、セグメント、製品ラインなど、平均が現実を隠す場所で分ける。
5. **健全性インジケーターを使う。** green/yellow/redで即時評価。取締役会が全体を走査し、yellow/redへズームできる。

**よくある失敗:**

今期見栄えの良い数字に合わせて、見せるメトリクスを変えること。取締役会はすぐ気づきます。数字の信頼を失う最速ルートです。毎回同じダッシュボードを出す。悪い指標が出たら、それこそが議論です。

### 5. 悪いニュースは取締役会に聞かれる前に出す

**パターン:**

悪いニュースを遅らせたり、砂糖をかけて伝えると、取締役会の信頼は削れます。悪いニュース自体は受け止められます。サプライズは受け止められません。遅い意思決定も嫌われます。

**Pre-Briefパターン:**

悪いニュースを全体の取締役会で出す前に、48〜72時間前にリードディレクターへ事前ブリーフします。

- **誰に:** 取締役会議長または最も経験豊富な取締役
- **何を:** 問題、評価、対応プラン
- **なぜ:** 全体への伝え方を整え、驚きを避け、既視のパターンから助言が得られる可能性があるため

そのうえで、全取締役会に短いメールを送ります:

「次回ミーティング前に共有したい点があります。[具体的な問題]。現時点で分かっていること、まだ分かっていないこと、対応策は以下です。取締役会ミーティングで詳細を更新します。」

**悪いニュースのフレームワーク:**

すべての悪いニュースは、次の4要素で伝える:

1. **何が起きたか**（具体的に1文、防御的でない）
   - 「エンタープライズ新規顧客10件のQ1目標に未達で、実績は7件でした」

2. **なぜ起きたか**（言い訳でなく根本原因）
   - 「製品ギャップを十分早く診断できず、顧客評価期間が後ろ倒しになりました」
   - 自分たちの責任として語る: 「需要シグナルを読み違えた」のであって「市場が変化した」ではない

3. **影響は何か**（重大性を正直に）
   - 「Q1 ARRに約$50Kの影響があり、当初ガイダンスを下回ります」

4. **何をするか**（具体アクション、オーナー、タイムライン）
   - 「初期段階で製品準備度を判定するよう営業モーションを変更。Q2目標を15に修正（Q1の積み残し7を含む）」

**未達を“伝えてはいけない”伝え方:**
- 「Q1目標は未達でしたが、パイプラインは強いです」
- 「外部要因で案件が遅れましたが、Q2には自信があります」
- 「実装面で課題はありましたが、今は解決済みです」

どれも曖昧で、防御的で、根本原因も計画も示していません。

**フォロースルーパターン:**

以降の取締役会アップデートでは、過去に挙げた課題を必ず参照します: 「前四半期に[課題]を共有しました。現状は[進捗]です。ステータス: [resolved / in progress / escalating]。」

これにより、フォロースルーの実績が積み上がります。取締役会は、自分の課題を追い続ける人を覚えています。

**よくある失敗:**

悪いニュースを良いニュースで挟んで気づかれないようにすること。取締役はすぐ見抜きます。悪いニュースそのものより、信頼を傷つけます。

### 6. 月次投資家アップデート

**パターン:**

多くの創業者は投資家アップデートを四半期でも送らないことがあります。優れた創業者は毎月送ります。状況が悪いときこそ。とくに悪いときこそ。

**なぜ月次か:**
- コールを設定せずに投資家の関与を維持できる
- 助け（紹介、助言、ブリッジ）が必要なとき、投資家がすでに文脈を持っている
- 継続性はオペレーション規律のシグナル。不定期更新は混乱のシグナル

**フォーマット:**

**件名:** [Company Name] — [Month] Update

**冒頭（1段落）:**
見出しは1つ。文脈は簡潔に。

**TL;DR（3 bullets）:**
- いま最重要の数字1つ
- 勝ち1つ（具体的に — 顧客名、案件規模、マイルストーン）
- 課題1つ（対応策付き）

**主要メトリクス（毎月同じ表）:**

| Metric | This Month | Last Month | 3-Mo Avg | vs Plan |
|--------|-----------|------------|----------|---------|
| ARR | | | | |
| MRR Growth | | | | |
| Burn Rate | | | | |
| Runway (months) | | | | |
| Pipeline | | | | |
| Customers | | | | |

前回から変化のないメトリクスは含めない。新しい動きに集中する。

**主要アップデート（2〜3 bullets）:**
- 重要採用、製品ローンチ、提携/顧客獲得
- 戦略ピボットや軌道修正
- 意味のある具体性で書く

**Asks（1〜2 bullets）:**
- どんな支援が必要か？紹介、採用リード、戦略助言
- 具体的に: 「[company type]のVP Engへの紹介希望」であり、「エンジニア人材を探しています」ではない

**運用リズムのルール:**
- 毎月同じ曜日で送る。第一月曜でも最終金曜でもよいが、決めたら絶対に欠かさない
- 重大ニュースは1週間以内に送る（次回定期更新まで寝かせない）
- 資金調達中は: 見込み投資家には週次、既存投資家には月次

**よくある失敗:**

調子が良いときだけ送ること。6か月の好調報告の後に沈黙すると、投資家には「何を隠しているか」が伝わります。

### 7. Burnは規律の話、Revenueは牽引力の話

**パターン:**

取締役会向け財務コミュニケーションには、別々の2つの物語があります。混同しないこと。

**Burnコミュニケーション:**
- 月次レート、runway（月数）、YoY改善
- 効率改善（何を削減し、何を最適化したか）
- 資本計画: 確保済み、目標、タイムライン

Burnの物語は: 「私たちは規律ある運営者で、資本の持ちを伸ばせる」

**Revenueコミュニケーション:**
- MoM成長、CAC、LTV、回収期間
- 顧客セグメント（self-serve vs enterprise、構成比は？）
- 収益化計画とタイムライン

Revenueの物語は: 「私たちは牽引力を持ち、それを伸ばす方法を理解している」

**両者を接続する:**
最良の財務コミュニケーションは、「燃焼を抑えながら成長を加速している」を示します。これはオペレーティングレバレッジの証拠であり、取締役会にとって最も説得力のあるメッセージです。

**よくある失敗:**

Burnと成長を混同すること。「急成長しています」と言いつつburn rateが上がると、取締役会は成長を買っていると受け取ります。「burnを40%削減しました」と言いつつ成長が止まると、サバイバルモードだと受け取ります。2つの物語を分けて語り、そのうえでつなげてください。

### 8. 取締役会から組織への戦略カスケード

**パターン:**

取締役会室で決まった戦略は、チームが知らなければ意味がありません。体系的なコミュニケーションカスケードを作りましょう。

**4つのレベル:**

**Level 1: Executive Team（週次）**
- 戦略優先事項と顕在化しつつあるリスク
- すり合わせが必要な主要意思決定

**Level 2: Extended Leadership（隔週）**
- 各機能に戦略がどう影響するか
- 主要優先事項と成功の測定方法

**Level 3: All-Hands（月次、60分）**
- リーダーシップアップデート（15分）: 現在地と変化点
- 勝ちの共有（10分）: 顧客、ローンチ、人
- 深掘り（20分）: 戦略施策を1件詳細に
- Q&A（15分）: 本音の質問に本音で回答

**Level 4: Team-Specific（継続）**
- チーム目標が会社戦略とどうつながるか
- このチームにおける成功定義

**テスト:**

無作為に社員1人を選ぶ。会社戦略を説明できるか？できないならカスケードは壊れています。経営陣の頭の中にしかない戦略は戦略ではなく、秘密です。

**OKRをカスケードに接続する:**
- 会社OKRは戦略から
- 機能OKRは会社に整合
- チームOKRは機能に整合
- 個人が自分の貢献を理解している

**よくある失敗:**

メッセージの不整合。会社の向かう先をリーダーごとに別々に語ると、組織は相反する目標に最適化します。戦略を書き下ろしてください。1ページで。全員が同じ言葉を使うように。

## Decision Trees

### Board Meeting vs Investor Update

```
Is this a full board meeting?
├─ Yes → Full structure: pre-read + Three Things + decisions + deep dive
└─ No → Continue...
    │
    Is this a major event (fundraise close, big miss, key hire)?
    ├─ Yes → Ad-hoc update immediately (don't wait for schedule)
    └─ No → Monthly investor update format
```

### メトリクスの示し方

```
Did you hit the target?
├─ Yes → State it, move on. Don't over-celebrate.
└─ No → Continue...
    │
    Do you understand why?
    ├─ Yes → Root cause + plan + revised timeline
    └─ No → Say "we're diagnosing" + what you're doing to find out
        │
        Is the miss material (affects runway, strategy, or board confidence)?
        ├─ Yes → Pre-brief lead director before board meeting
        └─ No → Include in Three Things narrative, "what's not working"
```

## よくある失敗

**1. 取締役会ミーティングをステータス報告にする**
取締役は読めます。Pre-Readを送りましょう。ミーティングは意思決定と議論に使い、データの読み上げには使わない。

**2. 四半期ごとにメトリクスを変える**
メトリクスの一貫性は信頼を生みます。悪く見える指標を外し、良く見える指標に差し替えた瞬間、「この数字は信用できない」と伝えたことになります。

**3. 明確なaskがない**
投資家アップデートでも取締役会ミーティングでも、毎回askを置くべきです。紹介、助言、承認、時間的猶予。投資家は助けたいのです。求めなければ離れていきます。

**4. 説明ではなく弁明になる**
未達の言い訳に10分使うと、取締役会には防御的に聞こえます。未達を述べ、原因を述べ、計画を述べる。次へ進む。

**5. 戦略が取締役会室にとどまる**
チームが戦略を説明できないなら、伝わっていません。カスケードしなければ存在しないのと同じです。

**6. 取締役会ミーティングでのサプライズ**
悪いニュースが取締役会で初出になるべきではありません。リードディレクターに事前ブリーフし、フラグメールを送る。ミーティング前に消化できるようにする。

## クイックリファレンス

**取締役会ミーティングの流れ:**
Pre-read（48〜72時間前）→ 質問（15分）→ Three Thingsナラティブ（15分）→ 意思決定事項（30〜45分）→ 深掘り（20〜30分）→ クローズドセッション（10分）

**Three Thingsモデル:**
What's working + What's not + What we're doing about it

**メトリクス階層:**
North star（1）→ Drivers（3〜5）→ Health（3〜5）→ Red flags（2〜3しきい値）

**悪いニュースのプロトコル:**
リードディレクターへ事前ブリーフ（48〜72時間）→ 全取締役会へフラグメール → 何が起きたか → なぜ → 影響 → 計画 → 以降の各ミーティングでフォローアップ

**月次投資家アップデート:**
TL;DR（3 bullets）→ 同一メトリクス表 → 主要アップデート（2〜3）→ 具体的ask（1〜2）

**コミュニケーションカスケード:**
Exec（週次）→ Leadership（隔週）→ All-hands（月次）→ Team（継続）
