# エンタープライズアカウントプランニング

エンタープライズ案件における戦略的なアカウントプランニングと実行。複雑な営業サイクルを再現性のある勝ち筋に変える — 少なくとも、何か月も無駄にする前に案件が死にかけていることを見抜けるようにする。

## 使うべきタイミング

**トリガー:**
- 「このエンタープライズ案件、どう計画すればいい？」
- 「この案件、3か月動いてるのに、なぜクローズしないの？」
- 「フルのアカウントプランを作るべき？それとも簡易版？」
- 「この案件が本当に進んでいるか、どう判断する？」
- 「MEDDICCのクオリフィケーション」
- 「相互アクションプランの作成」

**コンテキスト:**
- 平均ACVを上回る戦略案件
- 複数のステークホルダーが関与
- 営業サイクルが60日超
- 複雑な購買プロセス（法務、調達、セキュリティ）
- エンタープライズまたはミッドマーケットアカウント

## コアフレームワーク

### 1. MAPが3週間更新されていないなら、その案件は死んでいる

**私が見てきたパターン:**

Mutual Action Plan（MAP）は、案件健全性を示す最良の指標です。パイプラインステージでも、口約束でも、「彼らは製品を気に入っている」という話でもありません。

**MAPがすべてを物語る:**

**健全な案件:**
- MAPが毎週更新される
- 顧客側が自分たちのアクションアイテムを追加する
- 双方がスケジュール通りにタスクを完了する
- 新しいステークホルダーがMAPに登場する
- 日付が前倒しになる（先送りされない）

**死にかけの案件:**
- MAPの最終更新が3週間以上前
- アクションアイテムが自社側にしかない
- 顧客タスクが何週間も「pending」のまま
- 新規ステークホルダーが関与しない
- すべての日付が過去になっている

**なぜこうなるのか:**

案件が本物なら、顧客は実現したいと思っています。実際に動き、関係者を巻き込み、社内プロセスを進めます。

案件が死にかけると、あなたが全部やる状態になります。相手は「忙しくて」。そして「来週連絡します」。エコノミックバイヤーは「出張中」。

**3週間ルール:**

MAPが3週間更新されていないなら、その案件は死んでいます — まだ気づいていないだけです。**11年間で、停滞したMAPのまま成約した案件を一度も見たことがありません。**

**何をすべきか:**

**沈黙1週目:** MAP更新を送る: 「ここまで完了しました。[具体的な顧客アクション]の進捗はいかがですか？」

**沈黙2週目:** チャンピオンにエスカレーション: 「MAPについて返信がありません。[日付]に向けてまだ順調でしょうか？優先順位が変わったなら教えてください。」

**沈黙3週目:** 案件から外すかリセット: 「タイミングがまだ合わないように見えます。[期間]で一度止めて再接続しましょうか？それとも私がお手伝いできるブロッカーがありますか？」

**よくあるミス:**

「欲しいと言っていたから」で案件をパイプラインに残し続けること。口頭の関心 ≠ 行動です。相手が動いていないなら、買っていません。

### 2. EBディスカバリー問題（なぜ案件が8週目で死ぬのか）

**パターン:**

案件開始から8週間。POCは大成功。チャンピオンはあなたを高く評価。技術検証も完了。そこで提案書を送る。

その後: 音信不通。

**何が起きたか？** エコノミックバイヤーに会っていなかったのです。

**エコノミックバイヤー（EB）とは、次の人です:**
- 予算配分をコントロールする
- 最終購入判断を下す
- 契約にサインする

**違うのは:**
- あなたのチャンピオン（影響はあるが決定しない）
- テクニカルリード（検証はするが購入しない）
- デモに1回だけ参加したVP（助言はするがサインしない）

**EBへのアクセスなしで案件が死ぬ理由:**

あなたはチャンピオンの前提でビジネスケースを作りました。だがEBの優先順位は違います:
- チャンピオンが気にすること: 自チームの課題解決
- EBが気にすること: ROI、リスク低減、戦略整合

チャンピオン経由で提案書をEBに送ると、EBにはこう見えます:
- 文脈のない価格
- 自分が言語化していない課題への解決策
- まだ評価していないリスク

**結果:** 案件は停滞または失注。

**フレームワーク: EBバリデーションチェックリスト**

提案書送付前に確認:

- [ ] EBを特定したか？（氏名、役職、チャンピオン確認済み）
- [ ] EBに会ったか？（最低でもビデオ通話、理想は対面）
- [ ] EBは課題認識に同意しているか？（あなたの言葉ではなく、EB自身の言葉で）
- [ ] EBは成功指標に同意しているか？（ROIの測定方法）
- [ ] EBは価格帯を把握しているか？（概算を話しており、驚きがない）
- [ ] EBはタイムラインを理解しているか？（実装、稼働開始、価値実現）

**1つでも「いいえ」なら、まだ提案書を送らないこと。**

**EBへのアクセスを得る方法:**

**チャンピオンに聞く:**
「価格を最終化する前に、[EB名]と15分だけお話して、成果とタイムラインの認識を揃えたいです。つないでいただけますか？」

**チャンピオンが拒む場合:** 「私が対応します、あなたは話さなくて大丈夫です」
→ これは危険信号。チャンピオンがアクセスを持っていない（本物のチャンピオンではない）か、EBに案件を止められるのを恐れている（つまり案件が弱い）かのどちらかです。

**押し返す:**
「お気持ちはよく分かります。同時に、[EB]が価格を見る前に価値全体を理解できるようにしたいです。私の経験では、エコノミックバイヤーが早期に関与しないと、調達で案件が遅れます。短い認識合わせのコールを設定できますか？」

**よくあるミス:**

EBとの面談を「あると良いもの」と扱うこと。$50K超の案件では必須です。EBアクセスなし = 案件なし。

### 3. パーソナルウィンマッピング（人は自分のために買う）

**パターン:**

エンタープライズソフトウェアの購入は委員会で決まります。だが、委員会は買いません。**買うのは人です。**

そして人は個人的な理由で買います:
- キャリアアップ
- 上司への見栄え
- 自分の負荷軽減
- 保身（CYA）
- 自分の判断の正しさを証明
- 無能に見られないこと

**フレームワーク: パーソナルウィン特定**

各ステークホルダーごとに、次をマップします:

**職務上の勝ち:**
- これが成功したら、何で評価されるか？
- 個人的にどんな痛みが消えるか？
- どうすればその人の評価が上がるか？

**職務上のリスク:**
- 失敗したらその人に何が起きるか？
- うまくいかなかった場合の評判コストは？
- 社内で誰が懐疑的か？

**個人的動機:**
- 新任か？（短期の勝ちが必要）
- 予算削減に直面しているか？（支出正当化が必要）
- 昇進候補か？（目に見える成果が必要）
- 過去にベンダーで失敗したか？（リスク回避が強い）

**例: VP of Engineering**

**職務上の勝ち:**
- チームのオンコール負担を減らす（彼女への不満が減る）
- インシデント対応を高速化（QBRで見栄えが良い）
- より良いエンジニア人材を惹きつける（モダンなツール群）

**職務上のリスク:**
- チームが新ツールを拒否（押し付けたと思われる）
- 移行失敗（ダウンタイム、インシデント）
- ベンダー失敗（選定責任を問われる）

**個人的動機:**
- 就任6か月の新任で、成果が必要
- 稼働率指標の改善プレッシャーがある
- 過去に彼女が選んだ監視ツールが失敗した

**これでピッチがどう変わるか:**

**一般的なピッチ:**
「当社プラットフォームはインシデント対応時間を40%改善します。」

**パーソナルウィンのピッチ:**
「オンコール負担でチームが疲弊しているとお話しされていましたよね。導入チームでは初月にオンコールページ数が40%減る事例があり、離職防止に効きます。加えて、取締役会向けに稼働率指標を重視されているので、対応時間改善はQBRダッシュボードにもすぐ反映されます。」

**違い:**

Generic = 事業ケース  
Personal = キャリアケース

どちらも重要です。ただ、成約を決めるのはパーソナルウィンです。

**よくあるミス:**

事業課題にしか売らないこと。「コスト削減できます。効率改善できます。」これは必要ですが十分ではありません。**人は“自分に何があるか”を個人レベルで理解する必要があります。**

### 4. エンタープライズアカウントプランの構造（4つの構成要素）

完全なアカウントプランは、相互につながる4つの要素で構成されます。各要素が他を支えます。

**構成要素1: アカウントサマリー**
- 企業基本情報（本社、規模、業界、子会社）
- 技術環境（インフラ、ツール、プラットフォーム）
- 主要な全社施策（プレス、年次報告書、LinkedInから）
- 仮説: 「どう支援できるか？」（接触前に書く）
- LinkedInキーワード分析（あなたの領域への投資度合いを定量化）

**構成要素2: 組織図**
- 関連コンタクトを網羅: 氏名、役職、所在地、LinkedIn、メール、電話、メモ
- メモには記録: 担当領域、技術専門性、パーソナルウィン
- 階層横断で含める: C-suite、ディレクター、アーキテクト、リード、スペシャリスト
- バイヤーだけでなく、影響者・利用者・潜在ブロッカーもマップする

**構成要素3: オポチュニティプラン（MEDDICC）**
- **M - Metrics**: 顧客は成功をどう測るか？（EBと合意済み）
- **E - Economic Buyer**: 予算権限者は誰か？会っているか？
- **D - Decision Criteria**: 何を基準に意思決定するか？（技術、ビジネス、政治）
- **D - Decision Process**: 購買プロセスは？（調達、法務、セキュリティ審査）
- **I - Identified Pain**: 具体的にどんな痛みを顧客が語ったか？（あなたの言葉でなく顧客の言葉で）
- **C - Champion**: アカウント内であなたの代わりに積極的に売ってくれる人は誰か？
- **C - Competition**: 他にどこを評価しているか？競争構図は？

加えて: 課題/リスク表（緩和計画、必要支援、責任者を含む）

**構成要素4: 相互アクションプラン（MAP）**
- 共同タイムライン: Action, Your Owner, Customer Owner, Others Involved, Due Date
- 双方にアクションが必要 — 自社側だけなら、それは案件でなくデモ
- ステータス追跡（complete/in-progress）
- 定例チェックインの進行アジェンダとしてMAPを使う
- **MAPが3週間更新されなければ、案件は死んでいる**

**判断基準:**

フルアカウントプランは、潜在案件規模で上位10-20%のアカウントに投資する価値があります。その他は簡易版（summary + MEDDICC + next steps）を使う。

**よくあるミス:**
- 案件進行後にアカウントプランを作る（初回接触前に作る）
- MAPを毎週更新しない（停滞MAP = 停滞案件）
- MEDDICCを検証情報ではなく推測で埋める
- 明白な連絡先だけをマップして組織図を作らない
- 各ステークホルダーのパーソナルウィンを追跡しない

### 5. アカウントインテリジェンスのためのLinkedInキーワード分析

戦略アカウントに接触する前に、LinkedInであなたの領域への投資度合いを定量化する。

**実行方法:**

1. あなたの領域に関連するキーワードを8〜10個定義する（例: カテゴリ用語、技術職、ワークフロー用語）
2. LinkedInで「[company name] + [keyword]」を検索し、件数を記録する
3. 集中度をマッピング: どの拠点か？どの部門か？
4. 外れ値を特定（特定部門でキーワード集中が高いのは成熟度シグナル）

**なぜ有効か:**

ある企業のプロフィールに「SRE」が50人いれば、サイト信頼性の成熟度は高い。2人なら、高度なオブザーバビリティツール導入にはまだ早い。

これで分かること:
- そのアカウントを追うべきか（チーム体制があるか）
- 誰を狙うべきか（集中している場所はどこか）
- どうパーソナライズしてアプローチするか（彼ら固有の文脈に言及）

**例:**

「[Company] + DevOps」を検索:
- 120件 → DevOps組織が成熟、適合度高
- 5件 → 初期段階、まだ準備不足

「[Company] + SRE」を検索:
- 50件 → 信頼性に関心あり、稼働率/インシデント削減で訴求
- 0件 → SRE価値提案を先頭に出さない

**よくあるミス:**
- キーワード（一貫性あり）ではなく役職名（ばらつき大）だけを検索する
- 全従業員数との比較をしない
- 分析を更新しない（採用トレンドは四半期で変わる）

### 6. 統合セールスプロセス（ステージゲート）

エンタープライズセールスは、明確な出口基準を持つ定義済みステージで進みます。基準を満たさずにステージを進めないこと。

**Stage 0 — Pipeline Generation:** Prospecting → Qualified interest confirmed  
**Stage 1 — Discovery:** Environment/pain/requirements → Pain identified, stakeholders mapped  
**Stage 2 — Demonstrating:** Product demo, champion building → Champion identified  
**Stage 3 — Proving Value:** POC/trial → Technical validation complete  
**Stage 4 — Proposal:** Pricing, terms, scope → Proposal delivered, EB aligned  
**Stage 5 — Paper Process:** Legal, procurement, security → Approvals secured  
**Stage 6 — Closed Won:** Deal signed → Customer success handoff

**出口基準は重要:**

Stage 2 → Stage 3 へは、チャンピオンがいるまで進めない。  
Stage 3 → Stage 4 へは、POC成功基準を満たすまで進めない。  
Stage 4 → Stage 5 へは、EB承認があるまで進めない。

**よくあるミス:**

基準ではなく活動でステージを進めること。「デモしたからStage 3」— でもPOC合意がないなら、まだStage 2です。

## 意思決定ツリー

### フルアカウントプランは必要か？

```
Is deal size above average ACV?
├─ No → Simplified plan (summary + MEDDICC)
└─ Yes → Continue...
    │
    Sales cycle >60 days?
    ├─ Yes → Full account plan
    └─ No → Simplified plan
```

### この案件は本当に進んでいるか？

```
Is MAP being updated weekly?
├─ Yes → Healthy
└─ No → Continue...
    │
    Has it been >3 weeks since last MAP update?
    ├─ Yes → Dead deal (qualify out or reset)
    └─ No → At risk (escalate to champion)
```

### 提案書を送るべきか？

```
Have you met the Economic Buyer?
├─ No → Don't send yet (get EB access first)
└─ Yes → Continue...
    │
    Does EB agree on problem and success metrics?
    ├─ Yes → Send proposal
    └─ No → Align with EB before sending
```

## よくあるミス

**1. アカウントプラン作成が遅すぎる**
   - 案件進行後ではなく、初回接触前に作る

**2. MEDDICCが推測で埋まっている**
   - 各要素を顧客と検証し、当て推量しない

**3. Mutual Action Planの停滞**
   - MAPが毎週更新されないなら案件は停滞。3週間超 = 死亡。

**4. バイヤーしかマッピングしない**
   - 影響者・利用者・ブロッカーを含む完全な組織図が必要

**5. パーソナルウィンを無視する**
   - 人は事業ROIだけでなく、キャリア/評判の理由で買う

**6. 案件健全性を追跡しない**
   - Green/Yellow/Red指標で死にかけ案件を早期検知できる

**7. チャンピオン検証を飛ばす**
   - 社内チャンピオン不在では、あなた一人で売ることになる

## クイックリファレンス

**MAPヘルスチェック:**
- Green: 毎週更新、双方にアクション、顧客がタスクを完了
- Yellow: 隔週更新、ほぼ自社アクション、顧客返信が遅い
- Red: 3週間以上停滞、自社アクションのみ、顧客反応なし → **Dead deal**

**MEDDICCバリデーション:**
- [ ] Metrics: EBと成功基準で合意
- [ ] Economic Buyer: 面談済み、課題/解決策を検証済み
- [ ] Decision Criteria: 評価基準を理解している
- [ ] Decision Process: 調達/法務/セキュリティ手順を把握
- [ ] Identified Pain: 顧客自身の言葉で定義されている
- [ ] Champion: 社内であなたのために積極的に売っている
- [ ] Competition: 比較検討中の代替案を把握している

**パーソナルウィン質問:**
- 「あなた個人にとって、成功とはどんな状態ですか？」
- 「これがうまくいったらチームはどうなりますか？うまくいかなかったら？」
- 「今年、何の指標で評価されていますか？」
- 「社内で懐疑的なのは誰ですか？なぜですか？」

**アカウントプランチェックリスト:**
- [ ] 仮説を含むアカウントサマリー
- [ ] パーソナルウィンをマップした組織図
- [ ] MEDDICCが完全に検証済み（推測ではない）
- [ ] 顧客アクションを含むMAP（自社だけでない）
- [ ] 毎週のMAP更新 cadence を予定化
