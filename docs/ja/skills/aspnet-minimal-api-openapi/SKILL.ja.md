# OpenAPI を使った ASP.NET Minimal API

あなたの目標は、正しい型と包括的な OpenAPI/Swagger ドキュメントを備えた、構造化された ASP.NET Minimal API エンドポイントの作成を支援することです。

## API の構成

- `MapGroup()` 拡張を使って関連するエンドポイントをグループ化する
- 横断的関心事にはエンドポイントフィルターを使用する
- 規模の大きい API はエンドポイントクラスを分けて構成する
- 複雑な API では機能ベースのフォルダー構成の採用を検討する

## リクエストとレスポンスの型

- 明示的なリクエスト／レスポンス DTO・モデルを定義する
- 適切なバリデーション属性を備えた明確なモデルクラスを作成する
- 不変なリクエスト／レスポンスオブジェクトには record 型を使う
- API 設計標準に沿った、意味のあるプロパティ名を使う
- 制約を強制するために `[Required]` などのバリデーション属性を適用する
- 標準的なエラーレスポンスを得るために ProblemDetailsService と StatusCodePages を使用する

## 型の扱い

- 明示的な型バインディングを用いた、強く型付けされたルートパラメーターを使う
- 複数のレスポンス型を表現するために `Results<T1, T2>` を使う
- 強く型付けされたレスポンスのために `Results` ではなく `TypedResults` を返す
- null 許容アノテーションや init 専用プロパティなど、C# 10+ の機能を活用する

## OpenAPI ドキュメント

- .NET 9 で追加された組み込みの OpenAPI ドキュメントサポートを使う
- オペレーションの要約と説明を定義する
- `WithName` 拡張メソッドを使って operationId を追加する
- `[Description()]` を使ってプロパティとパラメーターに説明を追加する
- リクエストとレスポンスに適切なコンテンツタイプを設定する
- ドキュメントトランスフォーマーを使って、servers・tags・security schemes などの要素を追加する
- スキーマトランスフォーマーを使って OpenAPI スキーマにカスタマイズを適用する
