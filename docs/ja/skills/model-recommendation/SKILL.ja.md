# Copilotチャットモードおよびプロンプト向けAIモデル推奨

## ミッション

`.agent.md`または`.prompt.md`ファイルを解析し、その目的、複雑さ、必要な能力を理解した上で、GitHub Copilotで利用可能なAIモデルの中から最適なモデルを推奨します。タスクの特性、モデルの強み、コスト効率、性能のトレードオフに基づく根拠を提供します。

## 範囲と前提条件

- **入力**: `.agent.md`または`.prompt.md`ファイルのパス
- **利用可能モデル**: GPT-4.1、GPT-5、GPT-5 mini、GPT-5 Codex、Claude Sonnet 3.5、Claude Sonnet 4、Claude Sonnet 4.5、Claude Opus 4.1、Gemini 2.5 Pro、Gemini 2.0 Flash、Grok Code Fast 1、o3、o4-mini（廃止予定日付き）
- **モデル自動選択**: VS Code（2025年9月以降）で利用可能 - GPT-4.1、GPT-5 mini、GPT-5、Claude Sonnet 3.5、Claude Sonnet 4.5から選択（プレミアム乗数 > 1は除外）
- **コンテキスト**: GitHub Copilotのサブスクリプション階層（Free: 2K完了＋月50チャット、0xモデルのみ；Pro: 無制限0x＋月1000プレミアム；Pro+: 無制限0x＋月5000プレミアム）

## 入力

必須:

- `${input:filePath:.agent.mdまたは.prompt.mdファイルのパス}` - 絶対パスまたはワークスペース相対パス

任意:

- `${input:subscriptionTier:Pro}` - ユーザーのCopilotサブスクリプション階層（Free、Pro、Pro+） - デフォルトはPro
- `${input:priorityFactor:Balanced}` - 最適化優先度（Speed、Cost、Quality、Balanced） - デフォルトはBalanced

## ワークフロー

### 1. ファイル解析フェーズ

**ファイルの読み込みと解析**:

- 対象の`.agent.md`または`.prompt.md`ファイルを読み込む
- フロントマター（description、mode、tools、指定があればmodel）を抽出
- 本文を解析し以下を特定：
  - タスクの複雑さ（単純／中程度／複雑／高度）
  - 必要な推論深度（基本／中級／高度／専門家レベル）
  - コード生成の必要度（最小限／中程度／広範囲）
  - マルチターン会話の必要性
  - コンテキストウィンドウの必要サイズ（小／中／大）
  - 専門的能力（画像解析、長文コンテキスト、リアルタイムデータ）

**タスクタイプの分類**:

内容分析に基づき主要なタスクカテゴリを特定：

1. **単純で繰り返しのタスク**:

   - パターン：フォーマット、簡単なリファクタリング、コメント・ドックストリング追加、基本CRUD
   - 特徴：単純なロジック、最小限のコンテキスト、迅速な実行優先
   - キーワード：format、comment、simple、basic、add docstring、rename、move

2. **コード生成・実装**:

   - パターン：関数・クラス作成、機能実装、APIエンドポイント、テスト作成
   - 特徴：中程度の複雑さ、ドメイン知識、慣用的コード
   - キーワード：implement、create、generate、write、build、scaffold

3. **複雑なリファクタリング・アーキテクチャ**:

   - パターン：システム設計、アーキテクチャレビュー、大規模リファクタリング、性能最適化
   - 特徴：深い推論、複数コンポーネント、トレードオフ分析
   - キーワード：architect、refactor、optimize、design、scale、review architecture

4. **デバッグ・問題解決**:

   - パターン：バグ修正、エラー解析、体系的トラブルシューティング、根本原因分析
   - 特徴：段階的推論、デバッグコンテキスト、検証ニーズ
   - キーワード：debug、fix、troubleshoot、diagnose、error、investigate

5. **計画・調査**:

   - パターン：機能計画、調査、ドキュメント解析、ADR作成
   - 特徴：読み取り専用、コンテキスト収集、意思決定支援
   - キーワード：plan、research、analyze、investigate、document、assess

6. **コードレビュー・品質分析**:

   - パターン：セキュリティ分析、性能レビュー、ベストプラクティス検証、コンプライアンスチェック
   - 特徴：批判的思考、パターン認識、ドメイン専門知識
   - キーワード：review、analyze、security、performance、compliance、validate

7. **専門ドメインタスク**:

   - パターン：Django／フレームワーク特有、アクセシビリティ（WCAG）、テスト（TDD）、API設計
   - 特徴：深いドメイン知識、フレームワーク慣習、標準準拠
   - キーワード：django、accessibility、wcag、rest、api、testing、tdd

8. **高度な推論・多段階ワークフロー**:

   - パターン：アルゴリズム最適化、複雑なデータ変換、多段階ワークフロー
   - 特徴：高度な推論、数学的・アルゴリズム的思考、逐次論理
   - キーワード：algorithm、optimize、transform、sequential、reasoning、calculate

**能力要件の抽出**:

フロントマターの`tools`や本文指示に基づく：

- **読み取り専用ツール**（search、fetch、usages、githubRepo）：低複雑度、より高速モデル適合
- **書き込み操作**（edit/editFiles、new）：中程度の複雑度、正確性重視
- **実行ツール**（runCommands、runTests、runTasks）：検証ニーズ、反復的アプローチ
- **高度ツール**（context7/*、sequential-thinking/*）：複雑な推論、プレミアムモデル推奨
- **マルチモーダル**（画像解析参照）：ビジョン対応モデル必須

### 3. 推奨生成フェーズ

**主要推奨**:

- タスク解析と決定ツリーに基づき最適モデルを1つ特定
- ファイル内容の特性に紐づく具体的根拠を提示
- ユーザーのサブスクリプション階層に応じた乗数コスト影響を説明

**代替推奨**:

- 1～2の代替モデルを提示しトレードオフを説明
- 代替モデルが好まれるシナリオを含む
- 優先度（速度・品質・コスト）による上書き考慮

**自動選択ガイダンス**:

- タスクが自動モデル選択に適しているか評価（プレミアム乗数 > 1は除外）
- 手動選択が有効な場合とCopilotに任せる場合の説明
- 特定タスクにおける自動選択の制限を明示

**廃止警告**:

- ファイルに廃止予定モデル（o3、o4-mini、Claude Sonnet 3.7、Gemini 2.0 Flash）が指定されている場合は警告
- 推奨モデルへの移行パスを提示
- 廃止予定日時を含む（例：「o3は2025-10-23廃止予定」）

**サブスクリプション階層考慮**:

- **Free**: 0x乗数モデルのみ推奨（GPT-4.1、GPT-5 mini、Grok Code Fast 1）
- **Pro**: 0x（無制限）と1x（月1000回）モデルのバランス
- **Pro+**: 1xモデル（月5000回）を自由に使い、10xは特別な場合に正当化

### 4. 統合推奨

**フロントマター更新ガイダンス**:

ファイルに`model`フィールドがない場合：

```markdown
## 推奨：モデル指定の追加

現在のフロントマター：
```yaml

---

description: "..."
tools: [...]

---

```

推奨フロントマター：
```yaml

---

description: "..."
model: "[推奨モデル名]"
tools: [...]

---

```

根拠：[このモデルがタスクに最適な理由の説明]
```

ファイルに既にモデル指定がある場合：

```markdown
## 現在のモデル評価

指定モデル：`[現在のモデル]`（乗数：[X]x）

推奨：［現在のモデルを維持 | [推奨モデル]への切り替えを検討］

根拠：[説明]
```

**ツール整合性チェック**:

指定ツールとモデル能力の整合性を確認：

- `context7/*`や`sequential-thinking/*`を含む場合：高度推論モデル（Claude Sonnet 4.5、GPT-5、Claude Opus 4.1）推奨
- ビジョン関連ツールがある場合：画像対応モデルを推奨（GPT-5 Codex、Claude Sonnet 4、miniモデルは注意喚起）
- 読み取り専用ツール（search、fetch）ならコスト効率モデル（GPT-5 mini、Grok Code Fast 1）推奨

**Context7を活用したモデルドキュメント検証**:

```

- [ ] フロントマター正確抽出（未指定の場合は明記）
- [ ] タスク複雑度正確分類（単純／中程度／複雑／高度）
- [ ] 8カテゴリから主要タスクカテゴリ特定
- [ ] 決定ツリーに沿ったモデル推奨整合性
- [ ] ユーザー階層に応じた乗数コスト説明
- [ ] 代替モデルの明確なトレードオフ説明
- [ ] 自動選択ガイダンス（推奨／非推奨／状況依存）含む
- [ ] 廃止モデル警告含む（該当時）
- [ ] フロントマター更新例（有効なYAML）提示
- [ ] ツール整合性確認（モデル能力と指定ツールの一致）
- [ ] Context7利用による最新情報検証（必要時）
- [ ] レポートに全必須セクション含む（概要、解析、推奨、実装）

### 成功基準

- 推奨はファイル特性に基づき正当化されている
- コスト影響は明確かつ階層に適合
- 代替モデルは速度・品質・コストの異なる優先度をカバー
- フロントマター更新は即コピー＆ペースト可能
- ユーザーが即行動可能な明確手順を含む
- レポートは読みやすくスキャンしやすい（構造・表・絵文字マーカー）

### 失敗トリガー

- ファイルパス無効または読み込み不可 → 停止し有効パス要求
- ファイルが`.agent.md`または`.prompt.md`でない → 停止しファイル種別確認
- 内容からタスク複雑度判定不可 → より具体的ファイルまたは説明要求
- 推奨がドキュメント化された能力と矛盾 → Context7で最新情報検証
- サブスクリプション階層が無効（Free/Pro/Pro+以外） → Proをデフォルトとし注記

## 高度なユースケース

### 複数ファイル解析

ユーザーが複数ファイルを提供した場合：

1. 各ファイルを個別に解析
2. ファイルごとに推奨を生成
3. 推奨比較のサマリーテーブルを提供
4. パターンを指摘（例：「全てのデバッグ関連モードはClaude Sonnet 4.5が有効」）

### 比較分析

「このファイルに対してXとYどちらが良いか？」と問われた場合：

1. その2モデルに絞って比較
2. 並列表形式で提示
3. 明確な勝者を具体的根拠付きで宣言
4. サブスクリプション階層に基づくコスト比較も含む

### 移行計画

ファイルに廃止モデル指定がある場合：

1. 移行ガイダンスをレポートで優先提示
2. 現行挙動と置換モデル能力の比較検証
3. 破壊的変更が予想される場合は段階的移行案を提示
4. 必要に応じてロールバック計画も含む

## 例

### 例1: 単純なフォーマットタスク

**ファイル**: `format-code.prompt.md`  
**内容**: 「BlackスタイルでPythonコードをフォーマットし、型ヒントを追加」  
**推奨**: GPT-5 mini（0x乗数、最速、繰り返しフォーマットに十分）  
**代替**: Grok Code Fast 1（0.25x、さらに高速、プレビュー機能）  
**根拠**: タスクは単純かつ繰り返しであり、高度な推論不要。速度優先。

### 例2: 複雑なアーキテクチャレビュー

**ファイル**: `architect.agent.md`  
**内容**: 「スケーラビリティ、セキュリティ、保守性のためのシステム設計レビュー。トレードオフ分析、ADRレベルの推奨」  
**推奨**: Claude Sonnet 4.5（1x乗数、専門家推論、アーキテクチャに最適）  
**代替**: Claude Opus 4.1（10x、大規模コードベース（>500Kトークン）向け）  
**根拠**: 深い推論、アーキテクチャ専門知識、デザインパターン知識が必要。Sonnet 4.5が優秀。

### 例3: Djangoエキスパートモード

**ファイル**: `django.agent.md`  
**内容**: 「Django 5.xエキスパート、ORM最適化、非同期ビュー、REST API設計。最新Djangoドキュメントはcontext7利用」  
**推奨**: GPT-5（1x乗数、高度推論、優秀なコード品質）  
**代替**: Claude Sonnet 4.5（1x、代替視点、フレームワーク対応強力）  
**根拠**: ドメイン専門知識＋context7連携に高度推論が有効。1xコストは専門モードに妥当。

### 例4: Free階層ユーザーの計画モード

**ファイル**: `plan.agent.md`  
**内容**: 「読み取り専用ツール（search、fetch、githubRepo）を使った調査・計画モード」  
**サブスクリプション**: Free（2K完了＋月50チャット、0xモデルのみ）  
**推奨**: GPT-4.1（0x、バランス良好、Free階層に含まれる）  
**代替**: GPT-5 mini（0x、より高速だがコンテキストは少なめ）  
**根拠**: Free階層は0xモデル限定。GPT-4.1は計画タスクに最適な品質とコンテキストを提供。

**廃止モデル**（2025-10-23発効）:

- ❌ o3 (1x) → 推論用途はGPT-5またはClaude Sonnet 4.5に置換
- ❌ o4-mini (0.33x) → コスト重視ならGPT-5 mini (0x)、品質重視ならGPT-5 (1x)
- ❌ Claude Sonnet 3.7 (1x) → Claude Sonnet 4または4.5に置換
- ❌ Claude Sonnet 3.7 Thinking (1.25x) → Claude Sonnet 4.5に置換
- ❌ Gemini 2.0 Flash (0.25x) → Grok Code Fast 1 (0.25x)またはGPT-5 mini (0x)に置換

**プレビューモデル**（変更の可能性あり）:

- 🧪 Claude Sonnet 4.5 (1x) - プレビュー状態、API変更の可能性あり
- 🧪 Grok Code Fast 1 (0.25x) - プレビュー、期間中無料

**安定稼働モデル**:

- ✅ GPT-4.1、GPT-5、GPT-5 mini、GPT-5 Codex（OpenAI）
- ✅ Claude Sonnet 3.5、Claude Sonnet 4、Claude Opus 4.1（Anthropic）
- ✅ Gemini 2.5 Pro（Google）

### 自動モデル選択の挙動（2025年9月以降）

**自動選択に含まれるモデル**:

- GPT-4.1 (0x)
- GPT-5 mini (0x)
- GPT-5 (1x)
- Claude Sonnet 3.5 (1x)
- Claude Sonnet 4.5 (1x)

**自動選択から除外されるモデル**:

- 乗数 > 1のモデル（Claude Opus 4.1、廃止o3）
- 管理者ポリシーでブロックされたモデル
- サブスクリプションプランで利用不可のモデル（Free階層の1xモデルなど）

**自動選択のタイミング**:

- Copilotがプロンプトの複雑さ、コンテキストサイズ、タスクタイプを解析
- 利用可能かつレート制限内の候補から選択
- 自動選択モデルには10%の乗数割引適用
- チャットビューの応答上に選択モデルをホバー表示
