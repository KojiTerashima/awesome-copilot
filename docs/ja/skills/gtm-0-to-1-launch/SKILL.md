# 0-to-1 Launch

アイデアから最初の顧客獲得まで、新製品を立ち上げます。目標は見出しを飾ることではなく、「これなしではやっていけない」と言ってくれる顧客を10人見つけることです。

## 使うタイミング

**トリガー:**
- 「このプロダクトをどうローンチすべき？」
- 「最初の顧客獲得戦略を知りたい」
- 「ローンチしたのに誰も使っていない」
- 「Product Hunt と直接アウトリーチ、どっちがいい？」
- 「認知はあるのにコンバージョンしない」
- 「これが機能しているかどうか、どう判断する？」

**コンテキスト:**
- 新製品のローンチ
- 新製品に近い感覚の機能ローンチ
- 最初の10〜50顧客の獲得
- プロダクトマーケットフィットの検証
- 初期トラクションが止まる理由の診断

---

## コアフレームワーク

### 1. Press ≠ Growth（12件のサインアップに終わったローンチ）

**パターン:**

大規模なメディア露出を伴う機能ローンチを実施。TechCrunch、VentureBeat、プロダクト系ブログに掲載。発表日は大きな盛り上がり。

**結果:**
- 50K impressions
- 12 signups
- 2 conversions

**なぜ失敗したのか:**

最適化していたのはユーザー価値ではなく、メディアの話題性だった。機能はセルフサーブで使える状態に達しておらず、教育・文脈・伴走が必要だった。プレスは注目を集める。だが、活性化しない注目は虚栄指標にすぎない。

**何がより機能するか:**

ターゲット顧客50社に直接メールする。「[problem] に苦しむ御社のようなチームのために [feature] を作りました。先行アクセスに興味ありますか？」セットアップは個別に案内し、フィードバックを得て改善する。

**結果:** 50 emails → 15 replies (30% reply rate) → 8 trials → 4 conversions (50% trial-to-paid).

**教訓:**

初期顧客はプレス露出ではなく、直接アウトリーチから生まれる。プレスが効くのは後半（Series A の発表や大きな節目）。0-to-1 では気を散らす要因になりやすい。

### 2. 3層診断（なぜローンチは失速するのか）

**パターン:**

ローンチはした。認知もある程度ある。なのにコンバージョンが弱い。問題は3つの層のどこかにあり、層ごとに打ち手が異なる。

**Layer 1: ポジショニングの問題**

症状:
- メッセージングが競合と似ている
- 差別化に複雑な技術説明が必要
- 買い手から代替可能な存在だと見なされる
- 商談が比較質問で脱線する

診断: 「間違った戦場で非対称な戦いをしている」状態。つまり、資金力で勝る企業に機能競争を挑んでいる。競合がどこに独自価値を主張しているかを可視化し、彼らが簡単に模倣できない立ち位置を見つける。

修正: 単なる機能差ではなく、構造的に自社が持てる主張を定める。プロダクト開発リソースを投下する前に、アウトバウンドメッセージで検証する。

**Layer 2: 体験の問題**

症状:
- 認知は強いが活性化が弱い
- サインアップしても最初のワークフローを完了しない
- 入口が多すぎて意思決定麻痺を起こす
- ドキュメントが成果中心でなく機能中心

診断: 意図あるデフォルトがない柔軟性は、機能ではなく負債になる。ユーザーは「選択のパラドックス」に直面する。選択肢は多いのに、aha moment まで導くガイドが足りない。

修正: 即時価値を生む「否定しがたいユースケース」を2〜3個特定する。オンボーディングをそのユースケースに限定する。高度機能は習熟経路の先に置く。ヘルプは機能一覧ではなく jobs-to-be-done を軸に書き直す。

**Layer 3: アラインメントの問題**

症状:
- チームが「顧客対応の余力がない」と言う
- 部門ごとに最適化する指標がバラバラ
- すべてのアイデアが同じ重みで扱われる（優先判断軸がない）
- 活動と成果をつなぐ明確な北極星指標がない

診断: すべての施策が同優先になる「探索モード」は、リソース制約下では破壊的になる。

修正: 共有の北極星を1つ定義する。あらゆる意思決定でタイブレークとして使う：「これは顧客獲得に効くか？」つながらない活動は削る。進捗は四半期単位ではなく毎週可視化する。

**使い方:**

ローンチが失速したら、まずどの層が壊れているか診断してからリソースを投下する。問題がポジショニングなのに体験を直すと、エンジニア工数を浪費する。問題がアラインメントなのにポジショニングを直すと、マーケ予算を浪費する。

### 3. 最初の10顧客フレームワーク

**原則:** 最初の10顧客は売上のためではなく、学習のために存在する。

**学ぶべきこと:**
1. プロダクトは本当に課題を解決しているか？
2. 活性化フローは何か？（どう価値に到達するか）
3. どんな反論が出るか？（価格、機能、連携など）
4. 本当の買い手は誰か？（肩書き、役割、予算決裁権）
5. セールスサイクルはどのくらいか？（日・週・月）

**見つけ方:**

**Channel 1: Personal Network（最初の2〜3社）**
- 「[X] を作っているので、フィードバックをもらえませんか？」
- 有料顧客化する（無料で配らない。無料ユーザーのフィードバックは有料ユーザーと異なる）

**Channel 2: Direct Outreach（顧客3〜20）**
- ターゲットアカウント100件のリストを作る
- 各社の具体的な痛みに合わせて個別化する
- メッセージのバリエーションを検証する—どの切り口が返信されるか？

**Channel 3: Ceiling Moment Targeting（最も意図が高い層）**
- 最も意図が高い見込み客は、すでに類似ソリューションを導入し、その限界に当たった人たち
- 彼らはすでにツール学習に投資しており、天井に達し、乗り換えコストも低い
- 制約起点でアウトリーチする：「[incumbent] を使い切ったチームは [capability] が必要になって次に進みます。そこを作ったのが私たちです」
- 問題理解がすでにあるため、コールドアウトリーチより3〜5倍コンバージョンしやすい

**Channel 4: Community（開発者向けプロダクト）**
- 「[problem] を解決するために [X] を作りました。初期ユーザーを探しています」
- 手厚いオンボーディングを提供する
- ユーザーが Slack/Discord/フォーラムに集まるプロダクトと相性が良い

### 4. 2週間の実験サイクル

**パターン:**

初期段階では、完璧さよりスピードが重要。制約は「正しいかどうか」ではなく、「仮説をどれだけ速く検証して反復できるか」にある。

**実行方法:**

- すべてのテストは開始前に明確な成功基準を定義する
- 実験ごとに検証変数は1つに絞る（メッセージ、チャネル、価格、機能）
- 最大2週間で区切る—そこまでにシグナルが出なければ、基本的に出ない
- 機能したら1週間以内にリソースを3倍配分する
- 機能しなければ停止し、次のテストへ進む
- 結果に関係なく学びを記録する

**プレイブックのルール:**

成功した実験は、スケール前に必ずプレイブック化する。構成は Goal → Steps → Expected output → Metrics → Risks。初見の人が実行できないなら、ドキュメント化が不十分。

**なぜ重要か:**

単発の勝ちは積み上がらない。仕組み化された実験は積み上がる。目標は一度きりのローンチではなく、仮説を高速検証できる再現可能なマシンを作ること。

**よくある失敗:**

検証前の過剰計画。「完璧な条件」がそろうまで待つ。感情的に投資してしまい失敗実験を切れない。70%の情報で意思決定する。

### 5. パートナー主導の市場参入（配布チャネルがないとき）

**パターン:**

新市場に直販だけで入るのではなく、既存プレイヤーとの提携を活用して加速する。

**実行方法:**

1. ターゲットセグメントの市場リーダーを特定する
2. 提携提案ではなく顧客課題から入る—「もし御社ユーザーが [capability] を使えたら？」は自社都合から相手都合へ視点を移せる
3. 小さく始める：1つの具体課題を解く（全面提携ではなく狭い統合）
4. 広範なコミットメントを求める前に、3〜6か月のパイロットで価値を証明する
5. 参照顧客を共同で作る—相手側のリスクを下げる
6. 相手の GTM を活用する：統合後は相手の顧客基盤へ展開される

**スーパーノード・パターン:**

他ツールが自然に接続する統合ハブとして自社を位置付ける。自社が他プラットフォームに必要な重要データやワークフローを握る。この価値は複利で増える—新しいパートナーが増えるほど、次のパートナーに対する価値も上がる。

**カテゴリの順序戦略:**

提携を全方位で追わない。四半期ごとに2〜3カテゴリへ集中する:
1. 実需要から入る：「ユーザーは毎月50回 [partner] 連携を要望しています」
2. 主要プレイヤーと提携すると、競合にも「急いで組む」動機が生まれる
3. 1カテゴリで2〜3件の成功提携ができたら、共同顧客ストーリーを作る

**よくある失敗:**

明確な統合経路なしに提携を開始する。支援なしで認知創出をパートナー任せにする。提携をプラットフォーム拡張ではなく単なる販売チャネルとして扱う。

### 6. PMF検証チェックリスト

**プロダクトマーケットフィットとは、こちらが押し込む状態ではなく、顧客に引っ張られる状態。**

**Retention:**
- [ ] Week 1 ユーザーの40%+が Week 4 に戻ってくる
- [ ] 利用量が時間とともに増えている
- [ ] 営業プッシュなしで顧客が更新する

**Organic Growth:**
- [ ] 口コミ紹介が起きている
- [ ] 顧客が「チームを追加できますか？」と聞いてくる
- [ ] 有料マーケなしでインバウンド関心がある

**Sales Velocity:**
- [ ] セールスサイクルが短くなっている
- [ ] Win rate がトライアルの30%超
- [ ] 顧客が「今すぐ必要」と言う

**Qualitative:**
- [ ] プロダクトがなくなったら「非常に困る」が40%超（Sean Ellis test）
- [ ] 顧客が用途を明確に説明できる（ユースケースが明確）
- [ ] 顧客が公に推奨している

**これらがなければ、まだ PMF ではない。マーケティング/営業をスケールしない。**

## 意思決定ツリー

### なぜ私たちのローンチは失速しているのか？

```
Do prospects understand what you are?
├─ No → Layer 1: Positioning problem
│         Fix: Test new messaging before changing product
└─ Yes → Continue...
    │
    Do users activate after signing up?
    ├─ No → Layer 2: Experience problem
    │         Fix: Restrict onboarding to 2-3 use cases, guide to aha moment
    └─ Yes → Continue...
        │
        Is the team aligned on what matters?
        ├─ No → Layer 3: Alignment problem
        │         Fix: Single north star, weekly visibility, cut non-essential
        └─ Yes → Keep iterating, you're on the right track
```

### Press Launch か Direct Outreach か？

```
Self-serve ready? (Users get value in <10 min)
├─ No → Direct outreach only (press won't convert)
└─ Yes → Do you have >$1M funding to announce?
    ├─ Yes → Both (press for awareness, outreach for conversion)
    └─ No → Direct outreach first, press later
```

## よくある失敗

**1. 活性化ではなく見出し最適化**
50K impressions と 12 signups。Press ≠ growth。

**2. ローンチ前にターゲット顧客リストがない**
0-to-1 でスプレー&プレイは機能しない。まず100アカウントのリストを作る。

**3. デフォルトのない柔軟性**
全選択肢を与えるとユーザーは止まる。否定しがたいユースケースを2〜3個に絞って強く導く。

**4. プロダクトを無料で配る**
無料ユーザーのフィードバックは丁寧だが浅い。有料ユーザーのフィードバックは率直で実用的。

**5. 学習前のスケーリング**
最初の10顧客は売上ではなく学習のため。すべて記録する。

**6. 計画過多、検証不足**
2週間実験と明確な停止基準。素早く動き、学びを文書化する。

**7. 間違った層を診断する**
問題が体験なのにポジショニングを直す = マーケ費の浪費。問題がポジショニングなのに体験を直す = 開発工数の浪費。

## クイックリファレンス

**3層診断:**
Layer 1: Positioning（メッセージが競合と似る）→ 新メッセージを検証
Layer 2: Experience（認知はあるが活性化しない）→ aha moment まで導く
Layer 3: Alignment（チームが分散）→ 単一の北極星、週次可視化

**最初の10顧客:**
Personal network (2-3) → Direct outreach (3-20) → Ceiling moment targeting (highest intent) → Community (developer products)

**2週間の実験サイクル:**
Hypothesis → Success criteria → Test (2 weeks max) → Kill or 3x → Document playbook

**PMFシグナル:**
40%+ Week 1→4 retention + word-of-mouth + shortening sales cycles + >40% very disappointed

**パートナー主導の参入:**
顧客課題を先に → 狭いパイロット → 参照顧客を共同構築 → 相手の GTM を活用
