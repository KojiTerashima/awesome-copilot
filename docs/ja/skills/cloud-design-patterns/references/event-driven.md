# Event-Driven Architecture Patterns

## Event Sourcing パターン

**課題**: アプリケーション状態のすべての変更について、完全な監査証跡が必要。

**解決策**: ドメイン内データに対して実行された操作を表すイベント列全体を、追記専用ストアに記録する。

**使用タイミング**:
- 完全な監査証跡が必要なとき
- 時点指定クエリ（point-in-time state）を実装するとき
- イベントリプレイやデバッグを支援したいとき
- 結果整合性を伴うCQRSを実装するとき

**実装時の考慮点**:
- イベントを追記専用ログに保存する
- イベントを再生して現在状態を再構築する
- イベントのバージョニング戦略を実装する
- イベントスキーマ進化に対応する
- 時間経過によるストレージ増加を考慮する
- 性能のためにスナップショットを実装する
