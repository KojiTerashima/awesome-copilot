# Security Patterns

## Federated Identity パターン

**課題**: アプリケーションでユーザー認証・認可を管理する必要がある。  
**解決策**: 認証を外部IDプロバイダーへ委譲する。

**使用タイミング**:
- SSO（シングルサインオン）実装時
- 認証実装の複雑性を下げたいとき
- ソーシャルIDプロバイダーをサポートするとき

**実装時の考慮点**:
- Azure AD、Auth0 などのIDプロバイダーを使う
- OAuth 2.0、OpenID Connect、SAML を実装する
- ローカル保持するユーザーデータを最小化する
- IDプロバイダー障害時も安全に処理する
- 適切なトークン検証を実装する

## Quarantine パターン

**課題**: 外部アセットに悪意あるコンテンツや脆弱性が含まれる可能性がある。  
**解決策**: ワークロードが利用する前に、チーム合意の品質基準を満たすことを確認する。

**使用タイミング**:
- ユーザーアップロードファイル処理
- 外部データやパッケージの取り込み
- ゼロトラストアーキテクチャ実装

**実装時の考慮点**:
- 利用前に全外部コンテンツをスキャン（マルウェア、脆弱性）
- 本番から隔離した検疫環境を用意する
- リリースの品質ゲートを明確化する
- 自動スキャンと検証を実装する
- 監査のため全活動を記録する

## Valet Key パターン

**課題**: アプリケーションがすべてのクライアントデータアクセスを中継すべきではない。  
**解決策**: 特定リソース/サービスへの制限付き直接アクセスを可能にするトークンまたはキーをクライアントへ発行する。

**使用タイミング**:
- ストレージへ直接アクセスさせたいとき
- アプリ層経由のデータ転送を最小化したいとき
- 時間制限/権限制約付きアクセスを実装したいとき

**実装時の考慮点**:
- SASトークンや署名付きURLを生成する
- 適切な有効期限を設定する
- 権限（読み取り専用、書き込み専用、操作限定）を絞る
- 必要に応じてトークン失効機構を実装する
- valet key の利用状況を監視する
