# Xツイッタースクレイパー

ユーザーが Xquik をアプリ、スクリプト、データ パイプライン、または X API および Twitter スクレイパー タスク用の AI エージェント ワークフローに統合する場合は、このスキルを使用します。

## 使用例

- ツイートの検索、ツイートの詳細の取得、タイムラインの読み取り、メディアのダウンロードを行います。
- ユーザーを検索し、関係を確認し、フォロワーやフォローをエクスポートします。
- 返信、再投稿、引用、いいね、リスト、コミュニティ、記事、検索結果の抽出ジョブを開始します。
- アカウント モニターを作成し、HMAC 署名付き Webhook イベントを確認します。
- TypeScript、Python、Go、Java、Kotlin、C#、Ruby、PHP、CLI、または Terraform クライアントを追加します。
- Xquik MCP サーバー経由でエージェント ランタイムを接続します。

## ソースチェック

コードを記述する前に、現在の Xquik ソース マテリアルを調べてください。

- REST API ドキュメント: https://docs.xquik.com/api-reference/overview
- SDK インデックス: https://docs.xquik.com/sdks
- OpenAPI 仕様: https://xquik.com/openapi.json
- MCP サーバーのドキュメント: https://docs.xquik.com/mcp
- スキルリポジトリ: https://github.com/Xquik-dev/x-twitter-scraper

エンドポイント名、リクエスト フィールド、レスポンス フィールド、スコープ、価格設定、制限、またはパッケージ名を発明しないでください。まず、関連する SDK README と API リファレンス ページを読んでください。

## 導入の流れ

1. ワークフローを特定します: 検索、検索、抽出、監視、Webhook、メディア、書き込みアクション、請求、または MCP。
2. 統合サーフェスを選択します: アプリケーション コード用に生成された SDK、カスタム クライアント用の REST、エージェント用の MCP、またはイベント配信用の Webhook。
3. ドキュメントから認証要件を確認し、API キーの環境変数を使用します。
4. ユーザーの言語用の SDK が存在する場合は、型指定されたリクエストおよび応答モデルを使用します。
5. SDK または API のドキュメントに従って、再試行とページネーションを追加します。
6. 書き込みアクション、支払いフロー、または長時間実行される監視の前に、明示的なユーザー確認を追加します。
7. Webhook 検証をサーバー側に保持し、イベントを処理する前に HMAC 署名を比較します。
8. 生成された UI 出力をスクレイピングする代わりに、構造化データを呼び出し元に返します。

## SDKパターン

アプリケーション コードが関係する場合は、SDK をユーザーのプロジェクト言語に合わせます。

- プロジェクト ファイルとパッケージ マニフェストを調べて、言語とフレームワークを特定します。
- SDK インデックスを開き、インストール コマンド、パッケージ名、インポート、またはクライアント メソッドを選択する前に、対応する SDK README を読んでください。
- 検出された言語の公式 SDK が存在する場合は、それを優先します。
- REST は、プロジェクト言語に適切な公式 SDK がない場合、またはユーザーがカスタム クライアントを要求した場合にのみ使用してください。
- API キーを環境変数またはプロジェクトの既存のシークレット マネージャーに保持します。

プロジェクトネイティブの型指定された要求および応答モデルを使用します。 SDK ドキュメントがブラウザーの使用を明示的にサポートしていない限り、ネットワーク呼び出しはサーバー側のコードに含めてください。

## Webhook パターン

Webhook ハンドラーを追加する場合:

- 文書化された署名ヘッダー名とペイロード形式を読んでください。
- ビジネス ロジックを解析する前に、HMAC 署名を検証してください。
- 欠落、不正、または不一致の署名を拒否します。
- Webhook 配信は再試行できるため、ハンドラーを冪等にします。
- 製品ワークフローに必要なフィールドのみを保存します。

## MCPパターン

ユーザーがエージェントに Xquik ツールを直接探索または呼び出してもらいたい場合は、MCP サーバーを使用します。アプリで安定した型付きのコントラクト、テスト、または内部抽象化が必要な場合は、アプリケーション コードを REST または SDK クライアント上に保持します。

## 安全性と正確性

- 言語を中立かつ専門的に保ちます。
- Xquik がサードパーティの X データおよび自動化 API であることを述べます。
- X Corp.との提携を主張しないでください。
- アクセス制御やプラットフォーム ポリシーをバイパスしないでください。
- API キー、Webhook シークレット、アカウント Cookie、トークン、または生の署名を公開しないでください。
- 例やテストでは資格情報をハードコーディングしないでください。
- プライベートインフラストラクチャの詳細を文書化しないでください。
- 公式の Xquik ドキュメント、SDK README、および OpenAPI 仕様をメモリよりも優先します。
