# 類似検出 — ディープフェイク検出とメディアの安全性

Resemble AI プラットフォームを使用して、音声、画像、ビデオ、テキストを分析して、合成操作、AI 生成コンテンツ、透かし、話者 ID、メディア インテリジェンスを実現します。

## 基本原則 — 鉄の法則

**「完全な検出結果がない限り、メディアが本物であるか偽物であるかを決して宣言しないでください。」**

メディアの信頼性について推測、推論、推測を行わないでください。すべての信頼性主張は、`label`、`score`、および `status: "completed"` が返された、完了した類似検出ジョブによって裏付けられる必要があります。検出結果がまだ `processing` である場合は、待ちます。 `failed` の場合は、そう言ってください。自分自身の判断に置き換えないでください。

## いつ使用するか

ユーザーのリクエストに次のいずれかが含まれる場合は常に、このスキルを使用します。

- 音声、ビデオ、画像、テキストが AI によって生成または操作されているかどうかを確認する
- あらゆるメディア形式のディープフェイクを検出
- メディアの信頼性または出所の検証
- どの AI プラットフォームが音声を合成したかの特定 (ソース トレース)
- メディア上のウォーターマークの適用または検出
- 発言者の情報、感情、書き起こし、または誤った情報についてメディアを分析する
- 検出結果について自然言語で質問する
- 話者の身元を既知の音声プロファイルと照合または検証する
- AI によって生成されたテキストまたは機械によって書かれたテキストの検出
- 「ディープフェイク」、「偽検出」、「合成メディア」、「音声検証」、「透かし」、「メディアフォレンジック」、「真正性チェック」、「ソーストレーシング」、「これは本物ですか」、「AIが書いたテキスト」、「テキスト検出」に関する言及。

**テキスト読み上げの生成、音声の複製、または音声からテキストへの転写には使用しないでください**。これらは別の Resemble 機能です。

## 能力決定ツリー

|ユーザーは次のことを望んでいます... |これを使用します | API エンドポイント |
|------------------------------------------------------|------------------------------------------|--------------------------------------|
|メディアが AI 生成/ディープフェイクかどうかを確認する | **ディープフェイクの検出** | `POST /detect` |
| *どの AI プラットフォーム* が偽の音声を作成したかを知る | **オーディオ ソース トレース** | `POST /detect` フラグ付き |
|メディアから講演者の情報、感情、文字起こしを取得 | **インテリジェンス** | `POST /intelligence` |
|完了した検出について質問する | **インテリジェンスの検出** | `POST /detects/{uuid}/intelligence` |
|目に見えない透かしをメディアに適用する | **ウォーターマークの適用** | `POST /watermark/apply` |
|メディアにウォーターマークが含まれているかどうかを確認する | **透かし検出** | `POST /watermark/detect` |
|既知のプロファイルに照らして話者の ID を検証する | **アイデンティティ検索** | `POST /identity/search` |
|テキストが AI によって生成されたものであるかどうかを確認する | **テキスト検出** | `POST /text_detect` |
|将来のマッチングのために音声 ID プロファイルを作成する | **アイデンティティの作成** | `POST /identity` |

複数の機能が適用される場合 (例: ユーザーがディープフェイク検出とインテリジェンスを必要とする場合)、個別にリクエストを行うのではなく、`intelligence: true` フラグを使用してそれらの機能を 1 つの `POST /detect` 呼び出しに結合します。

## 必要なセットアップ

- **API キー**: Resemble AI ダッシュボードのベアラー トークン (`RESEMBLE_API_KEY` として設定)
- **ベース URL**: `https://app.resemble.ai/api/v2`
- **認証ヘッダー**: `Authorization: Bearer <RESEMBLE_API_KEY>`
- **メディア要件**: すべてのメディアは、公的にアクセス可能な HTTPS URL にある必要があります。

ユーザーが URL の代わりにローカル ファイル パスを指定する場合は、まずファイルをパブリック HTTPS URL でホストする必要があることを伝えます。ローカル ファイルを API にアップロードしないでください。 (例外: `POST /text_detect` はテキスト コンテンツをインラインで受け入れます。)

## フェーズ 1: ディープフェイクの検出

コア機能。 AI 生成のコンテンツ分析のために、`POST /detect` 経由で音声、画像、またはビデオを送信します。

**考慮すべき重要なフラグ:**
- `visualize: true` — ヒートマップ/視覚化アーティファクトを生成する
- `intelligence: true` — 検出と同時にマルチモーダル インテリジェンスを実行します (ラウンドトリップを節約します)
- `audio_source_tracing: true` — どの AI プラットフォームが偽のオーディオを合成したかを特定します (`"fake"` オーディオでのみ起動します)
- `use_reverse_search: true` — 画像の逆検索を有効にする (画像のみ)
- `zero_retention_mode: true` — 分析後のメディアの自動削除 (機密コンテンツの場合)

検出は非同期です。 `status` が `"completed"` または `"failed"` になるまで、2 秒 → 5 秒 → 10 秒の間隔で `GET /detect/{uuid}` をポーリングします。ほとんどの場合、10 ～ 60 秒で完了します。

**サポートされている形式:** 音声 (WAV、MP3、OGG、M4A、FLAC) ・ ビデオ (MP4、MOV、AVI、WMV) ・ 画像 (JPG、PNG、GIF、WEBP)

### 結果の読み取り

- **音声** — `metrics` での判定 — `label` と `aggregated_score` を使用
- **画像** — `image_metrics` での判定 — `label` と `score` を使用します。 `ifl` には非表示の周波数レイヤー ヒートマップがあります
- **ビデオ** — `video_metrics` の判定 — フレーム/セグメント結果の階層ツリー。 video-with-audio は `metrics` と `video_metrics` の両方を返します

完全な応答スキーマについては、[references/api-reference.md](references/api-reference.md#reading-results-by-media-type) を参照してください。

### スコアの解釈

|スコア範囲 |解釈 |
|----------------------|-----------------------------------------------------|
| 0.0 – 0.3 |本物/本物のメディアであることを示す強い兆候 |
| 0.3～0.5 |決定的ではありません — 追加の分析を推奨します |
| 0.5 – 0.7 |おそらく合成 — 審査のためのフラグ |
| 0.7 – 1.0 |高信頼性合成/AI 生成 |

**常にコンテキストを伴うスコアを表示します。** 「検出結果は 0.87 のスコアを返し、この音声が AI によって生成されたものであるという高い信頼性を示しています」と言います。決して「偽物です」ではありません。

## フェーズ 2: インテリジェンス — メディア分析

メディアに関する構造化された豊富な洞察: 発言者情報、感情、文字起こし、翻訳、誤った情報、異常。

Intelligence を実行するには 2 つの方法:
1. **検出と組み合わせる** — `intelligence: true` を `POST /detect` に追加します (推奨; 1 回の呼び出し)
2. **スタンドアロン** — `POST /intelligence` と URL (ディープフェイクの判定ではなく分析のみが必要な場合)

**オーディオ/ビデオの構造化フィールドには次のものが含まれます:** `speaker_info`、`language`、`dialect`、`emotion`、`speaking_style`、`context`、`message`、`abnormalities`、`transcription`、`translation`、`misinformation`。

**画像構造化フィールドには次のものが含まれます:** `scene_description`、`subjects`、`authenticity_analysis`、`context_and_setting`、`abnormalities`、`misinformation`。

### インテリジェンスの検出 — 結果について質問する

検出が完了したら、`POST /detects/{detect_uuid}/intelligence` と `{ "query": "..." }` を介して自然言語で質問します。質問 UUID を返します — `completed` まで `GET /detects/{detect_uuid}/intelligence/{question_uuid}` をポーリングします。

**提案する良い質問:**
- 「検出結果をわかりやすい言葉でまとめる」
- 「これが AI によって生成されたことを示唆する具体的な指標は何ですか?」
- 「音声とビデオの検出結果はどのように異なりますか?」
- 「信頼レベルとは何ですか?そしてそれは何を意味しますか?」
- 「分析に矛盾はありませんか？」

**前提条件:** 検出には `status: "completed"` が必要です。処理または失敗した検出に対して質問を送信すると、422 が返されます。

完全なパラメーターについては、[references/api-reference.md](references/api-reference.md#intelligence) を参照してください。

## フェーズ 3: オーディオソースのトレース

オーディオに `"fake"` というラベルが付いている場合は、どの AI プラットフォームがそれを生成したかを特定します。

**有効にするには**、`POST /detect` リクエストで `audio_source_tracing: true` を設定します。結果は、`audio_source_tracing.label` の検出応答に表示されます。

既知のラベル: `resemble_ai`、`elevenlabs`、`real` など、モデルが拡張されます。

**重要:** ソース トレースは、`"fake"` というラベルの付いたオーディオでのみ実行されます。実際のオーディオではソース トレース結果は生成されません。

スタンドアロン クエリ: `GET /audio_source_tracings` および `GET /audio_source_tracings/{uuid}`。

## フェーズ 4: 透かし入れ

出所追跡のためにメディアに目に見えない透かしを適用するか、既存の透かしを検出します。

- **適用**: `POST /watermark/apply` と `url`、オプションの `strength` (0.0 ～ 1.0)、オプションの `custom_message`。同期応答の場合は `Prefer: wait` を追加するか、`GET /watermark/apply/{uuid}/result` をポーリングします。応答には `watermarked_media` URL が含まれます。
- **検出**: `POST /watermark/detect` と `url`。音声は `{ has_watermark, confidence }` を返します。画像/ビデオは `{ has_watermark }` を返します。

正確なパラメーターの規則については、[references/api-reference.md](references/api-reference.md#watermarking) を参照してください。

## フェーズ 5: ID — 話者検証 (ベータ版)

音声 ID プロファイルを作成し、受信音声をプロファイルと照合します。

> **ベータ機能** — プレビュー プログラムに参加する必要があります。アクセス エラーが発生した場合はユーザーに通知します。

- **プロファイルの作成**: `POST /identity` と `{ audio_url, name }`
- **検索**: `POST /identity/search` と `{ audio_url, top_k }`

応答は、`confidence` (より高い = より強い) および `distance` (より低い = より近い一致) によるランク付けされた一致を返します。

完全なスキーマについては、[references/api-reference.md](references/api-reference.md#identity--speaker-verification-beta) を参照してください。

## フェーズ 6: テキスト検出

`POST /text_detect` を介して、テキスト コンテンツが AI によって生成されたものであるか人間が作成したものであるかを検出します。

> **ベータ機能** — `detect_beta_user` ロール、または `dfd_text` 製品を含む料金プランが必要です。

**主要パラメータ:**
- `text` (必須、最大 100,000 文字)
- `threshold` (デフォルトは 0.5)
- `privacy_mode: true` — 分析後にテキスト コンテンツが保存されない
- `callback_url` — 非同期通知 Webhook

同期応答の場合は `Prefer: wait` を追加するか、`GET /text_detect/{uuid}` をポーリングします。応答には `prediction` (`"ai"` または `"human"`) および `confidence` (0.0 ～ 1.0) が含まれます。

完全なスキーマとコールバック形式については、[references/api-reference.md](references/api-reference.md#text-detection) を参照してください。

## 推奨されるワークフロー

### フルメディアフォレンジック（最も徹底した）

包括的な分析を行うには、すべての機能を組み合わせます。

1. すべてのフラグを有効にして検出を送信します。
   ```json
   {
     "url": "https://example.com/suspect.mp4",
     "visualize": true,
     "intelligence": true,
     "audio_source_tracing": true,
     "use_reverse_search": true
   }
   ```
2. `status: "completed"` まで投票してください
3. 判決については `metrics` / `image_metrics` / `video_metrics` をご覧ください
4. 構造化メディア分析については `intelligence.description` を参照してください
5. オーディオに `"fake"` というラベルが付いている場合は、ソース プラットフォームの `audio_source_tracing.label` を確認してください
6. 何か説明が必要な場合は、Detect Intelligence を通じてフォローアップの質問をしてください
7. 出所に関連がある場合は、`POST /watermark/detect` 経由でウォーターマークを確認してください

### クイック真贋チェック（最速）

1. 最小限の検出を送信します: `{ "url": "..." }`
2. 完了するまでポーリングする
3. `label` と `aggregated_score` (音声) または `label` と `score` (画像/ビデオ) を確認してください。
4. スコアコンテキストを含む結果のレポート

### 来歴パイプライン (コンテンツクリエイター)

1. 元のコンテンツにウォーターマークを適用する: `POST /watermark/apply`
2. 透かしを入れたメディアを配布する
3. 後で、コピーに対して出所を検証します: `POST /watermark/detect`

## 危険信号 — 停止して再評価する

- **検出結果を伴わない真正性の宣言** — 視覚/聴覚検査のみに基づいてメディアが本物であるか偽物であるかを決して言わないでください
- **スコアを無視し、ラベルのみを報告する** — スコア 0.51 の `"fake"` ラベルは、スコア 0.95 とは大きく異なることを意味します。
- **API へのローカル ファイル パスの送信** — API にはパブリックにアクセス可能な HTTPS URL が必要です (テキスト検出には適用されません)。
- **100,000 文字を超えるテキストをテキスト検出に送信** — チャンクに分割するか、制限をユーザーに通知します
- **ポーリングが積極的すぎる** - 2 秒間隔で開始し、指数関数的に後退します。 1秒未満でループしないでください
- **検出が完了する前に Detect Intelligence に質問する** - 422 エラーが発生する
- **「実際の」オーディオでのソース トレースが必要です** — ソース トレースは、`"fake"` というラベルの付いたオーディオでのみ実行されます
- **ベータ機能 (ID、テキスト検出) を実稼働対応として扱う** — ベータ ステータスについてユーザーに警告します
- **機密メディアの `zero_retention_mode` を無視する** - メディアが機密またはプライベートであることをユーザーが示す場合は、常にこのフラグを提案します
- **フラグを組み合わせることができる場合に複数の個別の API 呼び出しを行う** — 個別のリクエストの代わりに、検出呼び出しで `intelligence: true` と `audio_source_tracing: true` を使用します

## 回答提示ガイドライン

ユーザーに結果を提示するとき:

1. **評決を導きます** — 「検出により、この音声は AI によって生成された可能性が高いことが示されました (スコア: 0.87)」
2. **スコアのコンテキストを提供します** — 上記のスコア解釈テーブルを使用します
3. **制限事項について** — 検出は確率的なものであり、絶対的な証拠ではありません
4. **実行可能な次のステップを含める** — 必要に応じて、インテリジェンス クエリ、ソース トレース、またはウォーターマーク チェックを提案します。
5. **決定的な結果が得られない場合 (0.3 ～ 0.5)** — 結果が決定的ではないことを明示し、異なるパラメーターを使用した追加の分析または手動レビューを推奨します。
6. **検出を法的証拠として決して提示しない** — 検出結果は分析ツールであり、法医学的証明ではありません

## エラー処理

|エラー |原因 |解像度 |
|----------|--------------------------------------------|------------------------------------------|
| 400 |リクエスト本文が無効か、`url` がありません |必要なパラメータを確認してください |
| 401 | API キーが無効または欠落しています | `RESEMBLE_API_KEY` を確認してください |
| 404 |検出 UUID が見つかりません |作成応答から UUID を確認します。
| 422 |検出が完了していません (インテリジェンス用) |検出が `completed` ステータスに達するまで待ちます |
| 429 |レート制限 |後退して指数関数的な遅延で再試行 |
| 500 |サーバーエラー |一度再試行してから、ユーザーに報告してください |

## プライバシーとコンプライアンスに関する注意事項

- **ゼロ保持モード**: 分析後にメディアを自動削除するように `zero_retention_mode: true` を設定します。 URL は編集され、完了後に `media_deleted` が true に設定されます。
- **テキスト プライバシー モード**: テキスト検出に `privacy_mode: true` を設定すると、分析後にテキスト コンテンツが保存されなくなります。
- **データ処理**: メディア URL とテキスト コンテンツはデフォルトで保存されます。 GDPR/コンプライアンスに敏感なワークフローの場合は、ゼロ保持 (メディア) またはプライバシー モード (テキスト) を有効にします。
- **コールバック セキュリティ**: `callback_url` を使用する場合は、エンドポイントが HTTPS であり、受信側で認証されていることを確認してください。
