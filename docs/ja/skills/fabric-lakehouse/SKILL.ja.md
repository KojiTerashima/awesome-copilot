# このスキルをいつ使用するか

このスキルは、次の場合に使用します。
- Fabric Lakehouse とその機能に関する定義とコンテキストを含むドキュメントまたは説明を生成します。
- ベスト プラクティスを使用して、Lakehouse ソリューションを設計、構築、最適化します。
- Microsoft Fabric の Lakehouse の中核となる概念とコンポーネントを理解します。
- Lakehouse 内で表形式および非表形式のデータを管理する方法を学びます。

# ファブリック レイクハウス

## 中心となる概念

### レイクハウスとは何ですか？

Microsoft Fabric の Lakehouse は、表形式データ (テーブルなど) および非表形式データ (ファイルなど) を保存する場所をユーザーに提供するアイテムです。データ レイクの柔軟性とデータ ウェアハウスの管理機能を組み合わせます。それは以下を提供します:

- OneLake の構造化データと非構造化データ用の **統合ストレージ**
- ACID トランザクション、バージョニング、タイムトラベル用の **Delta Lake 形式**
- T-SQL クエリ用の **SQL 分析エンドポイント**
- Power BI 統合の **セマンティック モデル**
- CSV、Parquet などの他のテーブル形式のサポート
- あらゆるファイル形式のサポート
- テーブルの最適化とデータ管理のためのツール

### 主要コンポーネント

- **デルタ テーブル**: ACID 準拠とスキーマ適用を備えたマネージド テーブル
- **ファイル**: ファイルセクションの非構造化/半構造化データ
- **SQL エンドポイント**: クエリ用に自動生成された読み取り専用 SQL インターフェイス
- **ショートカット**: コピーせずに外部/内部データへの仮想リンク
- **ファブリック マテリアライズド ビュー**: 高速なクエリ パフォーマンスを実現する事前計算テーブル

### Lakehouse の表形式データ

表形式の表データは「Tables」フォルダーに保存されます。 Lakehouse のテーブルの主な形式はデルタです。 Lakehouse は表形式のデータを CSV や Parquet などの他の形式で保存できますが、これらの形式は Spark クエリでのみ使用できます。
テーブルは、データが「Tables」フォルダーに保存される場合は内部テーブル、またはテーブルへの参照のみが「Tables」フォルダーに保存され、データ自体は参照される場所に保存される場合は外部になります。テーブルはショートカットを介して参照されます。ショートカットは、内部 (ファブリック内の別の場所を指す) または外部 (ファブリックの外部に保存されたデータを指す) にすることができます。

### Lakehouse のテーブルのスキーマ

レイクハウスを作成するとき、ユーザーはスキーマを有効にすることを選択できます。スキーマは、Lakehouse テーブルを整理するために使用されます。スキーマは「Tables」フォルダーの下のフォルダーとして実装され、それらのフォルダー内にテーブルを保存します。デフォルトのスキーマは「dbo」で、削除したり名前を変更したりすることはできません。他のスキーマはすべてオプションであり、作成、名前変更、または削除できます。ユーザーはスキーマ ショートカットを使用して別のレイクハウスにあるスキーマを参照できるため、単一のショートカットで宛先スキーマ内のすべてのテーブルを参照できます。

### 湖畔のファイル

ファイルは「Files」フォルダの下に保存されます。ユーザーはフォルダーとサブフォルダーを作成してファイルを整理できます。 Lakehouse にはあらゆるファイル形式を保存できます。

### ファブリックの実体化ビュー

スケジュールに基づいて自動的に更新される、事前に計算されたテーブルのセット。これらは、複雑な集計と結合に対して高速なクエリ パフォーマンスを提供します。マテリアライズド ビューは、PySpark または Spark SQL を使用して定義され、関連付けられた Notebook に保存されます。

### スパークビュー

SQL クエリによって定義された論理テーブル。これらはデータを保存しませんが、クエリ用の仮想レイヤーを提供します。ビューは Spark SQL を使用して定義され、テーブルの隣の Lakehouse に保存されます。

## 安全

### アイテムへのアクセスまたはコントロール プレーンのセキュリティ

ユーザーは、Lakehouse とそのコンテンツへのさまざまなレベルのアクセスを提供するワークスペース ロール (管理者、メンバー、投稿者、閲覧者) を持つことができます。ユーザーは、Lakehouse の共有機能を使用してアクセス許可を取得することもできます。

### データ アクセスまたは OneLake セキュリティ

データ アクセスには、Microsoft Entra ID (旧称 Azure Active Directory) とロールベースのアクセス制御 (RBAC) に基づく OneLake セキュリティ モデルを使用します。 Lakehouse データは OneLake に保存されるため、データへのアクセスは OneLake 権限によって制御されます。 Lakehouse は、オブジェクト レベルの権限に加えて、テーブルの列レベルおよび行レベルのセキュリティもサポートしており、テーブル内の特定の列または行を誰が表示できるかをきめ細かく制御できます。


## レイクハウスのショートカット

ショートカットは、コピーせずにデータへの仮想リンクを作成します。

### ショートカットの種類

- **内部**: 他の Fabric Lakehouse/テーブルへのリンク、ワークスペース間のデータ共有
- **ADLS Gen2**: Azure の ADLS Gen2 コンテナーへのリンク
- **Amazon S3**: AWS S3 バケット、クロスクラウド データ アクセス
- **Dataverse**: Microsoft Dataverse、ビジネス アプリケーション データ
- **Google Cloud Storage**: GCS バケット、クロスクラウド データ アクセス

## パフォーマンスの最適化

### V 次数の最適化

セマンティック モデルを使用したデータ読み取りを高速化するには、デルタ テーブルで V-Order 最適化を有効にします。これにより、一般的なアクセス パターンに対するクエリのパフォーマンスが向上する方法でデータが事前に並べ替えられます。

### テーブルの最適化

OPTIMIZE コマンドを使用してテーブルを最適化することもできます。このコマンドは、小さなファイルを大きなファイルに圧縮し、Z オーダーを適用して特定の列のクエリ パフォーマンスを向上させることもできます。定期的な最適化は、時間の経過とともにデータが取り込まれ、更新されるときにパフォーマンスを維持するのに役立ちます。 Vacuum コマンドを使用すると、特に更新や削除後に、古いファイルをクリーンアップして記憶域スペースを解放できます。

## 系統

Lakehouse アイテムはリネージをサポートしており、これによりユーザーはデータの起源と変換を追跡できます。 Lakehouse のテーブルとファイルのリネージ情報が自動的にキャプチャされ、データがソースから宛先にどのように流れるかを示します。これは、デバッグ、監査、およびデータの依存関係の理解に役立ちます。
