# 眼球

視覚的な証拠を使用して文書を分析します。 Eyeball をアクティブにすると、ユーザーのデスクトップ上に Word 文書が作成されます。この文書では、すべての事実の主張に、引用テキストが黄色で強調表示されたソース資料のインライン スクリーンショットが含まれます。

## アクティベーション

ユーザーがこのスキルを呼び出したとき (例: 「目を使う」、「これに注目する」、「このドキュメントに注目する」) は、次のように応答します。

> **目玉はアクティブです。** 私が文書を分析し、インライン ソース スクリーンショットを含む Word 文書を作成します。これにより、すべての主張を自分の目で確認できるようになります。

次に、以下のワークフローに従います。

## サポートされているソース

- **ローカル ファイル:** Word ドキュメント (.docx、.doc)、PDF (.pdf)、RTF ファイル
- **Web URL:** 公的にアクセス可能な任意の Web ページ

## ツールの場所

Eyeball Python ユーティリティは次の場所にあります。```
<plugin_dir>/skills/eyeball/tools/eyeball.py
```

実際のパスを見つけるには、次を実行します。```bash
find ~/.copilot/installed-plugins -name "eyeball.py" -path "*/eyeball/*" 2>/dev/null
```

そこに見つからない場合は、プロジェクト ディレクトリまたはユーザーのホーム ディレクトリに eyeball リポジトリがあるかどうかを確認してください。

## 初回実行セットアップ

初めて使用する前に、依存関係がインストールされていることを確認してください。
```bash
python3 <path-to>/eyeball.py setup-check
```

不足しているものがあれば、必要な依存関係をインストールします。```bash
pip3 install pymupdf pillow python-docx playwright
python3 -m playwright install chromium
```

Windows では、Word オートメーション用に pywin32 もインストールします。```bash
pip install pywin32
```

## ワークフロー

以下の手順を正確に実行してください。順序が重要です。

### ステップ 1: 原文を読む

分析を記述する前に、ソース文書の全文を抽出して読んでください。
```bash
python3 <path-to>/eyeball.py extract-text --source "<path-or-url>"
```

出力を注意深く読んでください。実際のセクション番号、見出し、ページ番号、および主要な言語を特定します。

**重要:** このステップをスキップしないでください。文書の構造に関する仮定に基づいて分析を記述しないでください。実際のテキストを読んでください。

### ステップ 2: 正確な引用を使用して分析を書く

分析の各ポイントについて、次のことを行う必要があります。

1. **文書に記載されている正しいセクション番号を参照してください** (例: 番号付けを想定しているため、「セクション 8」ではなく「セクション 9」)。
2. **抽出されたテキスト内でそのセクションが表示される正しいページ番号を参照してください**。
3. **あなたの主張を直接裏付けるソースからの逐語的なフレーズであるアンカーを選択してください**。

### ステップ 3: アンカーを正しく選択する

これが最も重要なステップです。アンカーは、スクリーンショットで強調表示される内容を決定します。

**する：**
- 自分の主張を直接裏付ける原文のフレーズをそのまま使用する
- 複数のアンカーを使用して、読者に表示されるテキストの全範囲をカバーします。
- 意図した場所にのみ表示される特定の一般的ではないフレーズを使用する

**しないでください：**
- 文書全体に表示される一般的なトピックラベル (「機密性」など) を使用します。
- 他の場所で相互参照として表示される場合は、セクションのタイトルを単独で使用します。
- 多くの場所で一致する単一の一般的な単語を使用する

**例:**

間違っています -- どこでも一致する汎用トピック ラベルを使用します。```json
{"anchors": ["User-Generated Content"], "target_page": 8}
```

右 -- 主張をサポートする特定の言語を使用します。```json
{"anchors": ["retain ownership", "Ownership of Content, Right to Post"], "target_page": 8}
```

間違っています -- セクションのタイトルが以前のページに相互参照として表示されています。```json
{"anchors": ["LIMITATION OF LIABILITY"]}
```

RIGHT -- 精度を高めるためにセクション番号を含め、正しいページをターゲットにします。```json
{"anchors": ["12. LIMITATION OF LIABILITY", "INDIRECT", "CONSEQUENTIAL"], "target_page": 13}
```

### ステップ 4: 分析ドキュメントを作成する

セクションの JSON 配列を構築し、ビルド コマンドを呼び出します。
```bash
python3 <path-to>/eyeball.py build \
  --source "<path-or-url>" \
  --output ~/Desktop/<title>.docx \
  --title "Analysis Title" \
  --subtitle "Source description" \
  --sections '[
    {
      "heading": "1. Section Title",
      "analysis": "Your analysis text here. Reference Section X on page Y...",
      "anchors": ["verbatim phrase 1", "verbatim phrase 2"],
      "target_page": 5,
      "context_padding": 40
    },
    {
      "heading": "2. Another Section",
      "analysis": "More analysis...",
      "anchors": ["exact quote from source"],
      "target_pages": [10, 11],
      "context_padding": 50
    }
  ]'
```

セクションオブジェクトフィールド:
- `heading` (必須): 出力ドキュメントのセクション見出し
- `analysis` (必須): 分析テキスト
- `anchors` (必須): 検索して強調表示するソースからの逐語的なフレーズのリスト
- `target_page` (オプション): 検索する単一のページ番号 (1 から始まるインデックス付き)
- `target_pages` (オプション): 検索するページ番号のリスト (スクリーンショットを縦方向に貼り合わせたもの)
- `context_padding` (オプション): PDF ポイントのアンカー領域の上下のパディング (デフォルト: 40)。より多くのコンテキストを表示するには、値を大きくします。

### ステップ 5: 出力を提供する

出力をユーザーのデスクトップに保存します。ユーザーにファイル名を伝え、それを開いて強調表示されたソースのスクリーンショットと照らし合わせて各主張を検証できることを伝えます。

## 納品前セルフチェック

最終的な文書を保存する前に、次のことを心の中で確認してください。

1. 各セクションの分析テキストは、ソースからの正しいセクション番号を参照していますか?
2. アンカーはターゲット ページに表示される逐語的なフレーズですか?
3. 各アンカーは、同じトピックに関連しているだけでなく、分析の主張を直接サポートしていますか?
4. スクリーンショットが分析と一致しない場合、分析が間違っているのでしょうか、それともアンカーが間違っているのでしょうか?間違っている方を修正してください。

## 注意事項

- 出力ドキュメントには、動的にサイズ変更される強調表示されたスクリーンショットが含まれます。複数のアンカーを指定すると、スクリーンショットはそれらすべてをカバーするように拡大されます。
- 検索語が見つからない場合は、出力ドキュメントにそのことが記録されます。このような場合は、アンカーが十分に言葉どおりに表現されていない可能性があります。調整して再構築します。
- Web ページの場合、Playwright は最初にページを PDF にレンダリングします。結果として得られるページ番号は、ブラウザに表示されるものと異なる場合があります。抽出されたテキスト出力 (ステップ 1) を使用して、正しいページ番号を決定します。
- ユーザーがすでにソース テキストを提供している場合、または現在の会話ですでにソース テキストを読んでいる場合は、手順 1 をスキップできます。ただし、分析を作成する前に、セクション番号とページ参照を実際のテキストと照らし合わせて必ず確認してください。
