# OpenAPI仕様からアプリケーションを生成する

あなたの目標は、OpenAPI仕様をもとに、アクティブなフレームワークの規約とベストプラクティスに従った、完全で動作するアプリケーションを生成することです。

## 入力要件

1. **OpenAPI仕様**: 以下のいずれかを提供してください：
   - OpenAPI仕様のURL（例：`https://api.example.com/openapi.json`）
   - OpenAPI仕様のローカルファイルパス
   - OpenAPI仕様の全文を直接貼り付け

2. **プロジェクト詳細**（仕様に含まれていない場合）：
   - プロジェクト名と説明
   - 対象フレームワークとバージョン
   - パッケージ/名前空間の命名規則
   - 認証方式（OpenAPIに指定がない場合）

## 生成プロセス

### ステップ1: OpenAPI仕様の解析
- OpenAPI仕様の完全性と正確性を検証
- すべてのエンドポイント、HTTPメソッド、リクエスト/レスポンススキーマを特定
- 認証要件とセキュリティスキームを抽出
- データモデルの関係性と制約を把握
- 曖昧さや不完全な定義を検出

### ステップ2: アプリケーションアーキテクチャの設計
- フレームワークに適したディレクトリ構造を計画
- リソースまたはドメインごとのコントローラー/ハンドラーのグルーピングを特定
- ビジネスロジックのサービス層の構成を設計
- データモデルとエンティティの関係を計画
- 設定および初期化戦略を設計

### ステップ3: アプリケーションコードの生成
- ビルド/パッケージ設定ファイルを含むプロジェクト構造を作成
- OpenAPIスキーマからモデル/DTOを生成
- ルートマッピング付きのコントローラー/ハンドラーを生成
- ビジネスロジックを含むサービス層を生成
- 必要に応じてリポジトリ/データアクセス層を生成
- エラーハンドリング、バリデーション、ロギングを追加
- 設定および起動コードを生成

### ステップ4: 補助ファイルの追加
- サービスおよびコントローラーのユニットテストを生成
- セットアップおよび実行手順を記載したREADMEを作成
- .gitignoreおよび環境設定テンプレートを追加
- APIドキュメントファイルを生成
- サンプルリクエスト/統合テストを作成

## 出力構造

生成されるアプリケーションは以下を含みます：

```
project-name/
├── README.md                      # セットアップおよび使用手順
├── [build-config]                 # フレームワーク固有のビルドファイル（pom.xml、build.gradle、package.jsonなど）
├── src/
│   ├── main/
│   │   ├── [language]/
│   │   │   ├── controllers/       # HTTPエンドポイントハンドラー
│   │   │   ├── services/          # ビジネスロジック
│   │   │   ├── models/            # データモデルおよびDTO
│   │   │   ├── repositories/      # データアクセス（該当する場合）
│   │   │   └── config/            # アプリケーション設定
│   │   └── resources/             # 設定ファイル
│   └── test/
│       ├── [language]/
│       │   ├── controllers/       # コントローラーテスト
│       │   └── services/          # サービステスト
│       └── resources/             # テスト設定
├── .gitignore
├── .env.example                   # 環境変数テンプレート
└── docker-compose.yml             # 任意：Docker設定（該当する場合）
```

## 適用されるベストプラクティス

- **フレームワーク規約**：フレームワーク固有の命名、構造、パターンに準拠
- **関心の分離**：コントローラー、サービス、リポジトリの明確なレイヤー分離
- **エラーハンドリング**：意味のあるレスポンスを伴う包括的なエラーハンドリング
- **バリデーション**：入力およびスキーマの検証を徹底
- **ロギング**：デバッグおよび監視のための構造化ロギング
- **テスト**：サービスおよびコントローラーのユニットテスト
- **ドキュメント**：インラインコードドキュメントおよびセットアップ手順
- **セキュリティ**：OpenAPI仕様に基づく認証/認可の実装
- **スケーラビリティ**：成長と保守を支える設計パターン

## 次のステップ

生成後：

1. 生成されたコード構造を確認し、必要に応じてカスタマイズ
2. フレームワークの要件に従い依存関係をインストール
3. 環境変数およびデータベース接続を設定
4. テストを実行して生成コードを検証
5. 開発サーバーを起動
6. 提供されたサンプルを使ってエンドポイントをテスト

## 必要に応じて確認すべき質問

- アプリケーションにデータベース/ORM設定を含めますか？それともインメモリ/モックデータのみですか？
- コンテナ化のためにDocker設定が必要ですか？
- 認証方式はJWT、OAuth2、APIキー、ベーシック認証のどれにしますか？
- 統合テストも必要ですか？それともユニットテストのみですか？
- 特定のデータベース技術の希望はありますか？
- APIにページネーション、フィルタリング、ソートの例を含めますか？
