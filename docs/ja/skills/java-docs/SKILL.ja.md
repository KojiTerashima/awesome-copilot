# Javaドキュメント（Javadoc）のベストプラクティス

- パブリックおよびプロテクテッドメンバーはJavadocコメントで文書化する必要があります。
- パッケージプライベートおよびプライベートメンバーも、特に複雑で自己説明的でない場合は文書化することが推奨されます。
- Javadocコメントの最初の文は要約説明です。メソッドが何をするかの簡潔な概要であり、句点で終わるべきです。
- メソッドのパラメータには`@param`を使用します。説明は小文字で始まり、句点で終わりません。
- メソッドの戻り値には`@return`を使用します。
- メソッドがスローする例外は`@throws`または`@exception`で文書化します。
- 他の型やメンバーへの参照には`@see`を使用します。
- 基底クラスやインターフェースからドキュメントを継承するには`{@inheritDoc}`を使用します。
  - 重大な動作変更がある場合は、その違いを文書化してください。
- ジェネリック型やメソッドの型パラメータには`@param <T>`を使用します。
- インラインコードスニペットには`{@code}`を使用します。
- コードブロックには`<pre>{@code ... }</pre>`を使用します。
- 機能が導入された時期（例：バージョン番号）を示すには`@since`を使用します。
- メンバーのバージョンを指定するには`@version`を使用します。
- コードの作者を指定するには`@author`を使用します。
- メンバーを非推奨としてマークし、代替案を提供するには`@deprecated`を使用します。
