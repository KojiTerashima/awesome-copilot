# Make Skill Template

新しいAgent Skillsを作成するためのメタスキルです。新しいスキルフォルダーをスキャフォールドしたり、SKILL.mdファイルを生成したり、Agent Skills仕様の理解を助ける際にこのスキルを使用してください。

## このスキルを使うタイミング

- ユーザーが「スキルを作成する」「新しいスキルを作る」「スキルをスキャフォールドする」と依頼したとき
- ユーザーがGitHub Copilotセットアップに専門的な機能を追加したいとき
- バンドルされたリソースを含むスキルの構造化を手伝う必要があるとき
- このテンプレートを複製して出発点にしたいとき

## 前提条件

- スキルが達成すべきことの理解
- 機能やトリガーを含む明確でキーワード豊富な説明
- 必要なバンドルリソース（スクリプト、リファレンス、アセット、テンプレート）の知識

## 新しいスキルの作成

### ステップ1: スキルディレクトリの作成

小文字かつハイフン区切りの名前で新しいフォルダーを作成します：

```
skills/<skill-name>/
└── SKILL.md          # 必須
```

### ステップ2: フロントマター付きSKILL.mdの生成

すべてのスキルには`name`と`description`を含むYAMLフロントマターが必要です：

```yaml
---
name: <skill-name>
description: '<何をするか>. <特定のトリガー、シナリオ、ユーザーが言いそうなキーワードがある場合に使用してください>.'
---
```

#### フロントマターのフィールド要件

| フィールド | 必須 | 制約 |
|------------|-------|-------|
| `name` | **必須** | 1〜64文字、小文字の英字・数字・ハイフンのみ、フォルダー名と一致すること |
| `description` | **必須** | 1〜1024文字、何をするかといつ使うかを説明すること |
| `license` | 任意 | ライセンス名またはバンドルされたLICENSE.txtへの参照 |
| `compatibility` | 任意 | 1〜500文字、必要に応じて環境要件 |
| `metadata` | 任意 | 追加プロパティのキーと値のペア |
| `allowed-tools` | 任意 | 事前承認されたツールのスペース区切りリスト（実験的） |

#### descriptionのベストプラクティス

**重要**: `description`は自動スキル検出の主要な手段です。以下を含めてください：

1. スキルが**何をするか**（機能）
2. **いつ使うか**（トリガー、シナリオ、ファイルタイプ）
3. ユーザーがプロンプトで言いそうな**キーワード**

**良い例:**

```yaml
description: 'Playwrightを使ったローカルWebアプリケーションのテストツールキット。フロントエンド機能の検証、UI動作のデバッグ、ブラウザのスクリーンショット取得、ブラウザコンソールログの確認を依頼されたときに使用。Chrome、Firefox、WebKitをサポート。'
```

**悪い例:**

```yaml
description: 'Webテストヘルパー'
```

### ステップ3: スキル本文の作成

フロントマターの後にマークダウンで指示を書きます。推奨セクション：

| セクション | 目的 |
|------------|-------|
| `# タイトル` | 簡潔な概要 |
| `## このスキルを使うタイミング` | 説明のトリガーを補強 |
| `## 前提条件` | 必要なツールや依存関係 |
| `## ステップバイステップのワークフロー` | タスクの番号付き手順 |
| `## トラブルシューティング` | よくある問題と解決策 |
| `## 参考資料` | バンドルされたドキュメントへのリンク |

### ステップ4: 必要に応じてオプションのディレクトリを追加

| フォルダー | 目的 | 使用タイミング |
|------------|-------|----------------|
| `scripts/` | 実行可能コード（Python、Bash、JS） | 操作を自動化する場合 |
| `references/` | エージェントが読むドキュメント | APIリファレンス、スキーマ、ガイド |
| `assets/` | そのまま使う静的ファイル | 画像、フォント、テンプレート |
| `templates/` | エージェントが修正するスターターコード | スキャフォールドの拡張 |

## 例: 完成したスキル構造

```
my-awesome-skill/
├── SKILL.md                    # 必須の指示書
├── LICENSE.txt                 # 任意のライセンスファイル
├── scripts/
│   └── helper.py               # 実行可能な自動化コード
├── references/
│   ├── api-reference.md        # 詳細ドキュメント
│   └── examples.md             # 使用例
├── assets/
│   └── diagram.png             # 静的リソース
└── templates/
    └── starter.ts              # コードスキャフォールド
```

## クイックスタート: このテンプレートを複製する

1. `make-skill-template/`フォルダーをコピー
2. スキル名（小文字・ハイフン）にリネーム
3. `SKILL.md`を更新：
   - `name:`をフォルダー名に合わせる
   - キーワード豊富な`description:`を書く
   - 本文を自分の指示に置き換える
4. 必要に応じてバンドルリソースを追加
5. `npm run skill:validate`で検証

## 検証チェックリスト

- [ ] フォルダー名は小文字かつハイフン区切り
- [ ] `name`フィールドがフォルダー名と完全に一致
- [ ] `description`は10〜1024文字
- [ ] `description`が何をするかといつ使うかを説明
- [ ] `description`はシングルクォートで囲まれている
- [ ] 本文は500行未満
- [ ] バンドルされたアセットはそれぞれ5MB未満

## トラブルシューティング

| 問題 | 解決策 |
|-------|---------|
| スキルが検出されない | より多くのキーワードとトリガーを含めて説明を改善 |
| 名前の検証に失敗 | 小文字、連続ハイフンなし、フォルダー名と一致を確認 |
| 説明が短すぎる | 機能、トリガー、キーワードを追加 |
| アセットが見つからない | スキルルートからの相対パスを使用 |
