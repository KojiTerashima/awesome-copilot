# CommonMark Markdown

`.md` ファイルを作成またはレビューする際は、[CommonMark spec 0.31.2](https://spec.commonmark.org/0.31.2/) に従って次のルールを適用してください。CommonMark spec は参照用です。CommonMark spec をダウンロードしないでください。

## 事前知識

- 行の終端は改行 (`U+000A`)、キャリッジリターン (`U+000D`)、またはファイル終端です。空行とは、スペースまたはタブのみを含む行です。
- タブはブロック構造では 4 スペースのタブストップとして振る舞いますが、コンテンツ内では展開されません。
- `U+0000` は置換文字 `U+FFFD` に置き換えます。
- **バックスラッシュエスケープ**: ASCII の句読点の前にある `\` は、その文字をリテラルとして表示します。コードスパン、コードブロック、自動リンクでは認識されません。
- **実体参照および数値文字参照**: `&amp;`, `&#123;`, `&#x7B;` のように、有効な HTML5 実体のみが対象です。コードスパンやコードブロックでは認識されません。構造文字の置き換えには使えません。

## 葉ブロック

- **区切り線**: 行頭のインデントが 0〜3 スペースで、その行の他の内容がスペースまたはタブのみの場合に、同じ `-`、`_`、`*` を 3 個以上並べたものです。段落を中断できます。
- **ATX 見出し**: `#` を 1〜6 個並べ、その後にスペースまたは行末を置きます。末尾の `#` 列は省略可能です（前にスペースが必要）。インデントは 0〜3 スペースまでです。
- **Setext 見出し**: テキストの下に `=`（レベル 1）または `-`（レベル 2）を引きます。段落を中断できないため、直前の段落の後には空行が必要です。
- **インデント付きコードブロック**: 4 スペース以上インデントされた行です。段落を中断できません。内容は Markdown として解釈されず、リテラルテキストになります。
- **フェンス付きコードブロック**: 3 個以上のバッククォートまたはチルダで開始します（混在不可）。終了フェンスは同じ文字を同数以上使う必要があります。バッククォートのフェンスでは info string にバッククォートを含められません。開始フェンスの後には言語識別子を指定してください。内容はリテラルテキストです。
- **HTML ブロック**: 開始タグ／終了タグの条件によって 7 種類定義されます。タイプ 1〜5 は対応する終了パターンで終わります。タイプ 6 は空行で終わります。タイプ 7 は段落を中断できず、空行で終わります。
- **リンク参照定義**: `[label]: destination "title"`。ラベル一致は大文字小文字を区別しません（Unicode case fold）。重複したラベルでは最初の定義が有効です。段落を中断できません。
- **段落**: 他のブロック構文として解釈できない、連続する空行でない行です。先頭の 3 スペースまでのインデントは除去されます。
- **空行**: ブロック間では無視されますが、リストが tight か loose かを判定する材料になります。

## コンテナブロック

- **引用ブロック**: 行頭に `>` を置いた行です（後続のスペースは任意）。遅延継続は段落テキストに対してのみ許可されます。連続する引用ブロック同士は空行で区切ります。
- **リスト項目**: 箇条書きマーカー (`-`, `+`, `*`) または順序付きマーカー（1〜9 桁の数字 + `.` または `)`）を使います。内容カラムは、マーカーの幅と最初の非空白までのスペース数（1〜4）で決まります。サブリストはその内容カラムまでインデントする必要があります。段落を中断する順序付きリストは `1` から始めなければなりません。
- **リスト**: 同種のリスト項目の並びです。箇条書き記号や順序付き区切りが変わると、新しいリストが始まります。項目のいずれかが空行で区切られていれば、そのリストは loose です。

## インライン要素

- **コードスパン**: バッククォートで囲まれたインラインコードです。改行はスペースに変換されます。先頭と末尾の両方にスペースがある場合、それらは削除されます（内容がすべてスペースの場合を除く）。コードスパン内ではバックスラッシュエスケープはリテラルとして扱われます。
- **強調と強い強調**: `<em>` には `*` / `_`、`<strong>` には `**` / `__` を使います。`_` は単語中の強調には使えません。left-flanking / right-flanking の区切り記号ルールが適用されます。ある区切り記号が開始と終了の両方になり得る場合、長さの合計が 3 の倍数であってはなりません（両方の長さが 3 の倍数である場合を除く）。
- **リンク**: インライン形式 `[text](url "title")` または参照形式 `[text][label]` / `[text][]` / `[text]` を使います。リンクテキストにはインライン要素を含められますが、別のリンクは含められません。`<…>` で囲まれた destination にはスペースを含められます。囲まれていない場合は、対応する丸括弧のみ許されます。リンクテキストと `(` または `[` の間に空白を入れてはいけません。
- **画像**: `![alt](src "title")`。リンク構文の先頭に `!` を付けたものです。代替テキストは説明部分のプレーンテキスト内容です。
- **自動リンク**: 山括弧で囲まれた `<URI>` または `<email>` です。スキームは ASCII 英字で始まり、2〜32 文字でなければなりません。CommonMark では裸の URL は自動リンクになりません（山括弧が必要です）。
- **生の HTML**: 開始／終了タグ、コメント (`<!--` … `-->`)、処理命令 (`<?` … `?>`)、宣言 (`<!` … `>`)、CDATA (`<![CDATA[` … `]]>`) は、そのままリテラル HTML として扱われます。
- **ハード改行**: 行末の 2 個以上のスペース、または行末直前の `\` です。コードスパンや HTML タグ内では認識されません。ブロック末尾では機能しません。
- **ソフト改行**: 行末の 2 個以上のスペースや `\` がない通常の改行です。ブラウザーではスペースとして表示されます。

## 検証チェックリスト

- [ ] ATX 見出しは、1〜6 個の `#` の後にスペースを置いている。
- [ ] フェンス付きコードブロックは言語識別子を指定し、開始と終了で同じ文字・同じ本数以上のフェンスを使っている。
- [ ] バッククォートフェンスの info string にバッククォートが含まれていない。
- [ ] インデント付きコードブロックの前に空行がある（段落を中断できないため）。
- [ ] 単語中の強調には `*` を使い、`_` は単語境界でのみ使っている。
- [ ] リンクは `[text](url)` または参照構文を使い、`(` や `[` の前に空白を入れていない。
- [ ] 画像には空でない代替テキストがある。
- [ ] 自動リンクは山括弧 (`<URL>`) を使っており、裸の URL を CommonMark の自動リンクとして扱っていない。
- [ ] 裸のリンク destination に対応していない丸括弧がない（必要なら `<…>` やエスケープを使う）。
- [ ] HTML ブロックのタイプ 7（独自タグ／インラインレベルタグ）は、段落の後に続く場合は前に空行がある。
