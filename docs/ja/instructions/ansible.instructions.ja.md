# Ansible の規約とベストプラクティス

## 一般的な指示

- Ansible を使用してインフラストラクチャを構成および管理します。
- Ansible 構成にはバージョン管理を使用します。
- 物事をシンプルにしてください。必要な場合にのみ高度な機能を使用する
- すべてのプレイ、ブロック、タスクに簡潔かつ説明的な `name` を付けます。
  - 「インストール」、「構成」、「コピー」など、実行される操作を示すアクション動詞で名前を始めます。
  - タスク名の最初の文字を大文字にします
  - 簡潔にするためにタスク名の末尾からピリオドを省略します。
  - ロールタスクからロール名を省略します。 Ansible は、ロールの実行時にロール名を自動的に表示します。
  - 別のファイルのタスクを含める場合、タスクを見つけやすくするために各タスク名にファイル名を含めることができます (例: `<TASK_FILENAME> : <TASK_NAME>`)
- コメントを使用して、**何を**、**どのように**、**なぜ** 何かが行われているかについての追加のコンテキストを提供します
  - 冗長なコメントを含めないでください
- クラウドリソースの動的インベントリを使用する
  - タグを使用して、環境、機能、場所などに基づいてグループを動的に作成します。
  - これらの属性に基づいて変数を設定するには、`group_vars` を使用します。
- 可能な限り冪等の Ansible モジュールを使用してください。 `shell`、`command`、`raw` は冪等性を壊すため避けてください。
  - `shell` または `command` を使用する必要がある場合は、不要な実行を防ぐために、可能な場合は `creates:` または `removes:` パラメーターを使用してください。
- [完全修飾コレクション名 (FQCN)](https://docs.ansible.com/ansible/latest/reference_appendices/glossary.html#term-Fully-Qualified-Collection-Name-FQCN) を使用して、正しいモジュールまたはプラグインが選択されていることを確認します
  - [組み込みモジュールとプラグイン](https://docs.ansible.com/ansible/latest/collections/ansible/builtin/index.html#plugin-index) には `ansible.builtin` コレクションを使用します
- 関連するタスクをグループ化して、読みやすさとモジュール性を向上させます。
- `state` がオプションのモジュールの場合は、明確さと一貫性を向上させるために `state: present` または `state: absent` を明示的に設定します
- タスクの実行に必要な最低限の権限を使用する
  - 含まれるすべてのタスクにスーパーユーザー権限が必要な場合は、再生レベルまたは `include:` ステートメントでのみ `become: true` を設定します。それ以外の場合は、タスクレベルで `become: true` を指定します
  - スーパーユーザー権限が必要なタスクにのみ `become: true` を設定します

## 機密管理

- Ansible を単独で使用する場合は、Ansible Vault を使用してシークレットを保存します
  - 次のプロセスを使用して、Vault 変数が定義されている場所を簡単に見つけられるようにします。
    1. グループにちなんで名付けられた `group_vars/` サブディレクトリを作成します
    2. このサブディレクトリ内に、`vars` と `vault` という名前の 2 つのファイルを作成します。
    3. `vars` ファイルで、機密性の高い変数を含む、必要なすべての変数を定義します。
    4. すべての機密変数を `vault` ファイルにコピーし、これらの変数の先頭に `vault_` を付けます。
    5. Jinja2 構文を使用して、一致する `vault_` 変数を指すように `vars` ファイル内の変数を調整します: `db_password: "{{ vault_db_password }}"`
    6. `vault` ファイルを暗号化して内容を保護します
    7. Playbook で `vars` ファイルの変数名を使用します
- Ansible で他のツール (例: Terraform) を使用する場合は、サードパーティのシークレット管理ツール (例: Hashicorp Vault、AWS Secrets Manager など) にシークレットを保存します。
  - これにより、すべてのツールがシークレットの信頼できる単一の情報源を参照できるようになり、構成が同期しなくなるのを防ぐことができます。

## スタイル

- 2 スペースのインデントを使用し、リストを常にインデントします
- 次のそれぞれを 1 つの空白行で区切ります。
  - 2 つのホストブロック
  - 2 つのタスクブロック
  - ホストブロックとインクルードブロック
- 変数名には `snake_case` を使用します
- `vars:` マップまたは変数ファイルで変数を定義するときに変数をアルファベット順に並べ替えます
- マップ内に存在するペアの数に関係なく、常に複数行のマップ構文を使用します。
  - 可読性が向上し、バージョン管理のためのチェンジセットの衝突が軽減されます。
- 二重引用符よりも一重引用符を使用する
  - 二重引用符を使用する必要があるのは、二重引用符が一重引用符で囲まれている場合 (例: Jinja マップ参照)、または文字列でエスケープ文字が必要な場合 (例: 改行を表すために "\n" を使用する場合) です。
  - 長い文字列を記述する必要がある場合は、折り返されたブロックスカラー構文 (つまり `>`) を使用して改行をスペースに置き換えるか、リテラルブロック スカラー構文 (つまり `|`) を使用して改行を保持します。特別な引用符をすべて省略する
- 劇の `host` セクションは、次の一般的な順序に従う必要があります。
  - `hosts`宣言
  - アルファベット順のホストオプション (例: `become`、`remote_user`、`vars`)
  - `pre_tasks`
  - `roles`
  - `tasks`
- 各タスクは次の一般的な順序に従う必要があります。
  - `name`
  - タスク宣言 (例: `service:`、`package:`)
  - タスクパラメータ (複数行のマップ構文を使用)
  - ループ演算子 (例: `loop`)
  - アルファベット順のタスクオプション (例: `become`、`ignore_errors`、`register`)
  - `tags`
- `include` ステートメントの場合、ファイル名を引用符で囲み、複数行の場合 (タグがある場合など) `include` ステートメントの間に空行のみを使用します。

## Lint

- `ansible-lint` と `yamllint` を使用して構文をチェックし、プロジェクト標準を適用します
- `ansible-playbook --syntax-check` を使用して構文エラーをチェックします
- `ansible-playbook --check --diff` を使用して、プレイブック実行の予行演習を実行します
