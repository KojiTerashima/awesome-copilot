# アクセシビリティ基準

Web アプリケーション開発のための包括的なアクセシビリティルール。すべてのアンチパターンには、重大度分類、検出方法、WCAG 2.2 リファレンス、および修正コード例が含まれています。

**重大度レベル:**

- **重大** - ユーザーはコンテンツにまったくアクセスできません。マージ前に修正する必要があります。
- **重要** — 支援技術ユーザーにとって大きな障壁となります。同じスプリントで修正します。
- **提案** — 支援技術の使いやすさを向上させます。将来の反復を計画します。

## 法執行の状況 (2026 年)

- **欧州アクセシビリティ法 (EAA)**: 2025 年 6 月から EU 加盟 27 か国すべてで施行されました。デジタル製品およびサービスに適用されます。罰金は最大300万ユーロ。 EN 301 549 を参照 (WCAG 2.1 AA にマップ)。
- **ADA タイトル II (米国)**: デジタルアクセシビリティ規則は、50,000 人以上にサービスを提供する州/地方自治体に対して 2026 年 4 月から発効します (小規模団体については 2027 年 4 月)。 WCAG 2.1 AA が必要です。
- **セクション 508 (米国連邦)**: WCAG 2.0 AA を参照 (2.1/2.2 への更新が予定されています)。

**対象**: WCAG 2.2 AA は、現在の法的要件をすべてカバーしています (2.1 AA および 2.0 AA のスーパーセット)。

## ARIAの5つのルール

1. **ネイティブ HTML を優先します** — `<div role="button">` ではなく `<button>` を使用します。ネイティブ要素には、キーボード、フォーカス、セマンティクスが組み込まれています。
2. **禁止されている場合はネイティブセマンティクスを変更しないでください** — `role="heading"` を `<button>` に追加しないでください。正しい要素を使用してください。
3. **すべての ARIA コントロールはキーボード操作可能である必要があります** — `role="button"` の場合、Enter キーとスペースキーのイベントを処理します。
4. **フォーカス可能な要素では `aria-hidden="true"` を使用しないでください** — 支援技術からは隠されていますが、フォーカス可能な要素は「ゴースト」要素を作成します。
5. **すべてのインタラクティブな要素にはアクセス可能な名前が必要です** — ラベル、`aria-label`、`aria-labelledby`、または表示されるテキストコンテンツを介して。

## セマンティック HTML アンチパターン (S1 ～ S8)

### S1: `<html>` に `lang` 属性がありません

- **重大度**: クリティカル
- **検出**: `lang=` なしの `<html`
- **WCAG**: 3.1.1 (A)

```html
<!-- BAD -->
<html>

<!-- GOOD -->
<html lang="en">
```

Next.js：`app/layout.tsx`に設定します。角度: `src/index.html` で設定します。 Vue/Nuxt: `app.vue` または `nuxt.config` で設定します。

### S2: ページごとに複数の `<h1>`

- **重大度**: 提案
- **検出**: ページ見出しの構造を不明瞭にする複数の `<h1>` 要素
- **WCAG**: ベストプラクティス (1.3.1 をサポート)

主要なトピックを表す `<h1>` を 1 ページにつき 1 つ使用することを推奨します。セクションには `<h2>` を使用します。複数の `<h1>` 要素は厳密な WCAG 違反ではありませんが、スクリーンリーダーのナビゲーションを混乱させる可能性があります。

### S3: ヘディングレベルギャップ

- **重大度**: 重要
- **検出**: `<h1>` の後に `<h3>` (`<h2>` をスキップ)
- **WCAG**: 1.3.1 (A)

論理的な入れ子を維持します: `h1 > h2 > h3 > h4`。別の見出しレベルを選択するのではなく、CSS を使用して見出しのスタイルを設定します。

### S4: Div スープ — ランドマーク要素なし

- **重大度**: 重要
- **検出**: `<nav>`、`<main>`、`<header>`、`<footer>` を含まずに `<div>` のみを使用するページ
- **WCAG**: ベストプラクティス (1.3.1、2.4.1 をサポート)

```html
<!-- GOOD -->
<header>...</header>
<nav aria-label="Main">...</nav>
<main>...</main>
<footer>...</footer>
```

### S5: `role="presentation"` を使用しないレイアウトテーブル

- **重大度**: 重要
- **検出**: `<table>`、`<th>`、`<caption>`、または `role="presentation"` なし
- **WCAG**: 1.3.1 (A)

レイアウトには CSS グリッド/フレックスボックスを使用します。レイアウトにテーブルを使用する必要がある場合は、`role="presentation"` を追加します。

### S6: ヘッダーのないデータテーブル

- **重大度**: クリティカル
- **検出**: `<table>` にはデータ行がありますが、`<th>` 要素はありません
- **WCAG**: 1.3.1 (A)

```html
<!-- GOOD -->
<table>
  <caption>User list</caption>
  <thead>
    <tr><th scope="col">Name</th><th scope="col">Email</th></tr>
  </thead>
  <tbody>
    <tr><td>Alice</td><td>alice@example.com</td></tr>
  </tbody>
</table>
```

### S7: 説明のないリンクテキスト

- **重大度**: 重要
- **検出**: `>click here<|>read more<|>learn more<|>here<|>more<|>link<`
- **WCAG**: 2.4.4 (A)

```html
<!-- BAD -->
<a href="/pricing">Click here</a>

<!-- GOOD -->
<a href="/pricing">View pricing plans</a>
```

### S8: セマンティック HTML を使用しないインタラクティブな要素

- **重大度**: クリティカル
- **検出**: `<div.*(?:onClick|@click|\(click\))`
- **WCAG**: 4.1.2 (A)

```tsx
// BAD — not focusable, no role, no keyboard support
<div onClick={handleClick}>Submit</div>

// GOOD
<button onClick={handleClick}>Submit</button>
```

## ARIA アンチパターン (A1 ～ A8)

### A1: ネイティブ要素上の冗長 ARIA

- **重大度**: 提案
- **検出**: `<button.*role="button"|<nav.*role="navigation"|<a.*role="link"`
- **WCAG**: ARIA ルール 2

冗長な ARIA を削除します。 `<button>` にはすでに `role="button"` があります。

### A2: フォーカス可能な要素の `aria-hidden="true"`

- **重大度**: クリティカル
- **検出**: フォーカス可能な要素 (ボタン、入力、a、[tabindex]) の `aria-hidden="true"`
- **WCAG**: ARIA ルール 4

`aria-hidden="true"` コンテンツ内にフォーカス可能な要素を残したままにしたり、フォーカス可能な要素で `aria-hidden="true"` を使用したりしないでください。 `<button>` や `<input>` など、それをサポートするネイティブコントロールの場合、コントロールを無効にすることが意図された動作である場合は、`disabled` を使用してください。 `<a>` 要素または `[tabindex]` でフォーカス可能になった任意の要素の場合は、代わりにフォーカス可能性を削除します (たとえば、`href` または `tabindex` を削除します)。コンテンツが完全に非インタラクティブであり、支援技術から隠される必要がある場合は、`inert`、`hidden` を使用するか、DOM から削除してください。

### A3: 必要な ARIA プロパティがありません

- **重大度**: クリティカル
- **検出**: `role="tab"` なし `aria-selected`、`role="checkbox"` なし `aria-checked`
- **WCAG**: 4.1.2 (A)

役割ごとに必須: `tab` には `aria-selected` が必要です。 `combobox` には `aria-expanded`/`aria-controls` が必要です。 `slider` には `aria-valuemin`/`aria-valuemax`/`aria-valuenow` が必要です。 `checkbox` には `aria-checked` が必要です。

### A4: 無効な ARIA ロール値

- **重大度**: クリティカル
- **検出**: 存在しない値を含む `role="[^"]*"`
- **WCAG**: 4.1.2 (A)

無効な役割は支援技術によって無視されます。よくある間違い: `role="input"`、`role="text"`、スペルミス。

### A5: ネイティブ HTML が機能する ARIA

- **重大度**: 重要
- **検出**: `role="button"` 対 `<div>`、`role="checkbox"` 対 `<div>`
- **WCAG**: ARIA ルール 1

```html
<!-- BAD — requires manual keyboard, focus, and state management -->
<div role="checkbox" aria-checked="false" tabindex="0">Accept terms</div>

<!-- GOOD — all behavior built-in -->
<label><input type="checkbox" /> Accept terms</label>
```

### A6: アイコンのみのボタンに `aria-label` がありません

- **重大度**: クリティカル
- **検出**: `<button` SVG/アイコンの子がありテキストなし、または `aria-label`
- **WCAG**: 4.1.2 (A)

```html
<!-- GOOD -->
<button aria-label="Close dialog"><svg aria-hidden="true">...</svg></button>
```

### A7: フォーカス可能な要素に関する `role="presentation"`

- **重大度**: 重要
- **検出**: インタラクティブ要素の `role="presentation"`
- **WCAG**: ARIA ルール 4

ブラウザはフォーカス可能な要素のプレゼンテーションの役割を無視します。

### A8: 動的コンテンツのライブ領域がありません

- **重大度**: 重要
- **検出**: `role="alert"`、`role="status"`、または `aria-live` のないトースト/通知コンポーネント
- **WCAG**: 4.1.3 (AA)

```html
<!-- GOOD — content announced when content is injected into a preexisting live region element in the DOM -->
<div role="status" aria-live="polite">Item saved successfully</div>
<!-- Use role="alert" (assertive) for errors -->
<div role="alert">Failed to save. Please try again.</div>
```

## キーボードとフォーカスのアンチパターン (K1 ～ K7)

### K1: `onClick` 非ネイティブ要素の `onKeyDown` なし

- **重大度**: クリティカル
- **検出**: キーボードハンドラーなしの `<div>` または `<span>` 上の `(?:onClick|@click|\(click\))`
- **WCAG**: 2.1.1 (A)

代わりに `<button>` を使用してください。 div が必要な場合: `role="button"`、`tabIndex={0}` を追加し、Enter キーとスペースキーのアクティブ化を処理します。

### K2: 正の `tabindex` 値

- **重大度**: クリティカル
- **検出**: `(?:tabindex="[1-9]\d*"|tabIndex=\{[1-9]\d*\})`
- **WCAG**: 2.4.3 (A)

`tabindex="0"` (タブオーダーに追加) と `tabindex="-1"` (プログラムによるフォーカスのみ) のみを使用してください。

### K3: 逃げ場のない集中トラップ

- **重大度**: クリティカル
- **検出**: Escape キーハンドラーまたはフォーカストラッピングを使用しないモーダル/オーバーレイ
- **WCAG**: 2.1.2 (A)

ネイティブ `<dialog>` を `showModal()` とともに使用します。これにより、キーボードのフォーカスが不活性な非ダイアログコンテンツに移動するのを防ぎます。さらに、閉じるための Escape キーが組み込まれており、フォーカスは呼び出し元の要素 (使用可能な場合) に自動的に戻ります。カスタムモーダル ダイアログの実装が必要な場合: ダイアログ内で Tab をトラップするか、非ダイアログコンテンツに `inert` 属性を使用します (ダイアログを含む要素で `inert` を使用しないでください)。エスケープで閉じます (ユーザーによるアクションの確認が必須でない場合)。クローズ時にトリガー要素にフォーカスを戻すか、トリガー要素が終了時に存在しなくなった場合は最適な論理位置に戻ります。

### K4: スキップリンクがありません

- **重大度**: 重要
- **検出**: 最初のフォーカス可能な要素としてスキップリンクがありません
- **WCAG**: 2.4.1 (A)

```html
<a href="#main-content" class="skip-link">Skip to main content</a>
<nav>...</nav>
<main id="main-content" tabindex="-1">...</main>
```

```css
.skip-link { position: absolute; top: -40px; left: 0; padding: 8px 16px; background: #000; color: #fff; z-index: 100; }
.skip-link:focus { top: 0; }
```

### K5: `outline: none` 交換なし

- **重大度**: クリティカル
- **検出**: `:focus-visible` 置換なしの `outline:\s*none|outline:\s*0\b`
- **WCAG**: 2.4.7 (AA)

```css
/* GOOD */
button:focus-visible { outline: 2px solid #005fcc; outline-offset: 2px; }
```

### K6: マウスのみのインタラクション

- **重大度**: 重要
- **検出**: `onMouseOver|onMouseEnter|@mouseenter` キーボード相当なし
- **WCAG**: 2.1.1 (A)

ホバーとフォーカスイベントを組み合わせます。 `onFocus`/`onBlur` を `onMouseEnter`/`onMouseLeave` と一緒に使用します。

### K7: カスタムモーダルを閉じた後にフォーカスが返されない

- **重大度**: 重要
- **検出**: フォーカスをトリガーに戻さずにカスタムモーダル ダイアログが閉じます
- **WCAG**: 2.4.3 (A)

トリガー要素への参照、またはクローズ時にトリガー要素が存在しなくなった場合は最適な論理位置に参照を保存します。モーダルを閉じるときに、`triggerElement.focus()` を呼び出します。

## フォームのアンチパターン (F1 ～ F6)

### F1: 関連ラベルなしの入力

- **重大度**: クリティカル
- **検出**: `<label>`、`aria-label`、または `aria-labelledby` なしの `<input|<select|<textarea`
- **WCAG**: 1.3.1 (A)、3.3.2 (A)

```html
<!-- GOOD -->
<label for="email">Email address</label>
<input id="email" type="email" placeholder="you@example.com" />
```

### F2: 入力にリンクされていないエラーメッセージ

- **重大度**: クリティカル
- **検出**: `aria-describedby` のない入力付近のエラー要素
- **WCAG**: 3.3.1 (A)

```html
<input id="email" type="email" aria-describedby="email-error" aria-invalid="true" />
<span id="email-error" class="error">Invalid email format</span>
```

### F3: 色または`*`のみで示される必須フィールド

- **重大度**: 重要
- **検出**: `aria-required="true"` または HTML `required` なしの `required` または `*`
- **WCAG**: 3.3.2 (A)、1.4.1 (A)

```html
<label for="name">Name <span aria-hidden="true">*</span></label>
<input id="name" type="text" required />
<p class="form-note">Fields marked * are required</p>
```

### F4: エラー概要なし、または最初のエラーに焦点を当てる

- **重大度**: 重要
- **検出**: 検証失敗時のフォーカス管理を行わないフォーム送信ハンドラー
- **WCAG**: 3.3.1 (A)

送信が失敗した場合は、最初の無効なフィールドに焦点を当てるか、エラーの概要を表示して焦点を当てます。

### F5: アクセス可能な代替のない CAPTCHA

- **重大度**: 重要
- **検出**: フォールバックなしのパズル/画像 CAPTCHA。 `autocomplete='off'` または貼り付けをブロックする JavaScript を含むパスワードフィールド
- **WCAG**: 3.3.8 (AA)

reCAPTCHA v3 (非表示)、hCaptcha アクセシビリティモード、または代替認証を使用します。パスワードフィールドへの貼り付けや自動入力をブロックしないでください。これは WCAG 3.3.8 に違反します。

### F6: ラベルとしてのプレースホルダー

- **重大度**: 重要
- **検出**: `<label>`、`aria-label`、または `aria-labelledby` を伴わない `placeholder=`
- **WCAG**: 3.3.2 (A)

プレースホルダーは常に、表示されている `<label>` と組み合わせてください。プレースホルダーはラベルではなくヒントです。

## ビジュアルおよびカラーのアンチパターン (V1 ～ V5)

### V1: テキストのコントラストが不十分です

- **重大度**: クリティカル
- **検出**: 4.5:1 (標準) または 3:1 (大) 未満のテキスト色の組み合わせ
- **WCAG**: 1.4.3 (AA)

```css
/* BAD — #999 on #fff is ~2.5:1 */
.text { color: #999; background: #fff; }

/* GOOD — #595959 on #fff is 7.0:1 */
.text { color: #595959; background: #fff; }
```

### V2: 色だけで伝わる情報

- **重大度**: クリティカル
- **検出**: エラー/成功状態を色のみで区別
- **WCAG**: 1.4.1 (A)

二次インジケーターを追加します: アイコン、テキスト、パターン、下線、または枠線。

### V3: サイズ変更を妨げるフォントサイズの修正

- **重大度**: 重要
- **検出**: `font-size:\s*[0-9]*px` (ルート/ベースを除く)
- **WCAG**: 1.4.4 (AA)

フォントサイズには `rem` または `em` を使用します。基本フォントは `px` にすることができますが、コンテンツフォントは相対フォントである必要があります。

### V4: 320px でコンテンツがリフローしない

- **重大度**: 重要
- **検出**: 固定幅コンテナ、狭い幅での水平スクロール
- **WCAG**: 1.4.10 (AA)

レスポンシブなレイアウト (グリッド、フレックスボックス) を使用します。 CSS幅320pxでテストします。固定幅のコンテナは避けてください。

### V5: `prefers-reduced-motion` なしのアニメーション

- **重大度**: 提案
- **検出**: `prefers-reduced-motion` メディアクエリなしの `animation:|transition:`
- **WCAG**: 2.3.3 (AAA)

ベストプラクティスと AAA の強化。重要でないアニメーションを `prefers-reduced-motion` の背後にゲートして、動きの少なさを要求するユーザーがインタラクションによって引き起こされる効果を経験することを強制されないようにします。

```css
@media (prefers-reduced-motion: no-preference) {
  .card { transition: transform 0.3s ease; }
  .card:hover { transform: scale(1.05); }
}
```

## メディアのアンチパターン (D1 ～ D4)

### D1: 代替テキストのない情報画像

- **重大度**: クリティカル
- **検出**: `alt=` 属性なしの `<img|<Image`
- **WCAG**: 1.1.1 (A)

代替テキスト決定ツリー: 装飾 = `alt=""`;テキストを含む = そのテキストを含めます。機能的 = アクションを説明します。情報 = 内容を説明します。

### D2: 空ではない Alt を使用した装飾画像

- **重大度**: 提案
- **検出**: 意味のある代替テキストを含む装飾画像
- **WCAG**: 1.1.1 (A)

装飾画像には `alt=""` を使用してください。装飾的な SVG の場合は `aria-hidden="true"` を追加します。

### D3: キャプションのないビデオ

- **重大度**: クリティカル
- **検出**: `<track kind="captions">` なしの `<video`
- **WCAG**: 1.2.2 (A)

```html
<video src="/tutorial.mp4" controls>
  <track kind="captions" src="/tutorial-en.vtt" srclang="en" label="English" default />
</video>
```

### D4: オーディオ/ビデオの自動再生

- **重大度**: 重要
- **検出**: `muted` のない `autoplay` 属性
- **WCAG**: 1.4.2 (A)

音声を自動再生しないでください。ビデオが自動再生される場合は、コントロールを使用してミュートから開始します。

## フレームワーク固有: React / Next.js (RX1-RX4)

### RX1: `<label>` に `htmlFor` がありません

- **重大度**: 重要
- **検出**: JSX の `<label.*for="` (`htmlFor` である必要があります)
- **WCAG**: 1.3.1 (A)、3.3.2 (A)

### RX2: フォーカス管理を使用しない SPA ルート変更

- **重大度**: 重要
- **検出**: フォーカス管理またはライブ領域を使用しないナビゲーション
- **WCAG**: 4.1.3 (AA)

ルート変更後は、メインの見出しに焦点を当てるか、ライブ領域を介して新しいページのタイトルをアナウンスします。 Next.js には、`document.title`、`<h1>`、パス名を読み取る組み込みのルートアナウンサー (v13 以降) が含まれています。すべてのページに一意の `<title>` があることを確認してください。

### RX3: フラグメントルートにより再レンダリング時にフォーカスが失われる

- **重大度**: 提案
- **検出**: DOM の再構築を引き起こす条件付きレンダリングを伴う `<>...</>` ルート
- **WCAG**: 2.4.3 (A)

`key` プロパティを使用して DOM アイデンティティを保持するか、`useRef` + `useEffect` を使用して手動でフォーカスを復元します。

### RX4: ARIA を考慮せずに挿入された HTML

- **重大度**: 重要
- **検出**: アクセシビリティ検証を行わないリッチテキスト レンダリング
- **WCAG**: 1.3.1 (A)

見出し階層、代替テキスト、および ARIA 構造について、挿入された HTML をサニタイズおよび検証します。

## フレームワーク固有: Angular (NG1 ～ NG4)

### NG1: `(click)` 上の `<div>` 役割とキーボードのサポートなし

- **重大度**: クリティカル
- **検出**: `(click)` 上 `<div>` または `<span>` なし `role=`、`tabindex`、`(keydown)`
- **WCAG**: 2.1.1 (A)、4.1.2 (A)

`<button>`を使用してください。 div が必要な場合: `role="button"`、`tabindex="0"`、`(keydown.enter)`、`(keydown.space)` を追加します。

### NG2: モーダルコンポーネントに `cdkTrapFocus` がありません

- **重大度**: 重要
- **検出**: `cdkTrapFocus` のないモーダルコンポーネント
- **WCAG**: 2.1.2 (A)

```html
<div class="modal" cdkTrapFocus [cdkTrapFocusAutoCapture]="true">...</div>
```

Angular CDK の `Dialog` サービスは、フォーカストラッピングと復元を自動的に処理します。

### NG3：LiveAnnouncerを使用しないルート変更

- **重大度**: 重要
- **検出**: `LiveAnnouncer` を使用しない Angular Router ナビゲーション
- **WCAG**: 4.1.3 (AA)

```typescript
router.events.pipe(filter(e => e instanceof NavigationEnd)).subscribe(() => {
  liveAnnouncer.announce(titleService.getTitle(), 'polite');
});
```

### NG4: アクセス可能な検証のないテンプレート駆動型フォーム

- **重大度**: 重要
- **検出**: `[attr.aria-invalid]` または `[attr.aria-describedby]` のないフォームにエラーが表示される
- **WCAG**: 3.3.1 (A)、3.3.3 (AA)

`[attr.aria-invalid]` と `[attr.aria-describedby]` をバインドして制御状態を形成します。

## フレームワーク固有: Vue (VU1 ～ VU3)

### VU1: 役割とキーボードのない非インタラクティブ要素の `@click`

- **重大度**: クリティカル
- **検出**: `<div>` 上の `@click` または `role=`、`tabindex`、`@keydown` を除く `<span>`
- **WCAG**: 2.1.1 (A)、4.1.2 (A)

`<button>`を使用してください。または、`role="button"`、`tabindex="0"`、`@keydown.enter`、`@keydown.space.prevent` を追加します。

### VU2: `v-if` フォーカス管理なしで切り替える

- **重大度**: 重要
- **検出**: `nextTick` 経由でフォーカスを管理せずに `v-if` を切り替えます
- **WCAG**: 2.4.3 (A)

```vue
<script setup>
import { ref, watch, nextTick } from 'vue';
const showPanel = ref(false);
const panel = ref(null);
watch(showPanel, async (val) => {
  if (val) { await nextTick(); panel.value?.focus(); }
});
</script>
```

### VU3: `v-html` アクセス可能な構造を持たないコンテンツの挿入

- **重大度**: 重要
- **検出**: `v-html` レンダリングユーザーまたは CMS コンテンツ
- **WCAG**: 1.3.1 (A)

インジェクションの前に、見出し階層、代替テキスト、および ARIA 構造の HTML をサニタイズおよび検証します。

## アクセシビリティチェックリスト (POUR)

### 知覚可能
- [ ] すべての画像には適切な代替テキスト (説明的なもの、または装飾用に空) が含まれています。
- [ ] 動画には同期されたキャプションがあります
- [ ] ページはセマンティックランドマークを使用します: `<header>`、`<nav>`、`<main>`、`<footer>`
- [ ] 見出しは論理階層に従います (h1 > h2 > h3、ギャップなし)
- [ ] テキストのコントラストは 4.5:1 (標準) / 3:1 (ラージ) を満たします
- [ ] UI コンポーネントのコントラストが 3:1 を満たす
- [ ] 色だけでは伝わらない情報
- [ ] 水平スクロールなしでコンテンツが 320 ピクセルでリフローされる
- [ ] `<html lang="...">` は正しく設定されています
- [ ] コンテンツを失うことなくテキストのサイズを 200% まで変更可能

### 操作可能
- [ ] すべての機能にキーボードからアクセス可能
- [ ] キーボードトラップなし (エスケープするとオーバーレイが閉じます)
- [ ] 最初のフォーカス可能な要素として提供されるスキップリンク
- [ ] すべてのインタラクティブ要素に表示されるフォーカスインジケーター
- [ ] フォーカスの順序が視覚的な順序と一致する
- [ ] スティッキーなヘッダー/フッターによってフォーカスが隠されない
- [ ] モーダルを閉じた後、フォーカスがトリガーに戻りました
- [ ] 少なくとも 24x24 CSS ピクセルのタッチターゲット
- [ ] アニメーションは `prefers-reduced-motion` を尊重しています
- [ ] 1 秒間に 3 回を超えて点滅するコンテンツはありません

### 理解できる
- [ ] すべてのフォーム入力には `<label>` または `aria-label` が関連付けられています
- [ ] `aria-describedby` を介して入力にリンクされたエラーメッセージ
- [ ] `required` または `aria-required` で示される必須フィールド
- [ ] 送信失敗時のエラー概要または最初のエラーに焦点を当てる
- [ ] フォーカスまたは入力時に予期しないコンテキストの変更はありません

### 屈強
- [ ] すべてのインタラクティブな要素には、アクセス可能な名前、役割、および状態があります。
- [ ] ARIA ロールには必須のプロパティがあります
- [ ] フォーカス可能な要素に `aria-hidden="true"` はありません
- [ ] ライブリージョンを通じて発表される動的コンテンツ
- [ ] SPA ルートの変更がスクリーンリーダーに発表されました
- [ ] ネイティブ HTML 要素には冗長な ARIA はありません
