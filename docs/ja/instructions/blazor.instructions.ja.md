## Blazor コードのスタイルと構造

- 慣用的で効率的な Blazor および C# コードを作成します。
- .NET と Blazor の規則に従います。
- コンポーネントベースの UI 開発には、Razor コンポーネントを適切に使用します。
- より小さなコンポーネントにはインライン関数を優先しますが、複雑なロジックは分離コードまたはサービスクラスに分離します。
- 非ブロックの UI 操作を保証するために、該当する場合は Async/await を使用する必要があります。

## 命名規則

- コンポーネント名、メソッド名、パブリックメンバーについては PascalCase に従ってください。
- プライベートフィールドとローカル変数にはキャメルケースを使用します。
- インターフェイス名の前に「I」を付けます (IUserService など)。

## Blazor および .NET 固有のガイドライン

- コンポーネントのライフサイクルに Blazor の組み込み機能 (OnInitializedAsync、OnParametersSetAsync など) を利用します。
- @bind を使用してデータバインディングを効果的に使用します。
- Blazor のサービスに依存関係の注入を活用します。
- 関心事の分離に従って Blazor コンポーネントとサービスを構造化します。
- 常に最新バージョンの C# を使用してください。現在は、レコード型、パターンマッチング、グローバル使用などの C# 13 機能を使用します。

## エラー処理と検証

- Blazor ページと API 呼び出しに対して適切なエラー処理を実装します。
- バックエンドでのエラー追跡にログを使用し、ErrorBoundary などのツールを使用して Blazor で UI レベルのエラーをキャプチャすることを検討してください。
- フォームで FluentValidation または DataAnnotations を使用して検証を実装します。

## Blazor API とパフォーマンスの最適化

- プロジェクトの要件に基づいて、サーバー側の Blazor または WebAssembly を最適に利用します。
- メインスレッドをブロックする可能性のある API 呼び出しまたは UI アクションには、非同期メソッド (async/await) を使用します。
- 不必要なレンダリングを減らし、StateHasChanged() を効率的に使用することで、Razor コンポーネントを最適化します。
- 必要に応じて ShouldRender() を使用して、必要な場合を除いて再レンダリングを回避し、コンポーネントのレンダーツリーを最小化します。
- ユーザーインタラクションを効率的に処理するには EventCallbacks を使用し、イベントをトリガーするときに最小限のデータのみを渡します。

## キャッシュ戦略

- 頻繁に使用されるデータ、特に Blazor Server アプリに対してメモリ内キャッシュを実装します。軽量のキャッシュソリューションには IMemoryCache を使用します。
- Blazor WebAssembly の場合、localStorage または sessionStorage を利用して、ユーザーセッション間でアプリケーションの状態をキャッシュします。
- 複数のユーザーまたはクライアント間で状態を共有する必要がある大規模なアプリケーションの場合は、分散キャッシュ戦略 (Redis や SQL Server キャッシュなど) を検討してください。
- 応答を保存することで API 呼び出しをキャッシュし、データが変更される可能性が低い場合の冗長な呼び出しを回避し、ユーザーエクスペリエンスを向上させます。

## 状態管理ライブラリ

- コンポーネント間で基本的な状態を共有するには、Blazor の組み込みの Cascading Parameters と EventCallbacks を使用します。
- アプリケーションが複雑になる場合は、Fluxor や BlazorState などのライブラリを使用して高度な状態管理ソリューションを実装します。
- Blazor WebAssembly でのクライアント側の状態の永続性については、Blazored.LocalStorage または Blazored.SessionStorage を使用してページのリロード間の状態を維持することを検討してください。
- サーバー側 Blazor の場合は、スコープ指定されたサービスと StateContainer パターンを使用して、再レンダリングを最小限に抑えながらユーザーセッション内の状態を管理します。

## APIの設計と統合

- HttpClient またはその他の適切なサービスを使用して、外部 API または独自のバックエンドと通信します。
- try-catch を使用して API 呼び出しのエラー処理を実装し、UI で適切なユーザーフィードバックを提供します。

## Visual Studio でのテストとデバッグ

- すべての単体テストと統合テストは Visual Studio Enterprise で実行する必要があります。
- xUnit、NUnit、または MSTest を使用して Blazor コンポーネントとサービスをテストします。
- テスト中に依存関係をモックするには Moq または NSubstitute を使用します。
- バックエンドおよびサーバー側の問題については、ブラウザー開発者ツールと Visual Studio のデバッグツールを使用して、Blazor UI の問題をデバッグします。
- パフォーマンスのプロファイリングと最適化については、Visual Studio の診断ツールを利用してください。

## セキュリティと認証

- 必要に応じて、API 認証用の ASP.NET ID または JWT トークンを使用して、Blazor アプリに認証と承認を実装します。
- すべての Web 通信に HTTPS を使用し、適切な CORS ポリシーが実装されていることを確認します。

## API ドキュメントと Swagger

- バックエンド API サービスの API ドキュメントには Swagger/OpenAPI を使用します。
- Swagger ドキュメントを強化するために、モデルと API メソッドの XML ドキュメントを確保します。
