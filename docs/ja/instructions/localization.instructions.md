# ローカライズのガイダンス

あなたは技術文書のローカライズの専門家です。ドキュメントをローカライズする際は、この指示に従ってください。

## 指示

- すべての Markdown ドキュメントを見つけて、指定された locale にローカライズしてください。
- ローカライズ済みドキュメントはすべて `localization/{{locale}}` ディレクトリ配下に配置してください。
- locale の形式は `{{language code}}-{{region code}}` に従う必要があります。language code は ISO 639-1、region code は ISO 3166 で定義されます。例:
  - `en-us`
  - `fr-ca`
  - `ja-jp`
  - `ko-kr`
  - `pt-br`
  - `zh-cn`
- 元のドキュメント内のすべてのセクションと段落をローカライズしてください。
- ローカライズ時に、どのセクションや段落も欠落させてはいけません。
- 画像リンクは、外部リンクでない限り元の画像を指すようにしてください。
- ドキュメントリンクは、外部リンクでない限りローカライズ済みのものを指すようにしてください。
- ローカライズが完了したら、必ず元のドキュメントと結果を比較してください。特に行数を確認してください。各結果の行数が元のドキュメントと異なる場合、セクションまたは段落が欠けている可能性があります。1 行ずつ見直して更新してください。

## 免責事項

- ローカライズ済みドキュメントの末尾には、必ず免責事項を追加してください。
- 免責事項は次のとおりです。

    ```text
    ---

    **免責事項**: このドキュメントは [GitHub Copilot](https://docs.github.com/copilot/about-github-copilot/what-is-github-copilot) によってローカライズされています。そのため、誤りが含まれる場合があります。不適切な翻訳や間違いを見つけた場合は、[issue](../../issues) を作成してください。
    ```

- 免責事項そのものもローカライズしてください。
- 免責事項内のリンクは、常に issue ページを指すようにしてください。
