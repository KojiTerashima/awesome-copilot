# SQL 開発

## データベーススキーマ生成
- すべてのテーブル名は単数形にする
- すべてのカラム名は単数形にする
- すべてのテーブルに `id` という名前の主キー列を持たせる
- すべてのテーブルに作成日時を保存する `created_at` という列を持たせる
- すべてのテーブルに最終更新日時を保存する `updated_at` という列を持たせる

## データベーススキーマ設計
- すべてのテーブルに主キー制約を設定する
- すべての外部キー制約には名前を付ける
- すべての外部キー制約はインラインで定義する
- すべての外部キー制約に `ON DELETE CASCADE` オプションを付ける
- すべての外部キー制約に `ON UPDATE CASCADE` オプションを付ける
- すべての外部キー制約は親テーブルの主キーを参照する

## SQL コーディングスタイル
- SQL キーワードは大文字で記述する (SELECT、FROM、WHERE)
- ネストしたクエリや条件には一貫したインデントを使う
- 複雑なロジックを説明するコメントを含める
- 可読性のため、長いクエリは複数行に分割する
- 句の並びを一貫させる (SELECT、FROM、JOIN、WHERE、GROUP BY、HAVING、ORDER BY)

## SQL クエリ構造
- SELECT 文では `SELECT *` ではなく明示的なカラム名を使う
- 複数テーブルを使う場合、カラム名はテーブル名またはエイリアスで修飾する
- 結合で代替できる場合は、サブクエリの使用を抑える
- 結果セットを制限するため LIMIT/TOP 句を含める
- 頻繁に検索されるカラムには適切なインデックスを用意する
- WHERE 句ではインデックス付きカラムに対する関数使用を避ける

## ストアドプロシージャー命名規則
- ストアドプロシージャー名には接頭辞として 'usp_' を付ける
- ストアドプロシージャー名は PascalCase を使う
- 目的がわかる説明的な名前にする (例: usp_GetCustomerOrders)
- 複数レコードを返す場合は複数形の名詞を含める (例: usp_GetProducts)
- 単一レコードを返す場合は単数形の名詞を含める (例: usp_GetProduct)

## パラメーター処理
- パラメーターには '@' を付ける
- パラメーター名は camelCase を使う
- 任意パラメーターにはデフォルト値を与える
- 使用前にパラメーター値を検証する
- コメントでパラメーターを文書化する
- パラメーターの並びは一貫させる (必須を先、任意を後)


## ストアドプロシージャー構造
- 説明、パラメーター、戻り値を含むヘッダーコメントブロックを入れる
- 標準化されたエラーコード / メッセージを返す
- 結果セットは一貫したカラム順で返す
- ステータス情報の返却には OUTPUT パラメーターを使う
- 一時テーブルには接頭辞として 'tmp_' を付ける


## SQL セキュリティのベストプラクティス
- SQL インジェクションを防ぐため、すべてのクエリをパラメーター化する
- 動的 SQL を実行する場合は prepared statement を使う
- SQL スクリプトに資格情報を埋め込まない
- システム詳細を露出しない適切なエラーハンドリングを実装する
- ストアドプロシージャー内で動的 SQL を使わない

## トランザクション管理
- トランザクションは明示的に開始しコミットする
- 要件に応じた適切な分離レベルを使う
- テーブルをロックする長時間トランザクションは避ける
- 大量データ操作にはバッチ処理を使う
- データを変更するストアドプロシージャーには `SET NOCOUNT ON` を含める
