# Markdown アクセシビリティレビューガイドライン

Markdown ファイルをレビューする際は、GitHub の [GitHub profile page をアクセシブルにする 5 つのヒント](https://github.blog/developer-skills/github/5-tips-for-making-your-github-profile-page-accessible/) に基づき、次のアクセシビリティ上の問題を確認してください。違反があれば指摘し、アクセシビリティへの影響が分かるよう明確に修正案を提示してください。

## 1. 説明的なリンク

- "click here"、"here"、"this"、"read more"、"link" のような一般的すぎるリンクテキストは指摘してください。
- 支援技術ではリンクが独立した一覧として提示されることがあるため、リンクテキストは文脈なしでも意味が通る必要があります。
- 同じページ内で、同一のリンクテキストなのに別の遷移先を指している複数のリンクは指摘してください。
- 本文中の裸の URL は、説明的なリンクに変換してください。

悪い例: `私のブログ記事を [こちら](https://example.com) で読んでください`
良い例: `私のブログ記事「[アクセシブルな履歴書を作る](https://example.com)」を読んでください`

## 2. 画像の代替テキスト

- 空の代替テキストを持つ画像（例: `![](path/to/image.png)`）は、明確に装飾目的でない限り指摘してください。
- ファイル名（例: `img_1234.jpg`）や一般的すぎるプレースホルダー（例: `screenshot`, `image`）になっている代替テキストは指摘してください。
- 代替テキストは簡潔かつ説明的であるべきです。画像内に見えているテキストも含めてください。
- 適切な場合は "screenshot of" を使ってよいですが、スクリーンリーダーは自動的に画像であることを読み上げるため、"image of" は先頭に付けないでください。
- 複雑な画像（グラフ、インフォグラフィックなど）では、代替テキストでデータを要約し、より長い説明を `<details>` タグやリンク先コンテンツで提供するよう提案してください。
- 代替テキスト改善の提案を行うときは、著者が確認すべき推奨案として提示してください。適切な代替テキストには、著者だけが把握している視覚的内容や文脈の理解が必要です。

## 3. 見出し階層

- 各ドキュメントの H1 (`#`) は 1 つだけで、ページタイトルとして使われるべきです。注: frontmatter から H1 が自動生成されるプロジェクトでは、コンテンツは H2 から始めてください。
- 見出しは論理的な階層に従い、レベルを飛ばしてはいけません（例: `##` の次に `####` が来るのは違反です）。
- 見出しの代わりに視覚的な強調として使われている太字テキスト (`**text**`) を指摘してください。
- 適切な見出し構造があると、支援技術の利用者はセクション単位で移動しやすくなり、視覚的に閲覧する利用者も内容を把握しやすくなります。

## 4. 平易な言葉

- 不必要に複雑な表現や専門用語が多すぎる文章は、より平易にできる箇所として指摘してください。
- 短い文、一般的な単語、能動態を優先してください。
- 長く密度の高い段落は、小さなセクションやリストに分割できる箇所として指摘してください。
- UI ナビゲーションを説明するときは、まず「Settings を開き、次に Preferences を選ぶ」のように、平易な言葉で順番に行動を書いてください。アイコン名や見た目の説明ではなく、一般的で安定したラベルを使います。
- 補足として視覚的な参照を括弧内に添えるのは構いません（例: `(歯車アイコン > Preferences)`）が、視覚的なパンくず表現やアイコン名だけでナビゲーションを説明してはいけません。
- 平易な言葉への改善提案は、著者が確認すべき推奨案として提示してください。文体や表現の選択には、対象読者、文脈、トーンの理解が必要です。

## 5. リストと絵文字の使い方

### リスト

- Markdown の正式なリスト構文 (`-`, `*`, `+`, `1.`) の代わりに、絵文字や特殊文字を箇条書きとして使っている場合は指摘してください。
- 平文のまま並んでいて、本来は適切なリストとして構造化すべき連続項目を指摘してください。
- 正しいリストマークアップにより、スクリーンリーダーは「3 件中 1 件目」のようなリスト文脈を読み上げられます。

### 絵文字

- 絵文字が連続して複数使われている場合は指摘してください。スクリーンリーダーでは各絵文字名がすべて読み上げられるため、利用者の負担になります（例: "rocket" "sparkles" "fire"）。
- テキストで伝えていない意味を絵文字だけで表現している場合は指摘してください。
- 絵文字は控えめかつ意図的に使うべきです。

## レビュー時の優先順位

複数の問題がある場合は、次の順序で優先してください。

1. 画像の代替テキストが欠けている、または空である
2. 見出しレベルの飛びや見出し階層の問題
3. 説明性のないリンクテキスト
4. 箇条書きやリストマーカーとして絵文字が使われている
5. 平易な言葉への改善

## レビューのトーン

- 各問題について、どの利用者に影響するのか（例: スクリーンリーダー利用者、認知障害のある人、非ネイティブスピーカー）を明示しながら、アクセシビリティへの影響を説明してください。
- 文章の個性や語り口を消さないでください。アクセシビリティと魅力的なコンテンツは両立できます。
- 提案は具体的で、すぐに実行できる内容にしてください。
