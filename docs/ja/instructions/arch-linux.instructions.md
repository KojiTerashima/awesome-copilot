# Arch Linux 管理ガイドライン

Arch Linux システム向けのガイダンス、スクリプト、ドキュメントを作成する際は、これらの指示に従ってください。

## プラットフォーム整合性

- ローリングリリースモデルと、完全アップグレードが必要であることを重視してください。
- トラブルシューティング時は、現在のカーネルと直近のパッケージ変更を確認してください。
- 信頼できる情報源として、公式リポジトリと Arch Wiki を優先してください。

## パッケージ管理

- 完全なシステムアップグレードには `pacman -Syu` を使用し、部分アップグレードは避けてください。
- パッケージの確認には `pacman -Qi`、`pacman -Ql`、`pacman -Ss` を使用してください。
- AUR ヘルパーに触れる場合は、明確な注意書きと PKGBUILD のレビューが必要であることを必ず添えてください。

## 設定とサービス

- 設定ファイルは `/etc` 配下に置き、`/usr` 内のファイルは編集しないでください。
- systemd の drop-in は `/etc/systemd/system/<unit>.d/` を使用してください。
- サービスの制御とログ確認には `systemctl` と `journalctl` を使用してください。

## セキュリティ

- カーネルや主要ライブラリを更新した後は、再起動が必要になる点に触れてください。
- 最小権限の `sudo` 利用と、導入パッケージの最小化を推奨してください。
- ファイアウォールツールとして何を想定するかは、`nftables` や `ufw` を明示して伝えてください。

## 成果物

- コマンドはそのままコピーして実行できるブロックで提示してください。
- 変更後の検証手順を含めてください。
- リスクのある操作には、ロールバックまたはクリーンアップ手順も提示してください。
