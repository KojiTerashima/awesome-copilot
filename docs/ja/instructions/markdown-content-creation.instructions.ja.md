# Markdown コンテンツ規則

以下の Markdown コンテンツ規則は、バリデーターで強制されます。

1. **見出し**: 適切な見出しレベル（H2、H3 など）を使ってコンテンツを構造化してください。H1 見出しはタイトルに基づいて生成されるため、使用しないでください。
2. **リスト**: リストには箇条書きまたは番号付きリストを使ってください。適切なインデントと間隔を保ってください。
3. **コードブロック**: コードスニペットにはフェンス付きコードブロックを使ってください。構文ハイライトのために言語を指定してください。
4. **リンク**: リンクには適切な Markdown 構文を使ってください。リンクが有効でアクセシブルであることを確認してください。
5. **画像**: 画像には適切な Markdown 構文を使ってください。アクセシビリティのために代替テキストを含めてください。
6. **表**: 表形式データには Markdown テーブルを使ってください。適切な整形と列揃えを確保してください。
7. **行の長さ**: 可読性のため、1 行の長さは 400 文字以内に制限してください。
8. **空白**: セクションを分け、可読性を高めるために適切な空白を使ってください。
9. **フロントマター**: ファイルの先頭に、必要なメタデータ項目を持つ YAML front matter を含めてください。

## 書式と構造

Markdown コンテンツの書式と構造には、次のガイドラインに従ってください。

- **見出し**: H2 には `##`、H3 には `###` を使ってください。見出しは階層的に使ってください。H4 を含む場合は構成見直しを推奨し、H5 以上ではより強く見直しを推奨してください。
- **リスト**: 箇条書きには `-`、番号付きリストには `1.` を使ってください。ネストしたリストは 2 スペースでインデントしてください。
- **コードブロック**: フェンス付きコードブロックにはトリプルバッククォート (```) を使ってください。構文ハイライトのため、開始バッククォートの後に言語を指定してください（例: `csharp`）。
- **リンク**: リンクには `[link text](URL)` を使ってください。リンクテキストが説明的で、URL が有効であることを確認してください。
- **画像**: 画像には `![alt text](image URL)` を使ってください。代替テキストには画像の簡潔な説明を含めてください。
- **表**: テーブルには `|` を使ってください。列が適切に揃っており、ヘッダーが含まれていることを確認してください。
- **行の長さ**: 可読性向上のため、行は 80 文字程度で折り返してください。長い段落にはソフト改行を使ってください。
- **空白**: セクションを分け、可読性を高めるために空行を使ってください。過剰な空白は避けてください。

## 検証チェックリスト

次の検証要件に準拠していることを確認してください。

### Front Matter

- [ ] `post_title`: 記事のタイトル。
- [ ] `author1`: 記事の主著者。
- [ ] `post_slug`: 記事の URL スラッグ。
- [ ] `microsoft_alias`: 著者の Microsoft alias。
- [ ] `featured_image`: アイキャッチ画像の URL。
- [ ] `categories`: 記事のカテゴリ。これらのカテゴリは /categories.txt の一覧から選ぶ必要があります。
- [ ] `tags`: 記事のタグ。
- [ ] `ai_note`: 記事作成に AI を使用したかどうか。
- [ ] `summary`: 記事の簡潔な要約。可能であればコンテンツに基づいて要約を推奨してください。
- [ ] `post_date`: 公開日。

### コンテンツと書式

- [ ] コンテンツが上記の Markdown コンテンツ規則に従っている。
- [ ] コンテンツがガイドラインに従って適切に整形・構造化されている。
- [ ] ルールとガイドラインへの準拠を確認するために、検証ツールが実行されている。
