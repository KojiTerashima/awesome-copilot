# アストロ開発手順書

最新のベストプラクティスを備えたコンテンツ主導のサーバーファースト アーキテクチャに従って、高品質の Astro アプリケーションを構築するための手順。

## プロジェクトのコンテキスト
- Astro 5.x と Islands アーキテクチャおよびコンテンツレイヤー API
- Type Safe と自動生成型による DX の向上のための TypeScript
- コンテンツ主導の Web サイト (ブログ、マーケティング、電子商取引、ドキュメント)
- 選択的なクライアント側ハイドレーションを使用したサーバーファーストレンダリング
- 複数の UI フレームワーク (React、Vue、Svelte、Solid など) のサポート
- デフォルトで静的サイト生成 (SSG)、オプションのサーバー側レンダリング (SSR)
- 最新のコンテンツ読み込みとビルドの最適化によりパフォーマンスが向上

## 開発基準

### 建築
- Islands アーキテクチャを採用: デフォルトでサーバーレンダー、選択的にハイドレートする
- タイプセーフな Markdown/MDX 管理のためのコンテンツコレクションを使用してコンテンツを整理する
- スケーラビリティのために機能またはコンテンツタイプごとにプロジェクトを構造化する
- 懸念事項を明確に分離したコンポーネントベースのアーキテクチャを使用する
- プログレッシブエンハンスメントパターンを実装する
- シングルページアプリ (SPA) パターンではなくマルチページアプリ (MPA) アプローチに従います。

### TypeScript の統合
- `tsconfig.json` を推奨 v5.0 設定で構成します。
```json
{
  "extends": "astro/tsconfigs/base",
  "include": [".astro/types.d.ts", "**/*"],
  "exclude": ["dist"]
}
```
- `.astro/types.d.ts` で自動生成されるタイプ (`src/env.d.ts` を置き換えます)
- `astro sync` を実行して型定義を生成/更新します
- TypeScript インターフェイスを使用してコンポーネント props を定義する
- コンテンツコレクションとコンテンツレイヤー API に自動生成されたタイプを活用する

### コンポーネント設計
- 静的なサーバーレンダリングコンテンツには `.astro` コンポーネントを使用します
- インタラクティブ性が必要な場合にのみフレームワークコンポーネント (React、Vue、Svelte) をインポートします
- Astro のコンポーネントスクリプト構造に従います。フロントマターが上、テンプレートが下にあります。
- PascalCase の規則に従って意味のあるコンポーネント名を使用する
- コンポーネントに焦点を当てて構成しやすくする
- 適切なプロパティ検証とデフォルト値を実装する

### コンテンツコレクション

#### 最新のコンテンツレイヤー API (v5.0 以降)
- 新しいコンテンツレイヤー API を使用して `src/content.config.ts` でコレクションを定義する
- 組み込みローダーを使用します: `glob()` (ファイルベースのコンテンツの場合)、`file()` (単一ファイルの場合)
- 新しい読み込みシステムにより強化されたパフォーマンスと拡張性を活用
- コンテンツレイヤー API の例:
```typescript
import { defineCollection, z } from 'astro:content';
import { glob } from 'astro/loaders';

const blog = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/blog' }),
  schema: z.object({
    title: z.string(),
    pubDate: z.date(),
    tags: z.array(z.string()).optional()
  })
});
```

#### レガシーコレクション (下位互換性)
- 従来の `type: 'content'` コレクションは自動 glob() 実装によって引き続きサポートされます
- 明示的な `loader` 構成を追加して既存のコレクションを移行する
- `getCollection()` および `getEntry()` を使用してタイプセーフなクエリを使用する
- フロントマター検証と自動生成タイプを使用してコンテンツを構造化する

### ビューの遷移とクライアント側のルーティング
- レイアウトヘッドの `<ClientRouter />` コンポーネントで有効にする (v5.0 で `<ViewTransitions />` から名前変更)
- `astro:transitions` からインポート: `import { ClientRouter } from 'astro:transitions'`
- ページ全体をリロードせずに SPA のようなナビゲーションを提供します
- CSS と view-transition-name を使用してトランジションアニメーションをカスタマイズする
- 永続的なアイランドを使用してページナビゲーション全体で状態を維持する
- `transition:persist` ディレクティブを使用してコンポーネントの状態を保存します

### パフォーマンスの最適化
- デフォルトは JavaScript ゼロです - 必要な場合にのみインタラクティブ性を追加します
- クライアントディレクティブを戦略的に使用する (`client:load`、`client:idle`、`client:visible`)
- 画像とコンポーネントの遅延読み込みを実装する
- Astro の組み込み最適化機能を使用して静的アセットを最適化します。
- コンテンツレイヤー API を活用して、コンテンツの読み込みとビルドを高速化します。
- 不要なクライアント側 JavaScript を回避してバンドルサイズを最小限に抑える

### スタイリング
- デフォルトで `.astro` コンポーネントでスコープ付きスタイルを使用する
- 必要に応じて CSS 前処理 (Sass、Less) を実装します。
- テーマ設定とデザインシステムに CSS カスタムプロパティを使用する
- モバイルファーストのレスポンシブデザイン原則に従う
- セマンティック HTML と適切な ARIA 属性によるアクセシビリティの確保
- 迅速な開発のためにユーティリティファーストのフレームワーク (Tailwind CSS) を検討する

### クライアント側の対話性
- インタラクティブな要素にフレームワークコンポーネント (React、Vue、Svelte) を使用する
- ユーザーの対話パターンに基づいて適切な水分補給戦略を選択する
- フレームワークの境界内で状態管理を実装する
- MPA の利点を維持するためにクライアント側のルーティングを慎重に処理する
- Web コンポーネントを使用してフレームワークに依存しない対話性を実現する
- ストアまたはカスタムイベントを使用してアイランド間で状態を共有する

### APIルートとSSR
- 動的機能のために `src/pages/api/` で API ルートを作成します
- 適切な HTTP メソッドとステータスコードを使用する
- リクエストの検証とエラー処理を実装する
- 動的コンテンツ要件に対して SSR モードを有効にする
- 認証とリクエスト処理にミドルウェアを使用する
- 環境変数を安全に処理する

### SEOとメタ管理
- Astro の組み込み SEO コンポーネントとメタタグ管理を使用する
- 適切な Open Graph および Twitter Card メタデータを実装する
- サイトマップを自動的に生成して検索インデックスを強化します
- アクセシビリティと SEO を向上させるためにセマンティック HTML 構造を使用する
- リッチスニペット用の構造化データ (JSON-LD) を実装する
- ページのタイトルと説明を検索エンジン向けに最適化する

### 画像の最適化
- 自動最適化には Astro の `<Image />` コンポーネントを使用します
- 適切な srcset 生成を使用してレスポンシブイメージを実装する
- 最新のブラウザには WebP および AVIF 形式を使用する
- スクロールせずに見える部分に画像を遅延読み込みする
- アクセシビリティのために適切な代替テキストを提供する
- ビルド時にイメージを最適化してパフォーマンスを向上させる

### データの取得
- コンポーネントのフロントマターでビルド時にデータを取得する
- 条件付きデータのロードに動的インポートを使用する
- 外部 API 呼び出しに対する適切なエラー処理を実装する
- ビルドプロセス中に高価な操作をキャッシュする
- Astro の組み込みフェッチを自動 TypeScript 推論で使用する
- ロード状態とフォールバックを適切に処理する

### 構築と展開
- Astro の組み込み最適化機能を使用して静的アセットを最適化する
- 静的 (SSG) またはハイブリッド (SSR) レンダリングの展開を構成する
- 構成管理に環境変数を使用する
- 実稼働ビルドの圧縮とキャッシュを有効にする

## Astro v5.0 の主要なアップデート

### 重大な変更
- **ClientRouter**: `<ViewTransitions />` の代わりに `<ClientRouter />` を使用してください
- **TypeScript**: `.astro/types.d.ts` で自動生成された型 (`astro sync` を実行)
- **コンテンツレイヤー API**: パフォーマンスを向上させるための新しい `glob()` および `file()` ローダー

### 移行例
```typescript
// Modern Content Layer API
import { defineCollection, z } from 'astro:content';
import { glob } from 'astro/loaders';

const blog = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/blog' }),
  schema: z.object({ title: z.string(), pubDate: z.date() })
});
```

## 実施ガイドライン

### 開発ワークフロー
1. TypeScript テンプレートで `npm create astro@latest` を使用する
2. 適切なローダーを使用してコンテンツレイヤー API を構成する
3. 型生成のために `astro sync` を使用して TypeScript をセットアップする
4. Islands Architecture を使用してレイアウトコンポーネントを作成する
5. SEO とパフォーマンスの最適化を備えたコンテンツページを実装する

### 宇宙飛行特有のベストプラクティス
- **アイランドアーキテクチャ**: クライアントディレクティブを使用した選択的なハイドレーションによるサーバーファースト
- **コンテンツレイヤー API**: スケーラブルなコンテンツ管理には `glob()` ローダーと `file()` ローダーを使用します
- **JavaScript なし**: デフォルトでは静的レンダリングになり、必要な場合にのみインタラクティブ性を追加します。
- **ビュートランジション**: `<ClientRouter />` を使用して SPA のようなナビゲーションを有効にします
- **タイプセーフティ**: コンテンツコレクションから自動生成された型を活用する
- **パフォーマンス**: 組み込みの画像最適化と最小限のクライアントバンドルで最適化します。
