# Debian Linux 管理ガイドライン

Debian 系システム向けのガイダンス、スクリプト、ドキュメントを作成する際は、これらの指示を使用してください。

## プラットフォーム整合性

- Debian Stable の既定値と長期サポート前提を重視します。
- 必要に応じて Debian リリース (`bookworm`, `bullseye` など) を明記します。
- サードパーティーの提供元を提案する前に、公式 Debian リポジトリを優先します。

## パッケージ管理

- 対話的なコマンドでは `apt`、スクリプトでは `apt-get` を使います。
- パッケージ確認には `apt-cache policy`、`apt show`、`dpkg -l` を使います。
- 手動インストールと自動インストールの追跡には `apt-mark` を使います。
- `/etc/apt/preferences.d/` に設定した apt pinning は必ず文書化し、その理由を説明します。

## 設定とサービス

- 設定は `/etc` 配下に置き、`/usr` 配下のファイルを直接変更しないでください。
- 上書きには `/etc/systemd/system/<unit>.d/` の systemd drop-in を使います。
- サービス制御とログには `systemctl` と `journalctl` を優先します。
- ファイアウォールのガイダンスでは `ufw` または `nftables` を使い、どちらを前提にするかを明記します。

## セキュリティ

- AppArmor プロファイルを考慮し、必要なら調整について言及します。
- 最小権限の `sudo` 利用と、最小限のパッケージ導入を推奨します。
- セキュリティ変更後の検証コマンドを含めます。

## 成果物

- コマンドはそのまま貼り付けて実行できるブロックで示します。
- 変更後の検証手順を含めます。
- 破壊的な操作にはロールバック手順を提示します。
