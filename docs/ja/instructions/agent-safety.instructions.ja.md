# エージェントの安全性とガバナンス

## 基本原則

- **フェールクローズ**: ガバナンスチェックにエラーがあるか曖昧な場合、アクションを許可するのではなく拒否します。
- **構成としてのポリシー**: アプリケーションロジックにハードコーディングされず、YAML/JSON ファイルでガバナンスルールを定義します。
- **最小権限**: エージェントは、タスクに必要な最小限のツールアクセス権を持っている必要があります。
- **追加のみの監査**: 監査証跡エントリを変更または削除しないでください - 不変性によりコンプライアンスが可能になります

## ツールのアクセス制御

- エージェントが使用できるツールの明示的な許可リストを常に定義します。無制限のツールアクセスを許可しないでください。
- ツールの登録とツールの承認を分離する - フレームワークはどのようなツールが存在するかを認識し、どのツールが許可されるかをポリシーで制御します
- 既知の危険な操作 (シェルの実行、ファイルの削除、データベース DDL) にはブロックリストを使用する
- 影響力の高いツール (電子メールの送信、展開、レコードの削除) については、人間による承認が必要です
- 無限ループやリソースの枯渇を防ぐために、リクエストごとのツール呼び出しにレート制限を適用します。

## コンテンツの安全性

- エージェントに渡す前に、すべてのユーザー入力をスキャンして脅威信号を検出します (データ漏洩、プロンプトインジェクション、権限昇格)
- 機密パターンのエージェント引数をフィルタリング: API キー、認証情報、PII、SQL インジェクション
- コードを変更せずに更新できる正規表現パターンリストを使用する
- ユーザーの元のプロンプトとエージェントが生成したツール引数の両方を確認してください

## マルチエージェントの安全性

- マルチエージェントシステム内の各エージェントは独自のガバナンスポリシーを持つ必要があります
- エージェントが他のエージェントに委任する場合、いずれかの最も制限の厳しいポリシーを適用します。
- エージェントの代理人の信頼スコアを追跡します。失敗すると信頼が低下し、継続的な適切な行動が必要になります。
- 内部エージェントに、それを呼び出した外部エージェントよりも幅広い権限を与えないでください。

## 監査と可観測性

- すべてのツール呼び出しを、タイムスタンプ、エージェント ID、ツール名、許可/拒否の決定、ポリシー名で記録します。
- 一致するルールと証拠を使用してすべてのガバナンス違反を記録します
- 監査証跡を JSON Lines 形式でエクスポートし、ログ集約システムと統合します
- 関連付けのために監査ログにセッション境界 (開始/終了) を含めます。

## コードパターン

エージェントツール関数を作成する場合:
```python
# Good: Governed tool with explicit policy
@govern(policy)
async def search(query: str) -> str:
    ...

# Bad: Unprotected tool with no governance
async def search(query: str) -> str:
    ...
```

ポリシーを定義する場合:
```yaml
# Good: Explicit allowlist, content filters, rate limit
name: my-agent
allowed_tools: [search, summarize]
blocked_patterns: ["(?i)(api_key|password)\\s*[:=]"]
max_calls_per_request: 25

# Bad: No restrictions
name: my-agent
allowed_tools: ["*"]
```

マルチエージェントポリシーを作成する場合:
```python
# Good: Most-restrictive-wins composition
final_policy = compose_policies(org_policy, team_policy, agent_policy)

# Bad: Only using agent-level policy, ignoring org constraints
final_policy = agent_policy
```

## フレームワーク固有の注意事項

- **PydanticAI**: `@agent.tool` をガバナンスデコレータ ラッパーとともに使用します。 PydanticAI の今後の Traits 機能は、このパターン向けに設計されています。
- **CrewAI**: クルーレベルでガバナンスを適用して、すべてのエージェントをカバーします。ポリシーの検証には `before_kickoff` コールバックを使用します。
- **OpenAI Agents SDK**: `@function_tool` をガバナンスでラップします。マルチエージェントの信頼にはハンドオフガードを使用します。
- **LangChain/LangGraph**: ガバナンスには `RunnableBinding` またはツールラッパーを使用します。フロー制御のためにグラフのエッジレベルで適用します。
- **AutoGen**: `ConversableAgent.register_for_execution` フックでガバナンスを実装します。

## よくある間違い

- 実行前のガバナンスではなく、出力ガードレール (生成後) のみに依存する
- ポリシールールを構成からロードするのではなくハードコーディングする
- エージェントが自身のガバナンスポリシーを自己変更できるようにする
- ツールの *名前* だけでなく、ツールの *引数* のガバナンスチェックを忘れる
- 時間が経っても信頼スコアが低下しない - 古くなった信頼は危険
- 監査証跡へのプロンプトのログ記録 - ユーザーのコンテンツではなく、決定事項とメタデータをログに記録します
