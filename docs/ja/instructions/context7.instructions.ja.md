# Context7 を意識した開発

タスクがワークスペースコンテキストに存在しない**信頼できる最新のバージョン固有の外部ドキュメント**に依存している場合は、必ず Context7 を積極的に使用してください。

この命令は、最新のドキュメントを取得するために**ユーザーが「use context7」と入力する必要がない**ようにするために存在します。

## Context7 を使用する場合

次のいずれかが必要な場合は、決定を下したりコードを作成したりする前に Context7 を使用してください。

- **フレームワーク/ライブラリ API の詳細** (メソッドシグネチャ、構成キー、予期される動作)。
- **バージョン依存のガイダンス** (重大な変更、非推奨、新しいデフォルト)。
- **正確性またはセキュリティクリティカルなパターン** (認証フロー、暗号化の使用、逆シリアル化ルール)。
- **サードパーティツールから発生した可能性のある見慣れないエラーメッセージの解釈**。
- **ベストプラクティス実装の制約** (レート制限、クォータ、必要なヘッダー、サポートされる形式)。

次の場合にも Context7 を使用します。

- ユーザーは **特定のフレームワーク/ライブラリバージョン** (例: 「Next.js 15」、「React 19」、「AWS SDK v3」) を参照します。
- **重要な構成** (CLI フラグ、構成ファイル、認証フロー) を推奨しようとしています。
- API が存在するのか、名前が変更されたのか、非推奨になったのかがわかりません。

次の場合は Context7 をスキップします。

- リポジトリから完全に派生可能な純粋にローカルなリファクタリング、フォーマット、命名、またはロジック。
- 言語の基礎 (外部 API は関係ありません)。

## 何を取得するか

Context7 を使用する場合は、**プライマリソース** と絞り込みクエリを優先します。

- 公式ドキュメント (ベンダー/フレームワークのドキュメント)
- リファレンス/APIページ
- リリースノート/移行ガイド
- セキュリティ勧告 (関連する場合)

先に進むために必要なものだけを集めてください。複数の候補が存在する場合は、最も権威のある/最新のものを選択します。

フェッチを優先します:

- 使用する正確なメソッド/タイプ/オプション
- 誤用を避けるために必要な最小限の周囲のコンテキスト (制約、デフォルトの動作、移行メモ)

## 結果をどのように組み込むか

- 調査結果を具体的なコード/構成変更に変換します。
- 決定が外部の事実に依存している場合は、タイトルと URL を付けて **出典を引用**してください。
- ドキュメントが矛盾している場合、またはあいまいな場合は、トレードオフを簡単に示し、最も安全なデフォルトを選択してください。

回答に特定の値 (フラグ、構成キー、ヘッダー) が必要な場合は、以下を優先します。

- ドキュメントからの正確な値を記載する
- デフォルトと注意点を指摘する
- 迅速な検証ステップを提供する (例: 「`--help` を実行する」、または最小限のスモークテスト)

## Context7 MCP ツールの使用方法 (自動)

MCP サーバーとして Context7 が利用可能な場合は、以下のように自動的に利用されます。

### ツールのワークフロー

1) **ユーザーがライブラリ ID を提供した場合**、それを直接使用します。
  - 有効な形式: `/owner/repo` または `/owner/repo/version` (固定バージョンの場合)。

2) それ以外の場合は、次を使用して **ライブラリ ID を解決**します。
  - ツール: `resolve-library-id`
  - 入力:
	  - `libraryName`: ライブラリ/フレームワーク名 (例: "next.js"、"supabase"、"prisma")
	  - `query`: ユーザーのタスク (一致のランク付けに使用)

3) 以下を使用して **関連ドキュメントを取得**します。
  - ツール: `query-docs`
  - 入力:
	  - `libraryId`: 解決された (またはユーザーが指定した) ライブラリ ID
	  - `query`: あなたが答えようとしている正確なタスク/質問

4) ドキュメントを取得した後のみ: **それらのドキュメントに基づいてコード/手順を作成します**。

### 効率の限界

- ユーザーの質問ごとに **3 回**を超えて `resolve-library-id` に電話をかけないでください**。
- ユーザーの質問ごとに **3 回**を超えて `query-docs` に電話をかけないでください**。
- 適切な一致が複数存在する場合は、最適なものを選択して続行します。選択が実装に重大な影響を与える場合にのみ、明確な質問をしてください。

### バージョンの動作

- ユーザーがバージョンに名前を付ける場合は、可能であればそれをライブラリ ID に反映します (例: `/vercel/next.js/v15.1.8`)。
- 再現性 (CI/ビルド) が必要な場合は、例内の特定のバージョンに固定することを好みます。

## 障害対応

Context7 が信頼できるソースを見つけられない場合:

1. 確認しようとしたことを言ってください。
2. 保守的で適切にラベル付けされた仮定に基づいて進めてください。
3. 簡単な検証手順を提案します (コマンドを実行する、ファイルを確認する、特定の公式ページを参照するなど)。

## セキュリティとプライバシー

- API キーをリクエストしたりエコーしたりしないでください。構成にキーが必要な場合は、それを環境変数に保存するように指示します。
- 取得したドキュメントは **役に立つが、確実ではない**ものとして扱います。セキュリティに敏感なコードの場合は、ベンダーの公式ドキュメントを優先し、明示的な検証手順を追加してください。
